  问题 1：权限确认过频，缺少一键放行

  根因

  改了什么

  - 新增配置 config/permissions.json：
    - eligibleCategories: ["read", "write"] —— 默认可被记住的类别；
    - highRiskCategories: ["execute", "delete", "credential", "network", "other"] —— 高风险类别，默认只能逐条放行；
    - highRiskAllowlist: [] —— 高风险操作若确需纳入一键放行，必须在此写显式正则。
  - 新增操作画像 apps/desktop/src/main/permission/profile.ts：
    - 按 kind/title/command/rawInput 归类为 read/write/delete/execute/network/credential/other；
    - 删除、凭据、执行命令等强制判为高风险；未知工具按 other fail closed；
    - applyWorkRootBoundary()：文件写入若显式指向 <WORK_ROOT>/<taskId> 之外，强制高风险且不可记住。
  - 新增授权存储 apps/desktop/src/main/permission/store.ts：
    - 会话授权只存内存，会话停止/移除时清理；
    - agent 授权写入 <workspace>/permissions.json（临时文件 + rename），重启后仍生效；
    - 文件损坏时清空授权（fail closed），不做“猜恢复”；
    - 匹配键为 agentId + category（会话授权再加 sessionId）。
  - 主进程自动放行 apps/desktop/src/main/electron/main.ts:372：
    - 在 approvals.request() 之前查 permissionStore.match(...)；命中直接返回 allow，不创建审批项；
    - 每个「会话 + 授权」首次命中写一次 permission.auto_allowed 审计，避免刷屏。
  - UI：
    - approval.ts:84-120：四个按钮「放行 / 本会话始终允许 / 对该 agent 永久允许 / 拒绝」；
    - 高风险默认禁用后两个按钮，并说明原因；若已在 highRiskAllowlist 中显式放行，则允许记住；
    - 左栏新增每个 agent 的「授权 N」和统一的「授权管理」入口；
    - apps/desktop/src/renderer/permission/grants.ts 列出全部授权，支持单条撤销和“撤销该 agent 全部授权”，并实时响应
      permission.updated。
  - 契约增量扩展：ApprovalView 增加 category/categoryLabel/highRisk/rememberable；HubAction.approval.decide 增加
    rememberScope；新增 permission.revoke；快照增加 permissionGrants。

  安全边界（明确说明）

  - 默认情况下一键放行只覆盖 read/write。
  - 执行任意命令、删除文件、凭据访问、网络访问、未知操作默认不可记住，必须逐条人工放行。
  - 要把某类高风险操作纳入一键放行，只能在 config/permissions.json 的 highRiskAllowlist 里写显式正则；改完需重启。
  - 文件写入另有路径边界：任务目录外的写入即使用户点“永久允许”也不会被记住。

  UI 侧 approval-verify 也断言了每张待批卡都有四个入口，结果为 ALL_PASS。

  回归风险

  - 授权粒度是“agent + 类别”，不是“具体命令/具体文件”；这是为了做到“同类不重复弹窗”，但意味着一次 write 授权会覆盖该
    agent 在该任务工作目录内的所有写入。任务目录外的写入已被路径边界单独拦截。
  - 永久授权存放在 %APPDATA%\bumimang\workspace\permissions.json，删除 workspace 或重置应用数据会丢失；agent 的 id
    改名后旧授权不再命中。
  - 配置在启动时读取，修改 permissions.json 后需要重启。
  - 若 agent 的权限请求完全不携带路径/命令，路径边界无法判断，只能按标题分类；这是协议信息不足导致的“尽力而为”，不会因此
    放宽高风险类别。

  问题 2：消息区自动滚到会话开头

  根因

  ├──────────────────────────────────────────────────┼───────────────────────────────────────────────────────────────┤
  │                                                  │ sync() 每次 store 更新都执行 clear(stage);                    │
  │ apps/desktop/src/renderer/panes/panes.ts:539-543 │ stage.appendChild(frag)，把所有窗格根节点摘下再挂回。DOM      │
  │                                                  │ 重新挂载会让每个 .pane-body 的 scrollTop                      │
  │                                                  │ 归零，表现为“自动跳到会话开头”。                              │
  ├──────────────────────────────────────────────────┼───────────────────────────────────────────────────────────────┤
  │                                                  │ log.blocks 是累计的全部块（sink 最多保留 500                  │

  - sync() 改为增量维护 DOM：只在顺序不对时 insertBefore，不再 clear(stage) 重挂；标签节点复用并原地更新。
  - panes.ts:363 新增 renderBlockWindow()：
    - 普通模式只渲染最后 CONV_WINDOW = 120 块；
    - 用户上滚后进入 history 模式，用块 id 作为锚点，新消息只累加未读数，不改变滚动位置；
    - 滚回底部或点「回到最新」后恢复 follow；
    - 窗口前还有内容时顶部显示「加载更早的消息（还有 N 条）」，点击后按高度差补偿 scrollTop，视口不跳。
  - 右下角新增「回到最新 · N 条新消息」浮层按钮，仅在非跟随状态显示。
  - 样式增加 .pane-body-wrap、.pane-jump-latest、.conv-load-earlier，并给 .pane-body 加 contain: layout style
    降低重排范围。
  - tabs-verify.ts 增加窗口化/滚动/性能断言。

  apps/desktop/src/main/electron/main.ts:67-78：打包形态下默认 workdir 使用

  即 C:\Users\Administrator\AppData\Roaming\bumimang\work。没有配置文件入口，也没有启动时自动创建和失败回落。

  问题 4：会话切换约 500ms 延迟

  根因

  代码中没有写死的 500ms setTimeout/debounce。实际延迟来自渲染路径：

  1. panes.ts:539-543：每次 store 更新（包括点标签导致的选中态变化）都 clear(stage) 后重挂全部窗格，所有会话的对话 DOM
     一起重新参与布局；
  2. 每个会话一次性渲染累计的最多 500 个块，隐藏的标签页也不销毁；
  3. 标签栏每次全量重建；
  4. 切换标签时先移除再插入大段 DOM，浏览器必须同步完成布局，体感就是约 500ms。

  改了什么

  - 窗格不再重挂；selectTab() 同步更新标签高亮和 .pane-hidden 可见性，切换路径只做类名切换。
  - 每个窗格只保留 120 块窗口，隐藏窗格不再持有全量 DOM。
  - 标签节点复用，避免整条标签栏重建。
  - 对话块节点复用：只有窗口末块会原地更新，其余块只创建一次。
  - .pane-body 加 CSS containment，减少布局影响范围。
  - 磁盘 IO 不在切换路径上：历史加载仍走原有 hub:history 异步路径，切换只读已加载的 sink。

  验证

  node_modules/electron/dist/electron.exe apps/desktop/electron/tabs-verify.ts --no-sandbox
  # PASS 切回 120 块窗格的同步耗时 < 250ms（旧实现全量 DOM + 重挂约 500ms）
  #      click→switch=6.2ms
  同一次验收还验证了切回后对话块数不变、标记文本仍在（未重建、未丢历史）。

  回归风险

  - 与问题 2 相同：只保留 120 块窗口，更早内容需点「加载更早」。
  - 性能数据来自受控快照（每会话 220 块）；真实 agent 的超长单块（巨大 diff/日志）仍可能拉高单次 patchBlock
    成本，但不再随会话总数线性放大。
  - 标签切换现在依赖 .pane-hidden 类名而非删除 DOM；若有外部样式覆盖 display，需要确认没有把隐藏窗格重新显示出来。
