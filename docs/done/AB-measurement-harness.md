# A/B 测量工具：把"省时间"变成可量

> 完成时间：2026-10-13 07:18

## 做了什么

写了工具，**但真实的 A/B 数字还没跑**——这点先说清楚，原因见下面"没做什么"。

`HANDOVER.md` §5 排第一的未验证项是"省时间没被量化"：多会话并行的**画面**（三窗格 34/34）与**机制**（简报包扇出 17/17）都验过了，但没有人测过 1 个会话 vs 3 个会话到底快多少、多烧多少。这个工具就是为那一格准备的。

它跑同一个任务两次（1 会话 / N 会话），各自记录：

- 墙钟时间
- 每会话的工具调用数与黑板读取数
- 黑板产出（死路 / 事实 / 意图各几条）
- 审批次数（一律自动放行，次数照记，避免测量被人工打断）
- **跨会话的疑似重复劳动**：把不同会话写的死路与事实两两比字符 bigram 的 Jaccard 相似度，≥0.6 就列出来

最后打印一张对照表并把原始数据落到 `docs/logs/ab-result.json`。

## 没做什么 / 已知问题

1. **真实数字没跑。** 三个原因，都是老的：① 需要**一道有确定解法的真题目**，而这个只有你有；② 一次 A/B 是 4 个真实 agent 轮次（1 + 3），按实测每轮 30–90 秒算要 5–10 分钟，且**烧真 token**；③ 我在 05:35 把这件活写进心跳目标，但随后的三次心跳是排队合并送达的，直到 07:15 才真正执行——**窗口已经过了**，所以只做到"工具可用"，没做到"数字拿到"。
2. **墙钟时间天然不可靠。** 它受模型速度、网络、并发调度影响，**单次测量不能当结论**。真要结论至少各跑 3 次取中位数，而那意味着 12 个 agent 轮次。
3. **判重是启发式的。** 字符 bigram 的 Jaccard 只能提示"这两条看起来像"，不能判定语义重复。阈值 0.6 是我拍的，没有标定过。
4. **`facts` 的 `created_by` 没取到**（表里有这个列，但 `listFacts()` 的返回类型里我投射掉了），所以事实类的重复检测目前把来源都记成 `?`，**跨会话判重对事实类失效**，只有死路类是准的。这是这个工具的一个真缺陷。
5. **没有做配对实验设计。** 1 会话先跑、N 会话后跑，第二次可能因为缓存/预热而系统性偏快。正确做法是交替顺序或各跑多次。
6. **超时到了不停手**：超时后循环退出，但仍在运行的会话会被 `shutdown()` 杀掉，那些会话的产出可能不完整——会让"多会话"侧的数字偏低。
