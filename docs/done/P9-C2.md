# P9-C2 · AWD 批量 manual 提交

> 状态：**P9-C2 完成；P9-C（C1 导出 + C2 批量 manual）收口**。日期：2026-10-25。
> 范围：AWD 面板勾选 confirmed 且未提交的候选 → 一次人工确认 → 逐条调用现有 `flag.submit` manual；**不新增 action、不调平台 API、不自动提交、不自动利用/开环境**。
> IR 答题卡不做固定模板/平台导出（用户决定）。

## 做了什么

- `renderer/awd/panel.ts`：
  - `submittableAwdFlags(view)`：只返回 `status=confirmed && submittedAt==null` 的候选。
  - Flag 轮换区改为带 checkbox 的行；不可提交候选的 checkbox disabled。
  - 「批量记录提交（manual）」按钮：
    - 勾选后一次 `openConfirmModal`（列出 value + “不会调用平台 API/不会自动提交”）；
    - 确认后逐条 `ctx.hub.dispatch({ type:"flag.submit", taskId, candidateId, mode:"manual" })`；
    - 统计成功/失败，`notify` 汇总；失败的候选保留未提交状态，可重试。
  - 无新增 Hub action；复用 P5-D 的 manual submit。
- `styles.css`：checkbox/批量行样式。
- `smoke.ts`：+1 条纯选择逻辑断言（只选 confirmed 且未提交）。
- 无 board/hub/contract 改动；无新表/平台。

## 行为

- 只有 confirmed 且未记录提交的候选可批量选择；new 需先人工 confirm，已提交不重复勾选。
- 批量按钮一次人工确认后逐条记录 `submitted_at/submit_status=manual`；**不复制到平台、不调平台 API**。
- 部分失败会报告成功/失败数量；无自动回滚/删除。
- 每条的 value 在确认框列出；内容含 flag 明文。
- 无自动提交/自动利用/开环境。

## 已知限制

1. **只是记录 manual 提交时间**，不是向平台提交；用户仍需复制 flag 到比赛平台。
2. 无批量 dry-run 预览（单条 flag.submit dry_run 仍可用）。
3. 无事务/回滚：部分成功部分失败时逐条结果，失败可重试；不删除候选。
4. 只选 confirmed 且未提交；new 必须先单条人工 confirm。
5. 批量确认框列出全部 value（含明文）；无脱敏/折叠。
6. 无 DOM 自动断言（选择逻辑纯函数单测 + Electron 加载）；按钮行为未做端到端 UI 自动化。
7. 只做 AWD flag 批量；IR 答题卡不做批量/固定模板/平台格式。
8. 无真实 AWD 数据；未经过比赛平台流程。
9. 无平台 API/自动提交/自动利用/开环境（设计底线）。
10. 不新增 action/表；依赖现有 flag.submit manual。
