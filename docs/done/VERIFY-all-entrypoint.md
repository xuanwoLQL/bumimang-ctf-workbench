# `npm run verify:all`：给四个确定性套件一个总入口

> 完成时间：2026-10-13 09:59

## 做了什么

上一轮我是**手动一条条跑**才发现 `verify:gate-live` 掉到 12/16 的——如果当时漏跑其中一条，那个回归就会一直躺着，而它破坏的正是"三种结局都验过"这个结论。

所以补一个总入口：

```json
"verify:all": "verify-gate && verify-gate-live && verify-briefing && verify-concurrency"
```

用 `&&` 串联，**任一条失败就停下**（不会因为后面的套件输出把前面的失败淹掉）。

四个套件合起来 **100 条断言**。

## 没做什么 / 已知问题

1. **不含需要真实 agent 的套件。** `verify:mcp-live`、`verify:arm-opencode`、`verify:arm-codex`、`verify:agent-permission` 都会 spawn 真 agent 并烧 token，所以没进 `verify:all`。**代价是：它们覆盖的路径（黑板可达、两家武装、原生提问行为）不在一次命令的保护范围内。** 这是有意的取舍，但要记住别把它们当"已经跑过"。
2. **不含 Lane B 的十个套件。** 那些在 `apps/desktop/electron/*-verify.ts` 里，是另一条 lane 的资产。理想是有一个跨 lane 的总入口，但那要两条 lane 约定命名与调用方式（本轮没做）。
3. **没有断言总数的汇总行。** 现在要靠人读四行数字。要加汇总就得改四个脚本的退出码约定或写个包装脚本——不值得为此改动四个已验证的脚本。
4. **`&&` 在 Windows 下走 cmd，串行且遇错即停**，这是想要的；但它不会并行，所以四个套件约 7 秒（够快，没必要并行）。
