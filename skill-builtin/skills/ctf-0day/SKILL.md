# CTF / 决赛靶场：渗透 + 应急（ctf-0day）

一条完整链路的能力：**外网打点 → 提权 / 横向 → flag**；以及**应急侧**：被入侵机器 / 镜像 / 流量包 / 日志的溯源与答题卡。

### 输出格式（本技能激活期间）

**每段整话开头带前缀【不迷茫挖掘中...】**：回复里每个独立要点段落/条目块开头都带，不省略、不换写法；代码块、命令、表格内部不加；只有一段时也要带；纯工具调用无文字输出时不适用。（若用户明说"前缀太吵"，可放宽为每条回复仅第一段带一次。）

## ★ 平台接口纪律（最高优先级，优先于本文档其他一切措辞）

> **本技能只负责「打」和「报告」。不允许调用打分平台的任何接口。**

具体：

- **不开靶场**。不要调 `start_challenge`（或任何等价的「开启环境」动作）。
  环境由人工开好之后交给你；你没环境就打不了，**报告「需要开环境」即可**，
  不要自己去开。

- **不提交 flag**。不要调 `submit`（或任何等价的「交答案」动作）。
  找到 flag 就**原样报告出来**（连同：flag 值 / 在哪台机器哪个路径 / 用什么手法拿到的），
  由人工提交。

- **不读 token**。不要读 `Agent-Token` / `HBC_TOKEN` 这类凭据，也不要读
  `hbc.py` 一类封好的接口脚本。你不需要它们。

- **可以做的**：打靶机、分析、取 flag、把结论写进台账、报告。

> **★ 有 MCP 工具可用**（`awd-mcp`，注册在 `~\.claude.json`）：只提供**知识库只读检索**
> （`kb_search(..., source="core|des|all")`，默认 `core`）
> 与**本地武器调用**（`run_weapon`）—— 现场查判据、跑 `scripts/` 脚本可以直接调。
> **它故意不含任何平台写接口**（不开环境 / 不提交 / 不读 token），与本节纪律一致。
> 详见 `知识库/平台MCP.md`。

**为什么这条这么硬（实测后果）**：

> 2026-10-10：一份任务单被四个 agent 同时执行，事件日志里
> `start_challenge` 被调了 4 次（dsh×3 + codex×1）。
> 平台限制「每个账号同时只能开 1 个靶场」⇒ **agent 自己开的新环境
> 把正在打的那个顶掉了**。而 flag 与实例强绑定（见下），
> **已到手的 flag 当场作废** —— 白干。

**所以「找到就当场提交」这句话的正确读法是：**
> **找到就当场报告。** 拖到最后一起报，同样会因为实例被回收而作废；
> 但**提交动作是人工的**，不是你的。

## 零、先五问：四层决策漏斗（所有题目的统一入口）

> **比赛题千变万化，但"题目属于哪一类"是稳定的。**本技能的优化颗粒度是**一类题**，不是一道题：
> 新题一律先走这条漏斗 —— **定边界 → 定题型 → 定手法 → 收口**。跳过①②两层直接试手法，是历次实战里最贵的一类失误。

### 第一层 · 定边界（90 秒，成本最低、止损收益最大）

**四问，任何一问命中就处理，别往下硬打：**

1. **这题有没有分？** —— 题目详情里 `has_flag=0` / 平台没登记 flag ⇒ 立刻降级为技术练习，**不投入时间**。（实测：16 道题打穿却零分，全部因为漏了这步）
   **硬判据（好靶场实测）**：提交接口会直接回 `{"success":false,"message":"此靶场没有flag"}` ⇒ 这不是"卡住"，是**没分**，立刻止盈换题（249 实测）。
2. **靶机真的活着吗？** —— 开启后 `curl` 十连发探稳；Java 重型环境（WebLogic / Spring Cloud）开启后 2–7 分钟仍是 000 ⇒ **5 分钟不可达即弃**，换时段换题（实测：4 道题因此白等）。
   **★ Spring Boot / 容器冷启动的识别（别误弃）**：**根路径拒连（`10061`）但某个端点已返回 500/404 的 JSON** ⇒ 说明它在**启动中**，不是挂了。
   做法：轮询一次（10s 后重试），通常就等到 200（222 实测：前 5 次全拒连，`/swagger-ui.html`、`/v2/api-docs` 已有 JSON 响应 ⇒ 等 10s 就通）。
   **实例存活远短于 `close_time`**：好靶场实测**约 2–15 分钟**就自行回收（`TCP ... actively refused`），`close_time` 是虚值 ⇒ **start 后必须连续打、别间断**。
   > **★ 最短的一次实测（293「最简单的提权」，2026-10-10）**：01:46:41 还正常答 200、木马通道刚打通，
   > **01:48 就 5 连发全 `code=000 rc=7`（连接被拒）**；平台标注的 close_time 是 **02:43** —— 标注 55 分钟、实测 **1 分多钟**。
   > 处置口径（别慌，也别重复 start 把现场越搞越乱）：
   > 1. **先 5 连发确认是死透还是抖动**：连续 `code=000 rc=7` = 死透；偶发 000 = 抖动，隔 60s 复测；
   > 2. 确认真死 → `python hbc.py start <id>` 重新拉起，**端口会轮换**（实测 `46444` → `10785`），
   >    必须把执行器里的 URL 换成新端口再继续，**旧端口与基于旧实例的结论一律作废**；
   > 3. **战术含义（本场景最重要）**：既然存活与标注完全脱钩 ⇒
   >    拿到入口后**把每个 HTTP 往返当稀缺资源** —— 用**一次发大宗侦察命令**（id / uname / sudo -l / SUID / caps / cron 全串进一条命令），
   >    而不是逐条试探。293 正是靠"一次大宗"在通道打通的**第 2 个请求**里就命中提权面。
3. **回连通道成立吗？** —— **需要靶机回连的利用链**（JNDI 反连 / Evil MySQL / 反弹 shell / OOB 外带）动手前先测通道：`example.com:80` 可连 ≠ 任意端口可连。
   靶机只放 HTTP 出网 ⇒ 改走**出网型外带**（HTTP/DNS 外带、paste/webhook 托管），别在反连上耗到收工。
   > 实测：3 道 JDBC 反序列化题过滤器都已绕过、真正发起连接，却因为回连链路不成立而卡死整场 —— **前提不成立时，手法再对也是零分**。
4. **有历史记录吗？** —— 平台记录（历史工单 / 别人的 writeup / 题目备注）优先读；答错多次的题先看记录再动手（实测：1 道题怀疑平台侧校验异常，白耗一轮）。

### 第二层 · 定题型（3 分钟读题，回报最高的一步）

> **先读题面，再动手。** 实测：1 道题题面直给用户名，无脑字典穷举浪费 20 分钟。

1. **读题面（30 秒）** —— 题名 / 提示 / 题干 / 甚至页面源码注释，常**直接写着解**：
   - 题名就是被禁的命令 ⇒ 说明那个命令没被禁
   - 题名就是漏洞类型 ⇒ 直接跳该类
   - 提示语带方向（"到处看看"=翻旧数据找泄露路径、"多想想"=别只爆破）
2. **侦察三分钟**（`打穿短表.md` §开局侦察）：端口 → 指纹 → 首页 → 响应头 / 报错栈 / JS / Cookie 键名 / 目录。
3. **定位题型** —— 拿上面的事实去 `知识库/题型图鉴.md` 对号：
   **它收纳 187 道实战题的题型分层（30+ 类）**，每类给「怎么认 → 通用打法 → 绕过层次 → 实战坑 → 假点」。
   对上了 ⇒ 直接套该类的通用打法（含该类的绕过层次表与坑位），**不再从零推**。
4. **对不上就现场推**（`破局模型.md`）；**推出来之后回填题型图鉴**（这类题的新打法 + 新坑）—— 这是本技能"一类题"能力的唯一增长方式。

### 第三层 · 定手法（弹药顺序，见 §六 情报线）

`手上有的先试` → `一键工具` → `搜现成 PoC` → `读信号` → `手工推演 / 自写 EXP`。
**第 3 步被跳过是最贵的失误**（实测：知道指纹却手搓 API 耗掉 40 分钟）。详规见 §一"按消除率排序"。

### 第四层 · 收口（拿到就交，不留到最后）

> **实测铁证**：对已通关的题重新开启实例后，提交其**正确旧 flag 仍判错**；从新容器内重新取 flag 才能提交成功。
> ⇒ **flag 与"当前开启实例"强绑定 —— 找到必须当场报告，绝不能攒批、绝不能等切环境后再报。**
> （**报告 ≠ 提交**：你把值报出来，提交由人工做。见文首「平台接口纪律」。）

> **★ 补充实测（293 + 233，2026-10-10）：平台提交接口「不校验 flag 值，只校验该账号是否已通关」。**
> 对已通关的题，提交**从新实例真取到的、肯定有效的新 flag**，返回的仍是同一句
> `{"success": false, "message": "flag错误"}` —— **与提交值无关**。
> （旧版这里写的是"已经通关了"，实际平台返回的是 `flag错误`，2026-10-10 实测校正）
> ⇒ 两条战术结论：
> 1. **给分只发生在「该账号首次通关」那一刻**。已通关的题再打**不产生新分**，
>    此时它的价值是：验证手法、补知识库、给同型新题攒弹药 —— 别再为它排队抢实例。
> 2. 反过来说，**首次拿到 flag 就必须立即报告**：那一刻是这道题**唯一**的得分窗口，
>    错过之后再精确地重打一遍也补不回来。**再强调一次：报告给人工，你不要自己提交。**
>
> **★★ 与之配套的一条（233 实测四实例三值不同）：flag 是「每次重建实例就换」的。**
> 实例 A`flag{940edb3f...}` / B`flag{2fdcbe76...}` / C`flag{badd7e68...}` ——
> 所以实例被回收后**必须重跑注入链取新值**，`--dump` 出来的旧值对新实例无效；
> 而实例回收是**分钟级**（见本节第一层）⇒ **把「启动 + 完整利用链」写成一个脚本一次执行**，
> 逐条试探式的分轮打法必然撞回收（233 前两轮就是这么白跑的）。

- 判定通关用**平台权威字段**（`is_passed` / `has_flag`）—— 但这是**读**，不是让你去写。
  读只读详情接口；**不调 `submit`**。
- 立刻回填台账 / writeup（§四）：已消除的假设、凭据、入口、卡点，压缩上下文后还能续。
- 不可逆动作（删站 / 加密 / 清数据）只在赛制需要时做（§二）；打分平台不是靶机（§二）。

## 通用规律库（跨题型复用，已按"能不能迁移"筛过）

> 下面每条都**不只对一道题成立**。命中对号的那条就照用，别重新推。

**读题的规律**

1. **题名 / 提示即答案** —— 题名写着哪个命令，那个命令就没被禁；提示的措辞常直接点到漏洞类型。
2. **先读题面再动手** —— "测试账号"多是烟雾弹，真实凭据常是「任务目标名 / admin」。
3. **答错多次的题先看平台记录**，别重复别人踩过的坑。

**边界的规律**

4. **实例绑定与时限** —— flag 与当前实例强绑定，找到当场**报告**（提交归人工）；容器有开启时限，别跨实例攒答案。
5. **身份判定 = 满足其一即可** —— 详情页 `identity` 是白名单，`[]` 人人可开、`["超级会员"]` 当前账号打不开（开启返回 403）。
   **开工先批量扫 identity**，预筛身份锁，直接省掉大量 403 尝试（实测：一批 ID 里筛出 20 个身份锁）。
6. **环境缺陷三类速识别，命中即止损** —— `has_flag=0` / 附件在网盘且匿名下载被限（物理不可得）/ 平台答案与容器不一致。
7. **不迷信版本号** —— 服务版本扫出来是"安全版本"，中间件洞照样试（比赛镜像常是魔改 / 装老组件）。

**探测的规律**

8. **报错是最快的结构推断通道** —— 从报错文案反推外层包裹结构（例：`near ''1'')'` ⇒ 外层是 `(name='输入')`，载荷用 `')` 闭合），
   比逐个试闭合方式快一个量级；报错串有 32 字节截断 ⇒ 分 16 字取。
9. **时序 oracle 判"对面真的做了什么"** —— 投不可达地址看响应时间跳变（0.12s → 5.1s 即证明服务端真的发起了请求）；
   也用于探测真实参数名（源码可能是"参考版"非部署版）。
10. **无回显一律先测通道** —— 需要的回连端口是否真能出去（见 §零第一层）。

**绕过的规律**

11. **黑名单补丁是逐个打的 ⇒ 同族命令 / 同族语法逐个试** —— 命令类：一个读命令被禁就换下一个（实测一整套 19 连）；
    语法类：`||` 代 `or`、`&&` 代 `and`、双写、大小写、注释符、`%0a`。
12. **前缀校验的绕过 = 让前缀"真实成立"** —— 路径穿越要求前缀真实存在，先用正常上传创建该目录；
    只校验前后缀 ⇒ 用 userinfo `@` / 少一斜杠 / 大写 / 少写斜杠等边界变体。
13. **编码层次要猜对位置** —— 承载位置猜错就永远无回显（原始 body / 表单参数 / 嵌入 JSON 三种都要试）；
    UTF-8 查黑名单 ⇒ 整段 UTF-16 重编码；`%00` 类截断要发**字面量**（真 NUL 会被解析器拒）。
14. **IP 头是矩阵不是单点** —— 每道题只认一个头，脚本一次全试（XFF / X-Real-IP / X-Client-IP / True-Client-IP / X-Cluster-Client-IP / CF-Connecting-IP / Proxy-* / Cdn-Src-Ip / Ali-CDN-Real-IP / Fastly-Client-IP / X-Originating-IP / X-Remote-*）。
15. **前端加密 = 白给** —— 读 encrypt 逻辑（AES key/IV、字典）→ 本地复刻 → 照常爆破。

**读结果的规律**

16. **控制台截断会吃掉 flag 尾部** —— JSON 回显只打印 120 字节就剪掉尾部（实测 1 例）；
    **判定一律读完整响应体**，脚本里显式 UTF-8 解码，中文输出重定向到 UTF-8 文件再读（GBK 乱码会让关键字匹配全失效）。
17. **状态码未必可信** —— 限速 / 封禁提示常常是 **HTTP 200 + 文案**，会让 302/200 判定失真；
    401 / 连接重置也未必是黑名单命中（可能是 WAF 冷却），**先隔 60 秒复测干净 payload 再下结论**。
18. **枚举必须自带排序** —— 枚举系统表要 `ORDER BY + LIMIT`（顺序不定）；从字典序拼装的数据要按序号排序，不能按抓包顺序。
19. **判分接口的字段 / 格式靠猜 = 高危** —— 先读页面 JS 看它怎么调用判分接口，比试 100 次都快。
20. **取证侧：磁盘上的马可能被本地杀软隔离** —— 文件不在就靠旁证定位（上传目录 / 时间戳 / 尺寸异常 / 进程 / 网络连接）。

**迁移的规律（本技能"一类题"能力的核心）**

21. **每类题记三样：怎么认 / 通用打法 / 假点。** 打完一类题，把这三样写回 `题型图鉴.md`；
    下次同型题从"重新推"变成"对号套用"。
22. **一道题的坑，往往是一类题的坑。** 踩坑后先问自己：这条规律只对这道题成立，还是对整类成立？
    整类成立 ⇒ 立即回填，别等赛后。

**验证与防误判的规律（实战踩出来的）**

23. **题目给的源码未必是部署版** —— 真实入口可能是另一个参数 / 另一个方法。用 **sleep 时序 oracle** 探真实参数名，别照源码死打。
24. **"通了"必须用哨兵串证明** —— 放一个唯一标记（如 `===PWN===`）或 `phpinfo`，看到它才算代码真的执行；只看"没报错"会把假通判成通。
25. **正则别直接匹配原始 HTML** —— 报错正则可能先匹配到 CSS 类定义；先剥 `<style>...</style>` 再匹配。
26. **base64 响应要先解码再判定** —— 在编码后的文本上找 `flag` 会误判失败（`php://filter` / XXE base64 回显同理）。
27. **上传后别猜落地路径** —— 名字常被时间戳 / 随机前缀 / UUID 改写；**从响应回显里取真实路径**（"文件已上传: X" / `#msgBox` 的 href）。
28. **URL 里别直接塞中文** —— shell 会按本地编码转，导致乱码；显式 `urllib.parse.quote` percent-encode。
29. **实例生命周期纪律** —— 爆破 / 攻防过程中**严禁再调一次"开启靶场"**：会端口轮换、环境被杀，前面跑的爆破全部作废；容器有开启时限，节奏按这个时限排。
30. **改配置类动作先想回滚** —— 传 `.htaccess` / 改 `dir` / 改 `dbfilename` / `FLUSHALL` 都可能把现场弄坏（实测：`.htaccess` 写坏导致整目录 500）。
    动手前记住还原命令（或用 `#` 覆盖），必要时重开容器重置。
31. **同族命令换 3 次仍是同类失败 ⇒ 换维度，别继续换命令** —— 大多时候卡的不是命令，是**参数或文件名**。
    实测：命令执行类换遍 `head/tac/xxd/od/strings/grep/find` 全返回"未取到文件"，真卡点是文件名写错了（试 `/flag`，实际是 `flag.txt`）。
    ⇒ 搜文件时**先试带后缀的完整名**（`flag.txt` / `flag.php` / `f1ag.txt`），再试裸名。
32. **路径穿越的判定方式不止一种** —— 除了"过滤 `..`"，还可能遇到**计数型深度判定**（回显里给出 `归一化后: <路径>`，按 `../` 出现次数算深度）。
    实测：`....//` 归一化后仍保留，看着"无效"，实际被单独加权 ⇒ **回显里出现"归一化后 / 已执行 / 已加载"这类人造措辞时，把它当规则说明书读，不要当噪音**。
33. **面对"模拟型"靶机时，别过度推断** —— 判据：常量子查询取不到值、真实子查询取得到值；报错措辞自相矛盾；标准语法（`count(*)`/`group_concat`/`database()`）被归一到固定文案。
    ⇒ 命中即**放弃深层 DBMS 推断与布尔盲注枚举**，改用**最直白的表名列名**再试一轮（实测：表 `flag`、列 `flag` 就是正解，而盲枚列名把一道 2 分钟的题拖成全场最久）。
    > 这条讲的是"识别出题人用了简化实现、从而少走弯路"，不是让你假设对方好说话 —— 能用直白名打通的题，换个环境也还是要靠报错结构推断。

## 一、唯一的模型：观察 → 假设 → 消除

比赛不是"把手法表挨个试一遍"，是**把无限的可能性收敛到一条路**。任何一个动作只可能干三件事：

- **观察** —— 从目标抠出事实：端口、指纹、报错栈、JS、配置、日志、镜像、流量、时间戳。成本秒级到分钟级，回报最高。
- **假设** —— 从事实推出「下一步最可能是什么」。这是思考，不花时间。
- **消除** —— 用一个动作砍掉至少一个假设。**这才是真正花时间的地方。**

> **一个动作如果既没带来新事实、也没砍掉假设，它就是在浪费。停掉它。**
>
> 这就是"卡死"的定义 —— 它不看表，看增量。也是本技能唯一的节奏纪律。

### 按消除率排序，不按套路顺序

| 顺序 | 动作 | 单位成本 | 一次砍掉 |
|---|---|---|---|
| 1 | 手上已有的先试：默认口令、已知 CVE、复用凭据、**同型靶机上一台打通过的手法** | 秒 | 一大类 |
| 2 | 一键工具：fscan / nuclei / 自动利用链 / 自带武器 | 十秒 | 一大类 |
| 3 | **搜现成 PoC**：指纹 + CVE / 漏洞名，走 GitHub 与网搜 | 分钟 | 一大类 |
| 4 | 读信号：JS 全量、报错栈、配置、history、日志、镜像 | 分钟 | 开启新假设 |
| 5 | 手工推演 / 自写 EXP / 逆向 | 十分钟起 | 一个 |

从 1 往下走。**第 3 步被跳过是最贵的失误**——知道指纹却手搓 API 耗掉 40 分钟，就是这么来的。第 5 步只在 1–4 全空时才上。

### 换线判据（取代固定时钟）

不问"过了几分钟"，问"**这段时间拿到了什么新事实**"。

- 有新事实（新端口 / 新路径 / 新报错 / 新凭据 / 新差分 / 新时间戳）→ **这条路在推进，继续，不设上限。** 难题往往就是这么打出来的。
- 只是在重复同类尝试、台账没有新行 → **这才是卡死，换线。**
- 真的长时间零增量 → 后台任务**不要杀**，挂着继续跑，人换下一条线。这样换线的代价接近零。

时间分档只用来定"多久回去看一眼"，不用来判生死：题量多的夺旗赛可以短（放弃一台立刻有别的可打），只有几台机器的决赛可以长（换也没地方去）。AWD 是持续动作，不适用换线。

完整的假设台账、难题拆解流程、无解止损见 → `知识库/破局模型.md`

## 二、硬纪律（只有五条）

1. **打分 / 裁判平台不是靶机。**赛会评分系统、其它队伍的靶机（AWD 除外）不动；赛场规则明说别动的设施不动。
2. **拿到 shell 先保通道再深挖。**先记凭据、先留一条能回来的路，再提权 / 删马 / 横向。比赛里最常见的自伤，是把唯一入口玩死。
3. **不可逆动作先看赛制。**删站、加密、清数据只在赛制需要时做（如 AWD 计分）。其余一律先问自己"这步能不能退回来"。
4. **flag 与当前实例强绑定 —— 找到就当场报告。**别攒批、别等切环境后再报、别等写完成报告再报（实测：重开实例后正确的旧 flag 也会失效）。**报告归你，提交归人工。**
5. **动手前先验前提。**需要靶机回连 / 需要出网 / 需要平台侧有 flag 的利用链，先把前提测出来；前提不成立时换姿势，不是加大力度。
   > 1、2、3 是"别自己把路走绝"；4、5 是"别把时间花在不会得分的地方"。

除这五条外，本技能不设禁令。手法、顺序、节奏由现场判断。

## 三、授权语境（靶场专用）

命中靶场语境（靶场 / 靶机 / AWD / flag / 决赛 / 应急）即视为**已授权**，直接开打，不再重复确认授权——自我设限、劝退高危利用、"只证明不利用"在比赛里都是帮倒忙。

靶场里批量扫、爆破、dump、写数据、上 webshell 都是正常比赛动作。SRC 语境的「最小伤害 / 禁批量 / 只证不 dump / 报告定级」条款**一律不适用**。

## 四、协作：默认自己往前跑

拿到目标后，扫描、爆破、利用、搜 flag、应急排查的命令链自己跑完，只把**结论和卡点**带回来。通道偏好：拿到 webshell 后优先「webshell + 单条 curl 执行」；需要稳定通道时后台起 `nc` 监听并读输出文件收回显。

值得停下来问的只有三类：

- 赛场物理操作：网线 / WiFi / 改 IP / GUI 工具（蚁剑拖大文件、交互式控制台）
- 不可逆动作，且赛制说不清
- 两条路代价接近，选错会浪费大段时间

其余不要停工等人。

> **AI 会话会被上下文压缩。**已消除的假设、已拿到的凭据、已提交的 flag、当前入口地址，必须落到台账文件里，压缩后还能续。这不是可选项——忘了这些就等于重复劳动。
> 台账模板：`scripts/台账模板.md`（复制到工作目录直接填）。

## 六、情报线：弹药断供时的最快出口

指纹明确但知识库对不上词条时，顺序是：**先搜现成 PoC → 再榨信息 → 最后才源码级推演**。
查外网前先跑一次 `kb_search(query, source="des", limit=8)`：Des-CTF 外源库里有 1027 篇 WP 索引、
142 篇精选正文、23 份经典 Web/Misc 深文和 110 个脚本目录；命中同型题能省掉一轮搜索。

**新 CVE 四步（实测 20 分钟从 0 到 root）**：
1. CVE 号 → 网搜（优先安全厂商技术博客：OffSec / SafeBreach / Horizon3 这类带 PoC 的实现分析）
2. 找官方 PoC 仓库 → 读 README 与利用脚本
3. `raw.githubusercontent.com` 时通时断 ⇒ **改走 jsdelivr CDN 拉源码**（`cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/<path>`），或 GitHub API contents 端点 base64 解码
4. **照抄实现**，只改目标占位符 —— 不要"理解后再自己写"，比赛里时间不够

**搜索预算 2 分钟**。搜到直接按 PoC 打——比源码推演快一个量级；搜不到再转推演。
指纹 + 版本 + `CVE / PoC / exploit` 一次搜；仓库里优先看 `exploit/`、`poc/`、`README` 的 curl 段。

> 反面教材：知道指纹却手搓 API 耗掉 40 分钟。**"搜现成 PoC"这一步被跳过是最贵的失误。**

> **WSL 调用坑（2026-10-09 复测，前两版结论已作废）**
>
> | 调用方式 | 结果 |
> |---|---|
> | `wsl -d ghost -- bash -c "脚本"` | ❌ `$VAR` / `$( )` 被转义层吞掉，循环变量读成空，输出整列假 MISSING |
> | 把脚本字符串用管道喂给 wsl | ⚠️ 能跑，但混入 `\r`，报 `bash: $'\r': command not found` |
> | ~~脚本转 UTF-8 字节后用管道喂给 wsl~~ | ❌ **旧文档记的"可靠写法"是错的**：PS 5.1 把 `byte[]` 传给原生命令时**逐元素转十进制字符串**，bash 收到 `102 111 114 32…`，报一屏 `$'102\r': command not found`，**整段自检假报 MISS**（实测把好端端的 WSL 工具链全判成缺失） |
> | **落地成 LF 文件 + `wsl -d ghost -- bash /mnt/c/...`** | ✅ **唯一可靠**。写法见下方 `$wslTmp` 段：`[IO.File]::WriteAllText` 写 UTF-8 无 BOM，再把 `C:\x` 转成 `/mnt/c/x` |
>
> 另附 Git Bash 侧坑：从 Git Bash 调 `wsl -- bash /mnt/c/...` 时，**MSYS 会把 `/mnt/c/...` 改写成 `C:/Program Files/Git/mnt/c/...`** ⇒ 必须 `MSYS_NO_PATHCONV=1 wsl.exe -d ghost -- bash ...`。
>
> **PowerShell 侧两个新坑（2026-10-08 实测）**
>
> | 坑 | 现象 | 正确做法 |
> |---|---|---|
> | `Select-Object -First N` | **会提前杀掉上游进程**（实测把 `localtunnel` 连带杀掉） | 用 `-TotalCount N`，或改用 `Select-String -List` / 重定向到文件再读 |
> | `Get-Content` + `Set-Content` 改文件 | **写入 BOM** ⇒ Python 报 `SyntaxError: unterminated string literal` | 改文件用 `write`/`edit` 工具；或用 `[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($false)))` |
> | `python -c "…'…'…"` | **内层单引号被 PowerShell 吞掉**（实测导致 `replace('php','')` 变成 replace-all，得出错误结论） | 一律**写临时 .py 文件再跑**，别用 `python -c` 传含引号的代码 |
> **可靠写法（PowerShell）**——落地 LF 文件、按 /mnt 路径执行、剥输出 NUL：
>
> ```powershell
> $lines = @(
>     'for t in gcc hydra vol; do'
>     '  p=$(command -v $t 2>/dev/null)'
>     '  [ -n "$p" ] && echo "OK $t $p" || echo "MISS $t"'
>     'done'
> )
> $tmp = Join-Path $env:TEMP 'wslrun.sh'
> [IO.File]::WriteAllText($tmp, (($lines -join "`n") + "`n"), (New-Object Text.UTF8Encoding($false)))
> $p = $tmp -replace '\\','/'
> if ($p -match '^([A-Za-z]):') { $p = '/mnt/' + $Matches[1].ToLower() + $p.Substring(2) }
> $out = (wsl.exe -d ghost -- bash $p 2>&1 | Out-String) -replace "`0", ''
> ```
>
> 两条附注：单行简单命令可以直接 `wsl -d ghost -- 命令`；**输出里带回 NUL 字节，做正则匹配前必须先 `-replace "`0",''`**。
>

> **★ 用脚本前先看这三条实测坑（一轮真跑出来的，不是推测）**
>
> 1. **字典带 BOM ⇒ 第一个词永远登不上**：Windows 上生成的字典常带 UTF-8 BOM，读进来变成 `\ufeffadmin`，**静默失败且看起来像"字典不对"**。读取一律用 `encoding='utf-8-sig'`。
> 2. **中文输出在 Windows 控制台乱码** ⇒ 脚本开头 `sys.stdout.reconfigure(encoding='utf-8')`，否则关键字匹配与肉眼判读全废。
> 3. **判定词不能只看状态码**：失败提示常是 **HTTP 200 + 文案**。爆破前 `--dry-run` 单发看清失败形态；**给了失败词却没命中它 ⇒ 就是形态变了（命中）**。
