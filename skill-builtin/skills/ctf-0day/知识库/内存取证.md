# 内存取证（volatility，给内存镜像时的开法）

> 场景：给 `.raw/.mem/.vmem/.dmp` 内存镜像，问攻击者进程、隐藏用户、提取的密码、执行过的命令。
> 本机跑法：WSL `wsl -d ghost -- python3 -m volatility3 -f 镜像 windows.cmdline`（vol3 库已装）；Windows 备 volatility2/3 zip。

## Volatility3 标准流程（按出分概率排序）

```bash
# 0. 识别镜像（拿到先跑，确认 profile）
python3 -m volatility3 -f mem.raw windows.info

# 1. 进程与命令行（最常考：攻击者跑了什么）
windows.pslist                 # 进程列表（EPROCESS 链）
windows.pstree                 # 进程树：看父子关系（异常父进程 = 注入痕迹，如 cmd.exe 的父亲是 services.exe）
windows.cmdline                # 每个进程的完整命令行——挖矿命令/后门启动命令/反弹shell命令全在这，直接出 flag
windows.cmdscan                # 扫描历史控制台命令（比 cmdline 更全，含已退出进程）
windows.consoles               # 控制台历史

# 2. 网络（矿池/反弹地址）
windows.netscan                # 网络连接：外连 IP 直接对应答题卡
windows.netstat

# 3. 文件与注册表
windows.filescan               # 全量文件列表（grep 找 .exe/.ps1/webshell 路径）
windows.dumpfiles --virtaddr 0xADDR   # 提取可疑文件做静态分析/交 MD5
windows.printkey --key "Software\Microsoft\Windows\CurrentVersion\Run"   # 启动项
windows.registryhivelist       # 隐藏用户：SAM\virus 看多余账户

# 4. 凭据与注入痕迹
windows.hashdump               # SAM hash（配合 hashcat 破）
windows.malfind                # 注入代码的内存段（VAD 异常：RWX 属性）——免杀马/注入shell必中
windows.dlllist --pid N        # 进程加载的非系统 DLL = DLL 注入后门
```

## Volatility2 对照（老教程/老比赛用 2，命令名不同）

```
imageinfo / kdbgscan → pslist/pstree → cmdscan/consoles → netscan/connscan
→ malfind → hivdump + chansales... vol2 没有 cmdline，用 cmdscan
```

## Linux 内存镜像（少见但出过题）

```bash
python3 -m volatility3 -f lin.mem linux.pslist linux.bash   # bash 历史直接还原攻击者命令
linux.check_syscall / linux.tty_check                        # rootkit 痕迹
```

## 答题卡对照（出过什么问什么）

| 考点 | 命令 |
|------|------|
| 恶意进程名/PID | pslist/pstree（孤儿进程、伪装系统名的 svch0st.exe） |
| 挖矿/后门启动命令 | **cmdline/cmdscan**（命令行原文常直接是 flag） |
| 攻击者外连 IP | netscan |
| 隐藏用户 | registry SAM（Names 键多出来的、`$` 结尾账户） |
| 注入痕迹 | malfind（RWX 段）+ yara 扫描 |
| 提取样本算 MD5 | dumpfiles → md5sum |
| USB HID 键盘输入（bit 流） | `linktype=220 usbmon`：头 64B + 8B HID，**只用 `submit(0x43)` 报文**；`set(cur)-set(prev)` 去重 + `mod & 0x22` 判 Shift；取 bit 流按 7bit ASCII 解码 |
| USB HID 鼠标轨迹 | 报文 `[button,dx,dy,wheel]` 累加位移 → PIL 画轨迹；用 x/y **跨度差异**判轴；丢弃起始飞入长直线；各向异性拉伸 |
| 网页终端交互（GoTTY） | 握手 `{"Arguments":"?arg=<token>","AuthToken":"<token>"}` + WS subprotocol `gotty`；输入帧 `"0"+按键`、输出帧 `"0"+base64`；token 在 `/auth_token.js` 的 `gotty_auth_token` |
| 隐蔽信道（ICMP/DNS 长度） | 见 `应急-流量与隧道.md` §隧道检测：按序号排序再拼、长度方差判 0/1 位 |

## 假点

- vol3 报 "unsatisfied requirement kernel" → 镜像太老/异构，试 vol2 的 imageinfo；还不行换 windows.dlllist.--pid 逐进程
- pslist 看着干净 → 上 pstree 看父子 + psscan 扫已退出进程（隐藏进程只瞒 pslist 不瞒 psscan）
- malfind 全是误报 → 看每段的保护属性和挂载文件，正常程序也有少量 RWX，重点看无文件回映射的
- 镜像文件巨大跑不动 → windows.xxx 插件按需跑，别一次全跑；先 info 确认架构
