# 内存马排查（Java 为主，线下赛热门题型）

> 场景：Web 应用被打了（Shiro/反序列化/Log4j2/任意文件上传），马不在磁盘上——直接注册进了 JVM 内存（Filter/Servlet/Listener/Interceptor/WebSocket/Agent 型）。磁盘查杀查不出来，这是出题人最爱。
> 答题卡常问：内存马类型（Filter/Servlet/Listener）、URL 路径、类名、密码、删除方式。

## Arthas 排查（首选，比赛备好 arthas-boot.jar）

```bash
java -jar arthas-boot.jar          # 选目标 java 进程

# 1. 列出所有 Filter/Servlet——重点看类名随机的、包名奇怪的
sc javax.servlet.Filter
sc *Filter
sc javax.servlet.Servlet
sc *Servlet

# 2. 反编译可疑类：内存马类通常磁盘无 .class、代码是 Base64+AES 解密注册
jad com.example.Filter0xDeAdBeef   # 一眼假类名直接 jad 看内容

# 3. 看 URL 映射：filterMaps 里多出来的条目（正常应用名单外的路径）
# 4. 取证：dump 类字节码留证，然后确认恶意代码逻辑（通常 eval(request.getParameter(...))）
dump 可疑类名

# 5. Web 管道查看（Tomcat）：
#    sc org.apache.catalina.core.StandardContext 后 getstatic 或 ognl 查 filterMaps
```

**判别铁律**：内存里有、磁盘上没有对应 `.class`/`.java` 的 Filter/Servlet/Listener = 内存马（正常应用类都在 war/jar 包里）。

## 无 Arthas 时的排查

```bash
# 1. 对比法：解压 war/jar 包，列出磁盘上所有类
unzip -l app.war | grep -E "Filter|Servlet" > disk_classes.txt
# 2. jvm-sandbox / 自己写 agent attach 枚举 FilterMap（比赛少用，arthas 够了）
# 3. 日志佐证：access.log 里高频 POST 的非常规路径（如 /shell、/cmd、随机路径）
#    → 该路径对应哪个 Filter 处理 → 反查类
grep -E "POST /(cmd|shell|exec|passwd)" /var/log/nginx/access.log | awk '{print $7}' | sort | uniq -c
```

## PHP/其它内存马对照

- PHP 无传统内存马，对应的是 **`auto_prepend_file`（php.ini/.user.ini）+ include 链**、`opcache` 缓存马：查 `.user.ini`、`php.ini` 的 auto_prepend 配置、opcache file_cache 目录
- .NET：IIS 模块注入——查 `web.config` 的 `<modules>` 节点异常 DLL

## 处置与加固（答题卡问"怎么处置"时）

1. 内存马无法"删文件"消除：**重启应用**是最直接清除（考试答这个）
2. 不重启：arthas 热更新类为空实现 / 删除 FilterMap 注册项
3. 找到注入源头堵住（反序列化入口/Shiro key/上传点），否则重启后还会被打进来
4. 改代码级加固：全局 Filter 白名单校验

## 假点

- `sc *Filter` 列出来的都是框架自带 → 看包名：`org.springframework/org.apache` 正常，`com.userxxx`/随机字符串可疑
- jad 反编译报"类未找到" → 换 classloader（`sc -d` 先看类加载器，Shiro 内存马常在 WebappClassLoader）
- access.log 里找不到马路径 → 内存马路径可以不在日志（POST 目标路径和 Filter 映射无关联时），回头全量 dump FilterMap
- 只查了 Filter → Listener/Servlet/Interceptor/WebSocket 型全过一遍，出题人考过 Listener 型
