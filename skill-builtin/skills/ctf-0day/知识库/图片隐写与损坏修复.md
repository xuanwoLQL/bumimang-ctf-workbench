# 图片隐写与损坏修复（画在图上的 flag 怎么读准）

> 来源：好靶场 553「为什么这个图片是损坏的」+ 552「为什么是个 exe 文件」实战通关（2026-10-08）
> 同族还有 812（图片隐写-镜像反转）、388、488 等 —— 本题族套路高度同质，**先按本篇顺序走**。

---

## 一、这类题的共同形态（重要）

**出题人把 flag 直接画在图片上**，再叠一层"壳"来伪装：

| 变体 | 壳 | 破法 |
|---|---|---|
| **553** | PNG 魔数损坏（`89 40 4F 47` 应为 `89 50 4E 47`） | 修 2 字节 → 打开 → 读图上字 |
| **552** | 真 JPEG，但 `Content-Disposition: attachment; filename=xxx.ex` + `Content-Type: application/octet-stream` | 看魔数不看扩展名 → 改名 .jpg → 读图上字 |
| **812** | 图正常，但**整图水平镜像** | `PIL.transpose(FLIP_LEFT_RIGHT)` → 读图上字 |
| **388** | **IHDR 的 CRC 被改**（stored `0x2859a99b` / calc `0x9849b2b2`）⇒ 所有标准解码器一律拒开；实际是**长宽隐写**（IDAT 解压后多出**正好 93 整行**） | 手解 chunk → 按 PNG filter 规则重建真实尺寸（969×**861**）→ 底部 93 行是黑底红字 flag |
| **488** | 藏在自定义 chunk / IHDR 谎报尺寸 | 见下"深查" |

> **388 实测结论（2026-10-08，C 线通关）**：`flag{Welcome_to_haobachang}`
> **并推翻两条旧结论**：① 它**不需要镜像**（重建后方向正常，先前"镜像"判断是拿错件所致）；② "本机 numpy 坏了"**不影响**——纯 Python 按 filter 规则重建即可，不必依赖 numpy。
>
> ⚠️ **素材错位警告**：同批题里 `stego812.bin` 与 `s812.png` md5 相同 ⇒ 那是 **812 题**的图（镜像反转），**不是 388 的附件**。做题前先核对附件归属，否则会在错的图上推半天。

⇒ **判据：如果"图片类题"你还没看过图，就别说没出口。** 报告里曾把 552 记为"无 flag 出口"、把 812 记为"编码未定位"，实测都是**没渲染图片**。

## 二、标准排查顺序（按性价比）

```
① 真实格式看魔数，不看扩展名/响应头
     PNG  89 50 4E 47      JPEG FF D8 FF      GIF 47 49 46 38      ZIP 50 4B 03 04
② 渲染 + 八朝向（★最高性价比）
     orig / flipLR / flipTB / rot90 / rot180 / rot270 + 2~8× 放大
③ 追加数据扫描（PNG 的 IEND 之后 / JPEG 的 EOI 之后）
     常见：IEND 后追加 48 字节 PHP 马（343 实测）
④ 文字行定位 + **6× 最近邻放大逐字复核**（本篇重点，见 §三）
⑤ PNG 深查（★388 实测有效）：
     a) **逐 chunk 校验 CRC** —— IHDR 的 CRC 不匹配 ⇒ 解码器一律拒开（不是文件坏了）
     b) **IDAT 解压字节数 vs IHDR 期望值** 对比：
          expected = H * (1 + W * channels)
          多出的字节若**恰好是整数行**（(len(raw) - stride*H_hdr) % stride == 0）
          ⇒ **长宽隐写**，真实高度 = H_hdr + 多出的行数
     c) 自定义 chunk（如 pHPx/pHPy）
⑥ 魔数修复（同族好文件对比，常只差 2~3 字节）
⑦ 位平面/LSB、通道分离（多数题排除：812 的 LSB 是 db 6d b6 严格周期）
⑧ EXIF / COM / tEXt / zTXt / iTXt 段
⑨ strings + flag{...} 正则
```

**②的实证**：553 修完魔数 → `PIL.open()` 成功 (800,200 RGB) → flag 画在图上；552 改名 .jpg 后 (800,600) → 图上三行文字，第二行直接写着 "Rename the file extension to .jpg to view"，底部就是 flag。

**⑤的实证（388，C 线 2026-10-08 通关）**：
```
PIL 报 UnidentifiedImageError
  → 逐 chunk 校验：IHDR stored CRC 0x2859a99b ≠ calc 0x9849b2b2   ← 根因在这
  → zlib 解 IDAT = 2503788 字节
  → IHDR 声称 969×768×3+768 = 2233344
  → 差 270444 = 93 × 2908（stride）⇒ 恰好 93 整行 ⇒ 长宽隐写
  → 按 PNG filter 规则手工重建 969×861 全量像素
  → 底部 93 行 = 黑底红字 flag{Welcome_to_haobachang}
```
**判据一句话**：**`PIL 打不开` ≠ 文件损坏 ⇒ 先查 IHDR CRC；`多出的像素恰好是整数行` = 长宽隐写。**

> 纯 Python 按 filter 规则重建即可，**不依赖 numpy**（"本机 numpy 坏了"不妨碍解这类题）。

## 三、★ 从图上读字符必须复核（553 的血泪教训）

**问题**：图片上的字是位图/等宽渲染，肉眼读极易混淆：

```
易混对： 8 / b      1 / l / I      7 / 1      0 / O      2 / Z      5 / S      ‍ g 的下伸部
```

**实测踩坑**：553 的 flag 先目视读数，**差点读错**（块切分与字符数对不上）。PIL 模板匹配在本机也失败（缺 TrueType 字体，FreeType 渲染字形不同）。

**有效复核法（两条同时做）**：

### ① 墨迹列投影做"结构自洽"校验
```python
from PIL import Image
import numpy as np
im = Image.open("flag.png").convert("L")
a = np.array(im)
ink = (a < 128).sum(axis=0)          # 每列墨迹像素数（列投影）
# 找连续非零段 = 字符块；统计块数与总宽
blocks = []
run = 0
for v in ink:
    if v > 0: run += 1
    else:
        if run: blocks.append(run); run = 0
if run: blocks.append(run)
print("墨块数:", len(blocks), "总宽:", sum(blocks))
```
**自洽判据（553 实例）**：图上 25 个墨块 / 226 列宽，而 `flag{` + 32 hex + `}` = **38 字符** ⇒ 块数 < 字符数是正常的（连体字与粘连），但**总宽/块宽比要合理**；且能解释特例（块[01] w=18 是 `f`+`l` 连体，其下方 x=18-21 的下伸部是 `g` 的 descender）。

### ② 放大后**读回来再逐字确认**
```python
im.resize((im.width*6, im.height*6), Image.NEAREST).save("flag_x6.png")
```
然后用 `read_image` 或目视，**逐字符念一遍**（对照 `flag{` + 32 位十六进制 + `}` 的结构：长度必须 **38**、hex 位必须是 `0-9a-f`）。

> **一句话纪律**：**图上取 flag，宁慢 2 分钟，不可读错 1 个字符。** 读错会浪费一次提交机会，且极易误判成"答错了/平台有问题"。

## 四、"无出口"的三种真相（552 的教训）

| 现象 | 真相 |
|---|---|
| 下载接口返回 `application/octet-stream` + `.ex` 文件名 | 很可能是**真图片**，只是响应头在骗你 ⇒ 看魔数 |
| 报告/前人说"无尾数据、无嵌入、无 flag 出口" | 多数是**没渲染图片**、没换朝向、没修魔数 |
| 图片"打不开" | 多数是**魔数/IHDR 被改了几个字节** ⇒ 与同族好文件 diff |

**552 的正确解读**：出口**就是这个下载接口本身** —— 下载 → 改名 → 看图。

## 五、工具

```python
# 必备（本机已装）
from PIL import Image           # 打开/翻转/放大（Image.NEAREST 最近邻，别用默认重采样）
import numpy as np              # 列投影/位平面
import zlib, struct             # 手解 PNG 的 IHDR/IDAT（magic 损坏时 PIL 会拒开）

# 修魔数（553 实例）
b = bytearray(open("broken.png","rb").read())
print(b[:8].hex())             # 期望 89504e470d0a1a0a
b[1], b[2] = 0x50, 0x4E         # 40 4F → 50 4E
open("fixed.png","wb").write(b)
Image.open("fixed.png").show()

# 追加数据扫描
raw = open("x.png","rb").read()
i = raw.rfind(b"IEND")
print("IEND 之后剩余字节:", len(raw) - (i + 8))
```

**本机注意**：`PIL` 渲染 TrueType 字形与题目位图字体不同 ⇒ **模板匹配会失败，别在它上面浪费时间**，直接用 §三的"放大 + 列投影"。

## 六、可复用规律（一句话版）

1. **图片类题，先渲染再看字**（+八朝向 +放大），再考虑 stegsolve/LSB
2. **魔数不看扩展名也不看响应头**（552 的 `.ex` / `octet-stream` 全是伪装）
3. **打不开 = 先 diff 魔数**，常只差 2~3 字节
4. **图上取 flag 必须复核**：6× 最近邻放大 + 列投影结构自洽，**hex 位只能是 `0-9a-f`**
5. **"无出口"三个字要怀疑**：出口往往就是那个"看起来无关"的下载/预览接口
