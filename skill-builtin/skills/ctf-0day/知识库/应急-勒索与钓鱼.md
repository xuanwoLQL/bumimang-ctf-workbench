# 应急：勒索加密 与 钓鱼邮件

> 这两类是应急赛的常客，原技能里是空白。共同点：**答题卡要的不是"发生了什么"，而是"谁、什么时候、从哪进来、范围多大"**。

---

## 一、勒索加密事件

### 1. 先定家族（30 秒内出结论，家族决定后面所有动作）

三样东西一起看，交叉确认：

```bash
# ① 加密后的扩展名（同一目录批量看，取众数）
ls -la /path | awk '{print $NF}' | grep -oE '\.[A-Za-z0-9]{3,10}$' | sort | uniq -c | sort -rn | head
# ② 勒索信文件名（家族指纹最强）
find / -maxdepth 4 -iname "*readme*" -o -iname "*decrypt*" -o -iname "*recover*" -o -iname "*.hta" 2>/dev/null | head -20
# ③ 桌面壁纸是否被换（很多家族会改壁纸放指引）
```

常见对照（扩展名 → 家族）：

| 扩展名 / 特征 | 家族 |
|---|---|
| `.WNCRY` `.WCRY` | WannaCry |
| `.GDCB` `.KRAB` | GandCrab |
| `.phobos` `.id[xxxx].[邮箱].phobos` | Phobos |
| `.makop` `.devos` | Makop / Devos |
| **纯数字后缀（`.2700` 等）** | **Phobos 系**（多个变种用数字后缀） |
| **`*.README.txt` + 随机串后缀**（如 `X3rmENR07.README.txt` / `.X3rmENR07`） | **Lockbit 变种** ⇒ **搜后缀即得家族** |

### 1.1 ★ 各家族"定制特征"（比后缀更可靠）

| 家族 | 独有的判据 | 出处 |
|---|---|---|
| **Phobos** | **每个文件夹里成对放 `info.txt` + `info.hta`**（不是单一勒索信）—— 这是它与常见家族最大的不同 | Solar 11 月 WP |
| **Phobos** | 预留 ID 在 **`.hta`** 里（如 `4A30C4F9-3524`）；**跨目录抽样对比**才能确认是否唯一 | 同上 |
| **Lockbit** | 勒索信文件名带随机串（`X3rmENR07.README.txt`），**后缀本身就是家族名** | 第一届 Solar 官方 WP |
| 通用 | **加密时间 = 被加密文件 mtime 的聚集点**（彼此只差几秒） | 见 `应急与取证通用判据.md` §二 |

### 1.2 ★ 通用提速法：**不认识的后缀，直接搜**

```
看到 *.README.txt 或数字后缀 ⇒ 直接搜 "X3rmENR07 勒索" / ".2700 勒索"
  ⇒ 一击命中家族名与解密工具
```
**为什么有效**：勒索家族的后缀是**全网唯一标识**，安全厂商的家族识别文章一定收录。

### 1.3 加密数据库恢复（真题考过）

```
被加密的 mdf 无法直接附加 ⇒ 用 D-Recovery SQL Server
★ 关键前提：需要一个【纯表结构的 mdf】作参照（题目会给，或从备份里取）
   ⇒ 选"被加密 mdf" + "参照 mdf" ⇒ 才能导出表结构与数据
```
| `.beijing` `.beijing_locked` | BeijingCrypt（国内） |
| `.mallox` `.mallox_locked` | Mallox |
| `.dragon444` `.c1` `.c0` | GlobeImposter（国内老牌） |
| `.locked` `.locky` | 通用 / Locky |
| 文件名 `_readme.txt` | STOP/Djvu |

勒索信内容本身常是要素：**联系邮箱 / Tor 地址 / 钱包地址 / ID 串**都可能被单独提问。

### 2. 定时间线：首次加密时间是全题的关键锚点

```bash
# Linux：找最早被改名的文件（-newer 组合或按 mtime 排序）
find / -xdev -newermt "2026-01-01" -printf "%T+ %p\n" 2>/dev/null | sort | head -30
# Windows：按修改时间排序取最早的一批
```

拿到"首次加密时间 T"后，**反查 T 之前 30 分钟到 2 小时**的窗口 → 那就是入口时间点。

### 3. 反查入口（国内勒索**绝大多数是 RDP 弱口令**）

```cmd
:: Windows：4625 失败的 4624 成功（尤其 Logon Type 10 = RDP）
:: 事件查看器筛选，或
wevtutil qe Security /q:"*[System[(EventID=4624)]]" /f:text /c:50
:: RDP 连接记录
reg query "HKCU\Software\Microsoft\Terminal Server Client\Servers" /s
:: 攻击者常执行的动作（这些也能反证入口）
vssadmin list shadows          :: 看是否被删
wevtutil qe Security /q:"*[System[(EventID=1102)]]"   :: 日志被清记录
```

入口候选清单：RDP 弱口令 / 暴露的 VPN / 未打补丁的边缘服务（Web 中间件） / 钓鱼附件 / 内网横向 / 已有 webshell 二次利用。

### 4. 范围与恢复可行性

- **范围**：同网段其它主机的同名扩展名文件；共享盘 / 备份服务器是否被加密
- **恢复**（要给出**依据**，不是"建议重装"）：
  - `vssadmin list shadows` / `wbadmin get versions` —— 卷影副本还在就能恢复
  - 攻击者常用 `vssadmin delete shadows /all` 删副本，**删了看事件日志 / Prefetch 有无该命令执行痕迹**
  - 离线备份 / 云备份 / 数据库 binlog 是否完好
  - NoMoreRansom 一类的公开解密器是否覆盖该家族（**只对有公开密钥泄露的家族有效**）

### 5. 答题卡要素

```
勒索家族：        （扩展名 + 信文件名 + 特征交叉确认）
首次加密时间：    （最早的异常 mtime，注明时区）
入侵入口：        （RDP 爆破 / VPN / 漏洞 / 钓鱼 —— 要有日志证据）
攻击者 IP：       （4625 高频源 + 4624 成功的源）
加密范围：        （主机数 / 目录 / 是否波及备份）
恢复可行性：      （卷影 / 备份 / 解密器，附证据）
```

### 假点

- 只答"中了勒索病毒"→ 没分。**入口与时间线才是分。**
- 拿生产机器做解密试验 → 二次破坏，比赛里直接扣分
- 只看被加密的文件 → 漏掉**勒索信之外的落地物**（攻击者工具、`.bat` 脚本、计划任务）
- `vssadmin` 删除没记录就以为没删 → 查 Prefetch / `$MFT` / USN journal

## 二、钓鱼邮件取证

### 1. 邮件头：真凶全在这里

```
Received:           从下往上读，是真实投递路径；最后一个"外部"跳的 IP = 真实发件 IP
Return-Path:        实际回信地址，与 From 不一致 = 伪造信号
From:               显示名可随便写，不值得信任
Reply-To:           与 From 不同 = 典型钓鱼（你回信会回给攻击者）
Message-ID:         域名与发件域不符 = 伪造线索
X-Originating-IP:   有时直接给出源 IP
Authentication-Results:  SPF / DKIM / DMARC 结果——fail 是强证据
```

快速提取（`.eml` 是纯文本，直接读头）：

```bash
# 前 60 行基本就是头
head -60 mail.eml
# 只看关键头
grep -iE "^(Received|From|Return-Path|Reply-To|Message-ID|Authentication-Results|Subject|Date):" mail.eml
```

### 2. 正文与 URL

- 正文常见 `quoted-printable` 或 `base64` 编码，先解码再看原文：
  ```bash
  python -c "
  import quopri,sys,base64,re
  d=open('mail.eml','rb').read()
  print(quopri.decodestring(d)[:3000].decode('utf8','ignore'))
  "
  ```
- 抽取链接，**解码 `href` 的真实地址**（显示文字常是假的），展开短链，识别仿冒域名（同形字 / 加后缀 / 错拼）
- 附件名与实际类型可能不符（`.pdf.exe`、双扩展名、RLO 覆写字符）

### 3. 附件分析

```bash
file 附件            # 真实类型优先
sha256sum 附件       # 先算 hash（答题卡常要）
olevba 附件.doc      # Office 宏提取（oletools）
binwalk -e 附件      # 复合/嵌套文件
```

高风险形态：Office 宏（`AutoOpen` / `Document_Open`）→ 下载 dropper；`.lnk` 带命令行；`.iso` / `.img` 挂载后跑 exe（绕过 MOTW）；`.js` / `.vbs` / `.hta`（`WScript.Shell` / `eval`）；**加了密码的压缩包**（密码常写在正文里）；`.html` 内嵌 `data:` 或重定向。

### 4. 主机侧对照：谁点了

```cmd
:: 附件落地位置
dir /s /b "%TEMP%" "%APPDATA%" "%USERPROFILE%\Downloads" 2>nul | findstr /i "附件名"
:: 浏览器下载记录 / Outlook 附件缓存
:: Prefetch 看哪些工具随后被执行
dir C:\Windows\Prefetch | findstr /i "excel winword wscript powershell"
```

### 5. 答题卡要素

```
发件 IP：         （Received 链里最后一个外部跳）
发件邮箱：        （Return-Path 优先于 From）
邮件主题 / 时间：
恶意 URL：        （解码后的真实地址）
附件名 / hash：
投递行为：        （点了之后跑了什么、落地在哪）
受影响主机：
```

### 假点

- 只看 `From` 显示名 → 那是可伪造的，**要看 `Received` 与 `Return-Path`**
- 附件只算 hash 不看行为 → 答题卡常问"执行后干了什么"
- 短链不解码就交 → URL 类是错的
- 正文编码不解 → 把乱码当内容写进答案
