# 应急与取证：从真题提炼的通用判据

> **这份文件的定位**：`应急响应总纲.md` 按**赛事问法**组织（第 N 问要什么），本文件按**方法**组织（怎么看出这件事）。
> **两者关系**：总纲告诉你"要答什么"，本文件告诉你"**凭一个信号就能定方向**"。
> **来源**：第一届/第二届 Solar 杯官方题解、帕鲁杯、2025 京津冀决赛、2026-5 月 Solar 月赛等真题（均为公开 WP）。
> **写法纪律**：只收**能迁移到同类题**的判据；**不复述具体题目**。

---

## 一、字节与结构判据（一眼定性质）

| 判据 | 能推出什么 | 迁移场景 |
|---|---|---|
| **文件头魔数**（`\x7fELF` / `MZ` / `PK\x03\x04` / `\xff\xd8\xff`） | 真实格式（**扩展名与响应头都不可信**） | 任何"文件打不开/格式可疑"的题 |
| **密文首字节 ^ 明文首字节 = 密钥** | 单字节 XOR 的密钥（**不用猜**） | 凡看到"XOR 加密且知道明文格式"（如 ELF/PNG 头固定）⇒ **一步反推密钥** |
| **文件头是 A 但内容像 B** | 拼接/隐写/容器嵌套 | 图片、压缩包、流量包 |
| **某个字段长度异常**（如 RSA 私钥 1704 字节而非标准值） | 有填充或附加数据 | 密钥文件类 |
| **`.pth`/模型文件 load 报 `invalid load key`** | **不是标准 pickle** ⇒ 自定义容器 | AI 安全题（见 `AI安全题实战.md`） |
| **CRC / 哈希不匹配** | 数据被改过（且能定位改了几字节） | 图片损坏、压缩包损坏、协议校验 |

**方法**：拿到任何"打不开/看着不对"的文件，**先 `xxd -l 64` 看头**，再对比"这个格式应有的头"。这一步 5 秒，能省 10 分钟瞎试。

## 二、时间聚集判据（**30 秒定位事件时刻**）

> **这是应急题提速最有效的一条，多份真题 WP 反复用到。**

```
正常业务的文件时间是【分散】的；
人的批量操作（上传马、加密文件、批量下载、批量改文件）
会让时间戳【高度聚集在一两分钟内】。
```

| 用法 | 具体做法 |
|---|---|
| **定位加密时刻** | 被加密文件的 mtime **彼此只差几秒** ⇒ 那个时刻就是加密发生时间（**勒索题标准解法**） |
| **定位入侵时刻** | web 目录里"最近 7 天新增的 php" 若集中在某 10 分钟 ⇒ 那就是上传马的时间 |
| **定位爆破开始** | 事件日志 4625 的**最早一条** = 爆破开始时间 |
| **定位批量操作** | 任何"批量"痕迹（多个文件同一时刻）都是攻击行为 |

**命令**：
```bash
# Linux：按时间排序看聚集
ls -lat --time-style=full-iso /var/www/html | head -30
# Windows：按修改时间排序
dir /T:W /O:D
# 通用：把时间戳提取出来做聚类
find /path -type f -printf '%T@ %p\n' | sort -n | awk '{print strftime("%H:%M",$1)}' | uniq -c | sort -rn | head
```

## 三、操作唯一性判据（**"只有一条"就是答案**）

> **工控/协议题的核心方法**，也可迁移到任何"大量正常流量 + 少量恶意流量"的场景。

| 判据 | 出处场景 | 迁移 |
|---|---|---|
| **过滤后"几乎全是读操作，只有一条写操作"** | Modbus 关泵 | 任何"找恶意指令"的题：**正常流量重复度高，恶意操作通常唯一** |
| **搜 `WriteRequest` 而不是 `ReadRequest`** | OPC UA | 写操作比读少几个数量级 ⇒ **先筛写** |
| **排除正常 CDN 后剩下的那个 IP** | 沙箱网络行为 | 白名单排除法 ⇒ **剩下的就是 C2** |
| **过滤器排除法**：先列全部，再逐条排除已知正常的 | 任何流量题 | 比"猜哪个可疑"可靠 |

**方法**：**不要找"异常"，要找"唯一"**。异常需要经验判断，唯一只需要计数。

## 四、反转与编码判据（**看到特征就知道是障眼法**）

| 判据 | 含义 | 动作 |
|---|---|---|
| **`rev` 特征是反转** | 文本/代码被整体反转 | 直接 `rev` 回来（**常见于反取证**） |
| **敏感字符串全 XOR 某个值**（如 `0xAA`） | 恶意软件躲 `strings` | 用 `strings` 搜不到时，**试 XOR 常用值**（`0x99`/`0xAA`/`0xFF`）再搜 |
| **Base64 短串（16 位起）** | 可能藏东西（防守方 WAF 会解码再扫） | 应急时**也要解码再扫**（见 `上传内容黑名单绕过.md`） |
| **双扩展名 `发票.pdf.exe`** | 钓鱼附件 | 看**真实扩展名**（往往在倒数第二位是掩饰） |
| **变量名/类名伪装成系统组件** | 后门（`svhost` vs `svchost`、`systemd-journaled` vs `journald`） | 查**路径是否合理**（系统服务不在 `/usr/local`、`C:\Users\Public`） |
| **参数值去掉前 N 字符再 Base64 解码** | 隐藏路径 | 看到"奇怪的前缀 + Base64"就试 |

**方法**：**先怀疑编码/反转/伪装这三类障眼法**，各花 10 秒排除，再进入内容分析。

## 五、工具指纹判据（**认工具 → 直接拿它的解密器**）

### 5.1 通用方法：从"固定字符串"认工具

| 特征 | 认到 |
|---|---|
| URI 里带 `?a=l64&h=IP&t=ws_`、UA `Go-http-client/2.0`、TCP 首包前 6 字节 `l64␣␣␣` | **VShell C2**（Go 系） |
| Cookie 值以 `;` 结尾、pass/key 由 md5 派生 | 哥斯拉 |
| 全程 AES、Accept 头固定 | 冰蝎 |
| 请求体含 `@ini_set("display_errors","0")` | 蚁剑 / 中国菜刀 |
| 明文 `z0=` 开头 base64 | 中国菜刀 |
| 勒索信 `*.README.txt` + 后缀（如 `.X3rmENR07`） | **搜后缀** ⇒ 家族名（Lockbit） |
| 每个文件夹**成对**放 `info.txt` + `info.hta` | **Phobos**（与常见家族不同） |
| 后缀 `.2700` 等纯数字 | Phobos 系 |

### 5.2 ★ 通用提速法：**"一个词认不出，就直接搜那个 token"**

```
看到不认识的标识（l64 / ws_ / X3rmENR07 / .2700）
  ⇒ 别硬分析，【直接搜 "l64 websocket C2"】 → 一击命中 VShell
```
**证据**：多份 WP 里作者都是这么做的（"搜后缀得家族"、"搜 'l64 websocket C2' 直接命中"）。

**为什么有效**：恶意工具的标识符是**全网唯一的**，搜索引擎里有别人的分析文章。

## 六、加密材料重组判据（**"解不开"往往是没拼对**）

| 判据 | 含义 | 动作 |
|---|---|---|
| **密文长度不是块大小的整数倍** | 缺分片或多垃圾数据 | **从分片 + 垃圾数据里按块长拼**（AES 128 字节 = 8 块） |
| **`digest()` vs `hexdigest().encode()`** | 16 字节 → AES-128 vs 32 字节 → AES-256 | ★ **MAC 校验一直失败但密钥看着没错 ⇒ 先核对这个**（见下 §九） |
| **IV 就是 Key 本身** | 某些工具的非标准做法 | 别默认 IV 是随机/全零 |
| **密钥来自"文件自身的哈希"** | 反取证（种子不在流量里） | 试 `MD5(前 4096 字节)[:8]`、`MD5(整个文件)`、`SHA256(自身)` |
| **单字节 XOR + 已知明文头** | 见 §一 | 首字节 XOR 即密钥 |

## 七、★ 陷阱清单（**验错判据 = 白做**）

| 陷阱 | 真相 | 判据 |
|---|---|---|
| **ZipCrypto 用 CRC32 当唯一判据** | **会撞假阳性**（CRC 对数但解出随机二进制） | **三条件**：校验字节（`header[11]` ∈ 0x33/0x34…）+ 明文全可打印 + CRC32 |
| **只爆一张图片的 CRC** | 同上 | 用"解出的内容是否可读"复核 |
| **哈希大小写** | 题目要 32 位**大写**时，小写判错 | 答题前**逐字核对格式**（含等号、大小写、分隔符） |
| **时区** | 日志时间与本地差 8 小时，整条时间线错位 | 题面要 UTC 就换算；**Wireshark 默认显示 UTC** |
| **"只有一条"被当成"没有"** | 过滤器写错导致看不到那一条 | 先看总数再筛选 |
| **单方向 Echo / 畸形包当成"连接成功"** | **以双方完成 TCP 握手为准** | 看 SYN-SYN/ACK-ACK |

## 八、AI/ML 题的通用判据（2025 后新题型）

| 判据 | 动作 |
|---|---|
| 附件是模型文件（`.pth/.pt/.onnx/.h5`）+ 样本 CSV | 判为 AI 安全题 ⇒ 先看格式再谈模型（见 `AI安全题实战.md`） |
| `pickle.load` 报 `invalid load key` | 自定义容器 ⇒ 先逆向容器 |
| 任务是"伪造数据骗过模型" | **从正常样本学分布 + 加小噪声生成**，别追求极端值 |
| 有"禁重放 / 禁重复"约束 | 生成时要**带随机性**且与原样本保持距离 |
| 有总额/数量硬约束 | **先用约束反推需要多少条**，再按分布生成 |

## 九、★ 一个能救命的通用排查法（"机制看着都对，就是不出结果"）

```
① 先核对【长度/类型】：不是块大小整数倍？
② 再核对【编码/表示】：digest 还是 hexdigest？大小端？
③ 再核对【密钥来源】：是密码？是哈希？是文件自身哈希？
④ 再核对【参数边界】：偏移 0-based 还是 1-based？IV 参与不参与？
⑤ 最后核对【判据】：我凭什么认为"解出来了"？（可打印？魔数？CRC？）

★ 结论：MAC/校验一直失败，90% 是 ①~③ 之一，不是算法错。
```

**实例（真题级）**：
```python
# 错：16 字节 → AES-128 → GCM MAC 永远校验失败，且报错看不出原因
# c2_key = hashlib.md5(salt.encode()).digest()
# 对：32 字节 ASCII hex → AES-256-GCM
c2_key = hashlib.md5(salt.encode()).hexdigest().encode()
```

## 十、一句话方法总表（现场速览）

| 遇到 | 先想 |
|---|---|
| 文件打不开 | 看魔数（§一） |
| 不知道事件什么时候发生 | 找时间聚集（§二） |
| 流量里找恶意操作 | 找"唯一"而不是"异常"（§三） |
| 内容读不懂 | 试反转/XOR/Base64（§四） |
| 不认识某个标识/工具 | **直接搜那个 token**（§五） |
| 解密失败 | 先核对长度/编码/密钥来源（§六、§九） |
| 觉得"解出来了" | 用**两个以上独立判据**确认（§七） |
| 模型/大量样本 | AI 安全题流程（§八） |
