# 比赛节奏与赛制

> 开场先花两分钟搞清赛制，再决定把力气放哪。赛制决定一切取舍。

---

## 一、先认赛制，再定打法

| 赛制 | 特征 | 打法要点 |
|---|---|---|
| **线上夺旗（解题）** | 一堆题，交 flag 得分，题量大 | **速度 + 广度**：简单题一个不留，难题挂着；一台卡住立刻换，因为总有别的可打 |
| **线下决赛（渗透）** | 几台靶机，按权限分层给分 | **深度**：一台机器要打到 root / domain admin，因为换也没地方去；内网横向的分常是大头 |
| **AWD 攻防** | 己方有靶机要守，别人来打你 | **攻守交替**：守分是持续动作。只攻不守必被翻盘（见 `权限维持与AWD.md`） |
| **应急响应专场** | 给被入侵机器 / 镜像 / 包 / 日志，按答题卡要素给分 | **先读答题卡**，问题决定排查方向；应急出分往往比渗透快（答对一个就给分） |
| **混合（渗透 + 应急双线）** | 两个半场都有分 | 渗透侧扫描后台跑，人先做应急；**让工具等人，不让人等工具** |

---

## 二、时间分配：给参考刻度，不给铁律

以 4 小时赛为例（其它赛程等比缩放）：

| 阶段 | 渗透线 | 应急线 |
|---|---|---|
| 0–30min | 全段扫描后台跑 + 指纹台账 | 分类答题卡，挑最快的流量 / 日志题先做 |
| 30min–2h | 主力打点：简单中等全部收掉 | 应急刷完一轮，难题挂起 |
| 2–3h | 内网横向 + 提权收 root / admin flag | 回头啃难题（内存马 / 内存取证 / 勒索 / 钓鱼） |
| 最后 30min | 补漏：打过的洞再试变体 | **全面复核答题卡**：格式 / 时区 / 大小写 / 提交状态 |

**两条判断**：

- 应急题出分通常比渗透快（答对一个要素就给分，渗透要打穿才出 flag）→ **应急先做、渗透后台跑**是常见的最优开局。
- 反过来，若应急题只有一两道且很难，主力压渗透。

**换线不看表，看增量**（完整判据见 `SKILL.md` 与 `破局模型.md`）：有新事实就继续，没有就换。参考刻度只用来提醒"该回去看一眼了"。

## 三、★ 竞速：一血/二血/三血机制下的差异化打法

> **前提**：赛制设**一血 / 二血 / 三血额外奖励** ⇒ **速度本身就是分数**，且和"拿总分"是**两个不同的目标**。
> 本技能库此前 90% 的篇幅在教"怎么拿分"（止损 51 处、优先级 31 处），但**"抢一血"的策略不同**（`一血` 全库仅 3 处）—— 这一节补齐。

### 3.1 一血改变的三件事

| 常规打法 | 一血机制下 |
|---|---|
| 优先打**高分**题 | 优先打**最快出分**的题（一血加分可能盖过高分题的差距） |
| 一台打穿再下一台 | **蜂群式**：先在所有目标上跑轻量探测，抢"最快冒头的 flag" |
| 找到 flag 攒着一起交 | **拿到即交**（晚 30 秒，一血就是别人的） |

### 3.2 开局前 5 分钟：把"等待"变成"并行"（一血的核心）

**原则：绝不让人等工具，让工具等人。**

```
第 0 分钟（同时发起，不等结果）：
  ├─ 后台① 全段存活扫描（nmap -sn / fscan -np）        ← 跑着
  ├─ 后台② 目标 Web 目录/指纹扫描（并行扫所有入口）      ← 跑着
  ├─ 后台③ 弱口令/字典爆破（对已知登录口，低频起步）      ← 跑着
  └─ 人：读题面 + 读答题卡 + 看拓扑图                    ← 唯一串行的事
第 3 分钟：后台结果陆续回来 → 按"哪个更接近出分"排序，人扑向第一个有反应的
```

**必须串行、不能并行的**（识别出来，别干等）：
- `start` 类实例启动（等它 ready）
- 限流窗口（平台 API 10s/3s 限制）
- 依赖前置状态的链（必须先拿到 A 才能做 B）

### 3.3 一血的第一性原理：抢"**独立且快**"的 flag

对每个候选 flag 问三个问题（按顺序，任一为"否"就换下一个）：

```
① 拿它需要几步？  1-2 步 ⇒ 一血候选；≥4 步 ⇒ 交给后面慢慢做
② 它是否【独立】？ 独立 flag 才能单独计分（同一 flag 出现在两台机上通常只算一台）
③ 我当前离它多远？ 已有 shell / 已有凭据 / 只差一个 payload ⇒ 立刻打
```

**典型"快 flag"清单**（开局就该扫这些）：
| 位置 | 为什么快 |
|---|---|
| 首页源码 / 注释 / JS | 0 步（F12 就能看到） |
| 响应头 / 返回包 | 0 步（F12） |
| `robots.txt` / `.git` / 备份文件 | 1 步（一条请求） |
| 弱口令登录后的页面 | 1 步（字典第 N 条） |
| 上传点直接传马 | 2 步（传 + 连） |
| 任意文件读取 `/flag` | 1-2 步（一条 payload） |

### 3.4 别人还在扫，你已经交了：三个抢时间的硬技巧

1. **变体一次打包全发**（本库规律）：一条脚本发 20 个绕过变体，比手试快一个量级
2. **预置 payload 库**：赛前把常用 payload 存成文件（上传绕过/路径穿越/注入闭合/webshell 一句话），现场 `cat` 出来改参数就用，**别现场想**
3. **拿到即交，不做"完美验证"**：先交（`flag{...}` 原样），再回头完善思路。验证留给人工复核时做

### 3.5 什么时候"放弃一血、转做高分题"

```
已过 2 个 flag 的首杀时间窗口（观察排行榜：一血已被别人拿走）
  ⇒ 停止为速度优化，转【深度】（高分题 / 多环链 / 域控）
判据：排行榜上某题的一血标记消失 ⇒ 那题不再有速度收益
```

**注意**：不要为了抢一血而**跳过打穿的机会** —— 一套口令打全段的价值远大于一次首杀。

## 三·B、权限分层拿分（渗透半场）

线下赛靶机通常一台多个 flag：

```
webshell / 低权 shell   →  flag1（前台 / /flag.txt）
提权到 admin / root     →  flag2（/root/flag、管理员桌面）
内网横向到下一台         →  flag3（内网机器）
域控 / 核心资产          →  flag4（DC 桌面、数据库 flag 表）
```

- **拿到低权不是终点。**每台机器打完低权立刻提权，root 后**重搜一遍 flag**（提权前读不到的 `/root/flag`、桌面文件现在能读了）。
- 常见藏点：Windows `C:\Users\xxx\Desktop\flag.txt`、Linux `/root/flag`、`/flag`、数据库 flag 表。
- 台账里给"提权后要回补的 flag"单独留一列，别忘。

## 四、双线配合（混合赛制）

- 应急靶机溯源出的**密码 / 后门路径 / 内部服务**，直接拿去渗透打点——出题人常复用（日志里的弱口令就是后台密码）。
- 渗透拿下的机器可反向当应急素材：你留的后门位置，就是别人可能留的位置。
- 部分赛制的应急靶机开着服务：溯源之余顺手扫一遍，可能直接拿 shell 拿隐藏 flag。

---

## 五、提交纪律（终场丢分重灾区）

1. **flag 即报**，别攒到最后一起报。**报告归 agent，提交归人工**（见 SKILL.md「平台接口纪律」）。
   人工提交失败时先看格式（大小写 / 花括号 / 多余空格 / 前缀）。
2. **看清 flag 格式**：`flag{md5}`（小写？）、`flag{UUID}`、纯字符串——按题目要求格式化。
3. **时间类答题写清时区**：题目要 UTC 就换算；日志时间与本地差 8 小时是经典坑，会让整条时间线错位。
4. **IP 类答题用应用层真实源 IP**，别把 CDN / WAF / 跳板 IP 交上去。
5. **判"已提交"要记时间**：flag 轮换型题目过一会儿可能变，回头重拿。
6. 台账三列：`flag 值 | 来自哪台哪处 | 提交结果`。同一 flag 出现在两台机上通常只算一台的分——优先找**独立** flag。
7. **最后 30 分钟只复核、不开新线**：把所有"找到了但没提交"的**汇总报告出来**，由人工提交。

## 六、心态与止损

- 被高手压着打是常态：按台账走自己的节奏，不追着一台机器证明自己。
- 卡住时后台任务**不要杀**，挂着继续跑，人换线——换线的代价就接近零。
- 先把简单中等全部收掉，难题挂着后台想。**难题是胜利的条件之一，不是必要条件。**
- 最后 30 分钟不接新难题，只收尾。
