# 端口与服务速查（认得出 → 直接打）

> **用法**：扫到不认识的端口，先在这里对一次。**每一行都是"能不能拿分"的判据，不是科普。**
> 格式：`端口 | 服务 | 认什么 | 打哪 | 假点`
> 来源：HackTricks network-services-pentesting 逐条核对 + 本地实战（标注「实测」的来自本机/靶场）。

---

## 一、对象存储 / 制品库 / 镜像仓库

| 端口 | 服务 | 认什么 | 打哪 | 假点 |
|---|---|---|---|---|
| 5000 | **Docker Registry** | `GET /v2/` → 200 或 401 带 `WWW-Authenticate: Bearer realm=...` | `GET /v2/_catalog` 列全部仓库 → 拉 manifest → 拉 layer → **解层找凭据/脚本/flag** | `/v2/` 回 401 只说明要 token，**不代表关着** ⇒ 继续试匿名 token 流程（`GET /service/token?service=...&scope=repository:<repo>:pull`） |
| 5000 | **Harbor**（Web 形态） | `GET /api/v2.0/systeminfo` → `{"auth_mode":"db_auth"}` | `/api/v2.0/projects` **常免认证**列项目；匿名 token 拉镜像层 | 能列仓库名但 pull 403 ⇒ 只到"命名空间可见"，**不算拿到** |
| 9000 | **MinIO / Portainer** | MinIO：`/<bucket>/?list-type=2`；Portainer：标题 `Portainer` | MinIO 桶策略全开可直接列/下对象；Portainer 弱口令 → 容器管理 | — |

## 二、大数据 / 搜索 / 消息队列（**未授权重灾区**）

|---|---|---|---|---|

| 5601 | Kibana | 标题 `Kibana` | 未授权可看全部仪表盘/日志；CVE-2019-7609 时间线 RCE | — |

| 5672 | RabbitMQ AMQP | — | 凭据泄露后 `rabbitmqadmin` 读队列 | — |
| 9092 | Kafka | — | 未授权 `ListTopics` → 读消息流（常含业务数据/凭据） | — |
| 2379 / 2380 | **etcd** | `GET /version` | **未授权读全部 key**：`/v2/keys/?recursive=true` 或 v3 `etcdctl get --prefix ""` ⇒ **K8s 集群的凭据/serviceaccount 常在这** | — |
| 10250 / 10255 | **Kubelet** | `GET /pods`（10255 只读口常无认证） | `/pods` 列容器 → `/exec/...` 进入容器（10250 常无鉴权） → 用 SA token 提权 | 10255 在新版已被移除 ⇒ 优先试 10250 |

## 九、扫描纪律（**别把容器扫崩**）

```bash
# 薄容器：目录扫 -t 1~2；端口扫先 -T4 单口再全集
nmap -sT -Pn -p 1-10000 --min-rate 1000 TARGET      # 无 sudo 时用 -sT（TCP 连接扫描）
fscan -h 10.10.2.0/24 -np                            # 只存活，最快
# 代理链下【必须】用 -sT（-sS 半开扫描不走 SOCKS，见 内网横向.md 假点）
proxychains4 nmap -sT -Pn -p 445,3389,5985 TARGET
```

**假点**：
- `proxychains nmap -sS` **必然扫不出**（SOCKS 只承载完整 TCP）⇒ 一律 `-sT -Pn`
- 扫出端口但连不上 ⇒ 先确认是否走了代理（工具不走代理时，只有本机可达）
- 内网机补丁比外网全 ⇒ **扫到洞也未必能打**，回到凭据复用主线
